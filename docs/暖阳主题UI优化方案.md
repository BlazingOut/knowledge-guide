# 暖阳主题 UI 优化方案（理解与实施计划）

> 输入：`docs/ref-design/AI建议修改UI方案.md`（外部 AI 的诊断与建议）+ `docs/ref-design/AI学习星图UI界面合集.png`（参考视觉稿）
> 创建日期：2026-10-28
> 状态：待确认后分阶段实施
> 原则：先还 CSS 的债，再谈美学；一次只解决一个层面的问题（布局 → 层级 → 颜色 → 装饰）

---

## 一、总体判断

外部 AI 方案的核心结论是：**页面不是缺少设计感，而是设计元素太多、太平均**——金色铺满失去强调作用、所有模块视觉权重接近、边框/圆角/阴影层层叠加。这个诊断是准确的，而且**代码现状比它描述的更严重**：`src/styles.css` 本身就是它第四章「Vibe Coding 越改越丑」的完整病历。

参考图（`AI学习星图UI界面合集.png`）比方案文档中的文字结构示意更适合作为视觉目标：绘本插画只出现在关键位置、星球按领域分色、「下一站」真实行动引导，这些都能对应到本项目的真实数据和交互。

## 二、代码现状诊断（证据）

### 2.1 数据证据

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| styles.css 体积 | 约 60KB / 385 行（超长行） | 单文件，无拆分 |
| `!important` | **396 处** | 后层补丁压前层补丁的产物 |
| `.cards` 规则定义 | **26 次** | 至少 8 层互相覆盖的卡片尺寸/滚动规则 |
| `@media` | 32 处 | 断点 1150/900/820/620 四套并存，同类规则分散 |
| 硬编码 hex 色值 | **148 处** | 不走 token；`#f0bd4f`（暖阳金）硬编码 19 次 |
| 星球图标补丁层 | 至少 5 层 | 「图标最终隔离」→「最终隔离规则」→「星球图标最终规则」→「最终修复」→「星球图标统一覆盖」（styles.css:57–168） |

典型的病灶示例：首页卡片的 `overflow` 同一属性在 `.shell .cards{overflow:visible!important}`（高特异性）与后置的 `.cards{overflow-y:auto!important}`（低特异性）之间"特异性互搏"，最终谁生效需要推演才能确定——规则失去可推理性的那一刻，后续每次调整都在赌运气。

### 2.2 与外部方案对应的六个具体病灶

1. **暖阳主题全区间发黄**：token 现值 `--bg-page:#fff9e9`、`--bg-sidebar:#fff4d0`、`--raised:#fff0bc`、`--border:#e7d39b`——背景、侧栏、卡片、提示条全部在浅黄区间，缺少明暗层次。
2. **金色滥用**：金色同时出现在卡片边框、星球轨道、星空装饰（starfield/main:before/after）、进度条端点、导航选中前缀、徽章、focus outline。「星光变成了墙纸」。
3. **三套"选中"语言并存**：导航选中 = 浅绿底 + 绿色内嵌条 + 金色星标前缀；领域 tab 选中 = 绿实底 + 金色星标前缀 + 光晕；主题/音效按钮选中 = raised 底 + 金深色描边。都在表达"选中"，语言不统一。
4. **常驻三件套**：`.card/.topic/.study-card/.library-overview` 等一律 `border + 圆角 + box-shadow(0 10px 28px)`，无悬停/默认的层次区分。
5. **固定视口 + calc 魔法数字**：`html,body{overflow:hidden}`、`main{height:100vh}`，各列表靠 `calc(100vh - 430px / 470px / 520px / 570px / 700px …)` 撑高度，减数散落在各断点里；卡片被钉死 `height:180px!important`。这是"内容挤爆卡片 → 打补丁 → 再挤爆"循环的根源，**外部方案没有覆盖到这一层，而它是布局重构的前置条件**。
6. **字号整体偏小**：正文 13px、辅助 10px、打卡卡片问题区 10px，桌面阅读吃力；且卡片标题经多轮补丁从 17px 被压到 14px。

## 三、对外部方案的采纳与修正

### 3.1 完全采纳

| 建议 | 落地要点 |
| --- | --- |
| 六色板 + 75/20/5 配比 | 暖阳主题 token 重定值（见 4.1）；金色只留 5% 点睛 |
| 状态语言统一 | Selected = 浅绿底 + 细绿边，删除金框/金标/光晕（见 4.3） |
| 默认无阴影、悬停才反馈 | 卡片默认 1px 边框无阴影，hover 上浮 + 边框变绿 + 轻阴影 |
| 星球图标改造（方案 A+C） | CSS 伪元素星球 → 内联 SVG 组件，删除 5 层补丁约 150 行；绘本插画只留给关键位置 |
| 迭代顺序 | 严格按 布局 → 层级 → 颜色 → 装饰，每阶段独立提交 |
| A/B 对比与"去掉一半装饰还舒服吗"检验 | 每阶段同视口截图对比后再进入下一阶段 |

### 3.2 修正与补充（外部方案未覆盖）

1. **新增 Phase 0「CSS 还债」**：合并 5 层补丁、收编 148 处硬编码色值、拆分文件。这一步**零视觉变化**，但不做它，后面每一步都在和 396 个 `!important` 打架。这是全方案的第一优先级。
2. **侧边栏宽度不用改**：现值 235px 已在外部方案建议的 220–240px 区间内；真正要做的是收纳设置区（课程源/主题/音效/数据四组堆叠视觉过重）。
3. **方案基于旧截图**：未包含近期新增的全局搜索、课程源切换（自研/JavaGuide）、课文阅读页。首页重构需与这些共存。
4. **calc 魔法数字治理**：改为 flex/grid `min-height:0` 自适应分配，卡片从 `height:180px!important` 改为 `min-height` 由内容撑开；`.card-foot` 从绝对定位改为流式 `margin-top:auto`（避免内容增高时与底部按钮重叠）。
5. **夜航主题同步映射**：两套主题共用同一组语义 token，只精修暖阳会让夜航进一步失衡。夜航色值本阶段原则上不变，仅收编为 token 引用。
6. **移动端对齐**：参考图含移动端稿；现有 620px 断点 + 底部导航须同步回归。断点从 1150/900/820/620 四套收敛为 **1150 / 820 / 620** 三档。
7. **采纳参考图的两个增量点**：① 星球按类别做结构差异（环/卫星/彗尾）+ 克制的色相区分（金/绿/深墨系，不引入冷色破坏暖调）；② 底部提示条升级为「下一站：XX」真实 CTA——数据现成（`states` + `domains` 可算出当前领域第一个未完成知识点），不是装饰。

## 四、设计规范（先写系统，再写页面）

### 4.1 语义 Token（两主题映射）

| Token | 用途 | 夜航（维持现值） | 暖阳（新值） | 暖阳（现值→问题） |
| --- | --- | --- | --- | --- |
| `--bg-page` | 主内容背景 | `#071316` | `#FAF8F1` 纸张白 | `#fff9e9` 偏黄 |
| `--bg-sidebar` | 侧边栏 | `#050d11` | `#F1EDE0` 纸色加深一档 | `#fff4d0` 偏黄 |
| `--surface` | 卡片/面板 | `rgba(18,43,37,.92)` | `#FFFDF8` 暖白 | ≈同背景，无层次 |
| `--raised` | 强调面板（tip/热力图） | `#1b3d31` | `#F4EFE3` | `#fff0bc` 过黄 |
| `--border` | 常规边框 | `#2b5848` | `#DCDDD2` 柔雾灰 | `#e7d39b` 金边泛滥 |
| `--text` | 标题/正文 | `#f3f1d9` | `#293B3A` 深墨 | `#3b4539` 偏灰绿 |
| `--muted` | 次要文字 | `#b9c7ae` | `#5C6B5E` | `#6f7968` |
| `--subtle` | 辅助/meta | `#829a89` | `#9A9884` | `#a09a82` |
| `--green` | 主色（选中/强调/星球） | `#82b879` | `#78966B` 星球绿 | `#719861` |
| `--green-soft` | hover/浅强调 | `#b3d895` | `#A9C39B` | `#bbd795` |
| `--green-bg` | **新增**：选中底色 | `rgba(130,184,121,.16)` | `#E7EFDD` 浅绿底 | 现为硬编码 `#82b87929` 等 |
| `--yellow` | 强调金（5% 配额） | `#f7d56b` | `#E9B95F` 星光金 | `#f0bd4f` |
| `--yellow-deep` | 金的文字级变体 | `#e2ae43` | `#B08136` | `#b8832e` |
| `--rose` | 删除/警示 | `#d78378` | `#C97B6C`（不变） | — |
| `--shadow-hover` | **新增**：悬停阴影 | `0 8px 20px rgba(7,19,22,.35)` | `0 8px 20px rgba(41,59,58,.10)` | 现为硬编码 |
| `--focus-ring` | **新增**：键盘焦点 | `--green-soft` | `--green` | 现为金色 outline |

新增 token 的夜航值在实施时按现观感校准。 Primary 按钮按外部方案用「绿实底 + 白字」，实施时对 `#78966B` 底做一次对比度抽查，不达标则把按钮底加深一档（如 `#6E8C60`）。

### 4.2 色彩配比与金色白名单

约 75% 中性（纸张白/暖白/柔雾灰）、20% 绿与深墨（侧栏结构、导航选中、按钮、标题文字）、5% 金。

**金色白名单**（仅允许出现）：星球图标的环/卫星/彗尾、进度条端点 ✦、Hero 引言装饰、打卡完成庆祝动效、（夜航）星空装饰。
**金色黑名单**（移除）：常规边框、卡片 hover 光圈、导航/领域选中态、提示条与徽章背景、focus ring、按钮描边。

### 4.3 状态规范

| 状态 | 规范 |
| --- | --- |
| Primary 按钮 | 绿实底 + 白字，无金 |
| Secondary 按钮 | 透明底 + 柔雾灰描边 + muted 字；hover 绿描边绿字 |
| Selected（导航/tab/开关统一） | `--green-bg` 底 + 1px `--green` 边 + `--text` 字；删除金框、金色 `:before` 星标、光晕、内嵌条 |
| Default 卡片 | 1px `--border`、无阴影；hover 上浮 2px + 绿边 + `--shadow-hover` |
| Focus（键盘） | 2px `--focus-ring` outline |

### 4.4 字体层级（桌面）

| 层级 | 现值 | 新值 |
| --- | --- | --- |
| 页面主标题 h1 | 38px（子页 32px） | 34px（子页 30px） |
| 区块标题 h2 | 20–23px | 22px |
| 卡片标题 h3 | 13–17px 混乱 | 16px |
| 正文 | 13px | 14px |
| 说明文字 | 11–12px | 13px |
| meta/DM Mono | 9–10px | 11–12px |

### 4.5 间距与圆角

- 间距 4px 基数；卡片间距 16px；区块间距 28px。
- `main`：`max-width:1240px` 居中（现 1400px），左右内边距 40–48px 响应式。
- 圆角三档：控件 10px / 卡片 16px / 大面板 20px。
- 侧边栏维持 235px；设置区四组改紧凑分组（合并边框线、缩小标题），降低视觉权重。

### 4.6 星球图标组件

- 新建 `src/components/PlanetIcon.tsx`：`kind: 'network' | 'ringed' | 'node' | 'comet'`，内联 SVG，token 着色。
- 本体统一哑光球（左上高光 radial 渐变，星球绿系）；四类差异靠**结构**：network 经纬弧线 / ringed 行星环 / node 轨道 + 双卫星 / comet 彗尾，accent 分别取金/绿-soft/深墨/金深，不引入冷色。
- `HomePage`/`Shell`（brand）替换引用后，删除 styles.css 中全部星球伪元素规则（styles.css:57–168 及散落覆盖，约 150 行）。

## 六、风险与验证

| 风险 | 缓解 |
| --- | --- |
| Phase 0 合并覆盖层引入隐性回归 | 以最终计算值为准合并；逐页同视口截图比对；单独 commit 可回滚 |
| calc → flex 改造后滚动行为差异 | Phase 4 独立验证四页内滚 + 移动端；不与视觉改动混提 |

| 硬编码色值收编时误改夜航观感 | 夜航统一取"现值即 token 值"策略，Phase 1 后才允许变值 |
| 无自动化视觉测试 | 验证靠 `npm run build` + 三视口（1600×900 / 1280×800 / 390×844）× 两主题人工截图比对，重点页：星航日志/我的星图/今日航行/知识星库/阅读页/添加知识点弹窗 |

## 七、明确不做的事

- 不改信息架构（页面划分、导航命名、路由关系）。
- 不重设计夜航主题（仅 token 映射与还债）。
- 不引入 UI 框架 / Tailwind / CSS-in-JS，保持手写 CSS + 原生自定义属性。
- 不做参考图中的新页面（课程中心/错题本/收藏夹等）——那是产品功能扩张，不是本次主题优化。
