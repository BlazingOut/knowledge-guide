# 三、怎样才能真正做出《小王子》的感觉？

我建议你不要只把它当作配色主题，而是把它变成整个产品的视觉叙事系统。

你的产品有一个很好的核心概念：秋招知识不是一份需要一次性背完的清单，而是一个逐步探索、逐步点亮的宇宙。

可以建立下面这套映射关系：

知识领域 = 星球

计算机网络、操作系统、数据结构、算法分别是一颗独立的星球。

知识点 = 星星

每完成一个知识点，就点亮一颗星星。不要只显示抽象的百分比。

学习路径 = 航行

下一步告诉用户该去哪里，而不是只让用户在页面上选择分类。

阶段成果 = 发现新星

完成一个阶段后，给予克制、有仪式感的反馈，比如解锁新的知识星图。

最重要的是：不要在所有页面上都堆满星星、行星和轨道。

首页可以有一点绘本气息，知识列表应该易读，刷题页面应该专注，学习完成页可以有一点浪漫。不同页面有不同的视觉密度，整个产品才会有呼吸感。

# 四、用 Vibe Coding 时，怎样避免越改越丑？

这是我认为对你最有帮助的部分。

很多时候，问题不在于你审美不够好，而在于你和 AI 的协作方式没有把设计约束清楚。

## 第一步：先写设计系统，再写页面

不要每次让 AI 直接生成整个页面。先建立一份简短的设计规范，让后续所有页面都遵循它。

你可以直接使用下面这段提示词：

### Prompt 01 · 建立设计系统

&#x20;复制提示词

目标：统一设计语言，而不是马上再生成一套新 UI。

## 第二步：一次只解决一个层面的问题

建议严格按照这个顺序迭代：

1. 先调布局。 先去掉不必要的模块、调整宽度和信息顺序，不要同时改颜色。
2. 再调视觉层级。 明确标题、卡片、按钮和辅助文字谁最重要。
3. 再调颜色。 统一背景、文字、主色、强调色和边框。
4. 最后调装饰。 处理星星、球体、轨道、动画和阴影。

为什么这样做？

如果布局本身有问题，你不断修改配色和阴影，只是在美化一个错误的结构。等结构重做，之前的调整又全部失效。

## 第三步：明确告诉 AI 不要做什么

你可以在每轮 UI 修改时加入这段约束：

### Prompt 02 · UI 精修约束

&#x20;复制提示词

目标：减少 AI 自由发挥，避免每次迭代都产生新的视觉风格。

## 第四步：每次只改一个页面，先看对比再决定

不要让 AI 一次性重做整个产品。

以你现在的“我的星图”页面为例，可以先完成三个版本：

- A：保留现有布局，只统一颜色和状态。
- B：调整信息层级，减少装饰。
- C：保留星球主题，采用更明显的编辑式排版。

把三版放在相同屏幕尺寸下比较，选出最合适的结构，再继续细化。

你要评估的不是“哪个更炫”，而是：

- 第一眼能否知道这个页面是干什么的？
- 能否快速找到下一步要做的事情？
- 不看装饰，页面结构是否仍然清晰？
- 去掉一半的边框和阴影后，页面是不是更舒服？

如果最后一个问题的答案是肯定的，通常说明原来的视觉效果确实堆得太多了。

# 五、如果是我来改你这个产品，我会怎么做？

我会把目标定成：

温柔的绘本气质 + 现代学习工具的清晰结构。

而不是“复古星空风后台管理系统”。

具体来说，我会优先做这五件事：

优先级 1：降低整体黄色占比

让主背景回归暖白，卡片回归接近白色的中性底色，金色仅作为点睛。

优先级 2：减少框线和阴影

普通卡片去掉明显阴影，选中态只保留浅绿底色和细绿色描边。

优先级 3：重新设计首屏结构

把标题、学习进度、下一步行动组成完整的学习首页，再展示知识领域。

优先级 4：缩小装饰元素

球体缩小约 25%–35%，减少无意义的背景星星，让装饰不再和标题竞争。

优先级 5：建立可复用组件

让导航、卡片、按钮、进度条和提示区域遵循同一套设计规范，而不是每个页面单独调样式。

还有一点我想特别提醒你：不要把所有精力都放在“让它更好看”上。 这是一个帮助用户准备 AI 岗位秋招的产品。它最终应该让用户感受到自己正在一步步接近求职目标。

当用户打开页面时，除了觉得好看，还应该知道自己已经学了什么、接下来该学什么，以及距离准备好还有多远。

这才是《小王子》的视觉主题与产品功能真正结合起来的地方。

如果你愿意继续往下做，我建议下一步直接从你的真实前端代码入手，而不是继续凭感觉调整截图。先确定你目前使用的是哪种技术栈，再把这套视觉规范落实到全局样式和可复用组件中，后续每个页面都会更容易保持一致。
