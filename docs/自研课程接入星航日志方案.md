# 自研课程接入星航日志 · 实现方案

## 1. 背景与目标

### 1.1 现状

- **星航日志（knowledge-guide）**：纯前端打卡应用（Vite + React 19 + TS + Tauri 2），三个领域（计算机基础 / 后端开发 / AI 应用开发）的知识点全部指向 **JavaGuide 外部链接**，学习状态存于 localStorage，无后端。
- **课程仓库（ai_application_development_study）**：自研的六大类课程（`courses/` 下 17 门课、120+ 篇 markdown 课文），每门课有 README 大纲；配套可运行代码平铺在 `code/`（如 `code/network/network_lesson01.py`）。已推 Gitee（`Mystery9527/ai_application_development_study`）。

### 1.2 目标

1. 自研课程成为**主要打卡方向**：打卡闭环为「读课文 → 看配套代码 → 标记完成 → 计入热力图」。
2. 支持**课程源切换**：在「自研课程」与「外部资料（JavaGuide）」之间切换，JavaGuide 保留为辅助。
3. **统一数据格式**：自研课程与 JavaGuide 使用同一套领域 → 分类 → 知识点结构，`source.type` 区分来源，未来接入新课程源只需加一个 JSON。

### 1.3 设计原则

- 不引入后端 / 数据库 / 账号系统；课文与代码作为**静态资源**打进应用，网页版与桌面版均可离线阅读。
- 打卡与统计逻辑（localStorage 状态机、热力图、连续天数）**零改动复用**。
- 课程更新后只需**重跑同步脚本**，进度永远以文件系统为准（课程 README 中的进度表实际已落后，如 langgraph 实际已有 12 篇课文）。

## 2. 统一数据格式

### 2.1 现有 JavaGuide 结构（保持兼容）

```ts
type Topic = { id: string; title: string; url: string }
type Category = { id: string; title: string; url: string; topics: Topic[] }
type Domain = { id: string; title: string; description: string; data: { children: Category[] } }
```

JSON 文件顶层为 `{ id, title, source: { name, url, localFile }, children: [...] }`，`main.tsx` 将其包装为 `Domain`。

### 2.2 统一后的结构（扩展点用 `?` 可选字段）

```ts
type Topic = {
  id: string;
  title: string;
  url: string;                  // JavaGuide：外链 http(s)；自研：本地课文相对路径 courses/<课程>/xxx.md
  codeFiles?: string[];         // 自研：配套代码相对路径 courses/code/<课程>/xxx.py，可多个
}
type Category = {
  id: string;
  title: string;
  url: string;                  // JavaGuide：外链；自研：本地课程 README 相对路径 courses/<课程>/README.md
  readme?: string;              // 自研：README 相对路径（与 url 一致，二选一冗余，便于阅读面板复用）
  topics: Topic[];
}
type Domain = { id: string; title: string; description: string; data: { children: Category[] } }
```

### 2.3 课程源

```ts
type SourceId = 'self' | 'javaguide'
type Source = { id: SourceId; title: string; domains: Domain[] }
```

- `self`：由同步脚本生成的 `src/data/self-courses.json`（六大类 → 6 个 Domain）。
- `javaguide`：现有三个 JSON 文件（`计算机基础知识.json` / `后端开发知识.json` / `AI应用开发知识.json`），不改动。

### 2.4 id 防冲突

- 自研分类 id 统一加前缀：`course-<课程目录名>`（如 `course-network`、`course-database-sqlite`）。
- 自研知识点 id：`course-<课程>-<序号>`（如 `course-network-05`）。
- 现有 JavaGuide 分类 id（如 `computer-network`）保持原样，两者互不冲突，localStorage 中的学习状态**共存互不影响**（用户已打卡的 JavaGuide 数据不会丢失）。

## 3. 同步脚本 `scripts/sync-courses.js`

Node 脚本（无第三方依赖，Node 18+ 即可），放在星航日志仓库，命令：

```bash
node scripts/sync-courses.js [课程仓库路径]   # 默认 ../ai_application_development_study
```

### 3.1 输入扫描

- `courses/<六大类>/<课程>/` 下的 `*.md` 课文文件、`README.md`、`assets/` 目录。
- `code/<课程>/` 下的所有代码文件（.py / .sql 等）。

六大类映射为领域：

| courses 目录 | 领域 | Domain id |
| --- | --- | --- |
| engineering | 工程基础 | self-engineering |
| cs-basics | 计算机基础 | self-cs-basics |
| backend | 后端基础 | self-backend |
| ai-apps | AI 应用 | self-ai-apps |
| algorithms | 算法 | self-algorithms |
| capstone | 综合实战 | self-capstone |

### 3.2 课文 → 知识点

- **标题**：读取课文首个 `# 标题` 行（如 `# 第一课：网络分层模型与协议栈`），无标题则用文件名。
- **排序**：按文件名排序（`lesson-01-*`、`NN-*` 自然顺序即课程顺序）。
- **url**：`courses/<课程目录名>/<课文文件名>`（拷贝后的相对路径，相对 public 根）。

### 3.3 课文 ↔ 配套代码配对

提取课文编号 `N`（`lesson-NN-` 或 `NN-` 前缀），在 `code/<课程>/` 下按以下规则匹配（可能命中多个，全部收录）：

- 文件名包含 `lesson0N` / `lesson_N` / `lessonN`；
- 文件名以 `NN-` 或 `N-` 开头（适配 database 的 `03-select-filter-sort-page.sql` ↔ `03-SELECT...md`）。

无匹配则 `codeFiles` 省略（不影响打卡）。`00-qiuckcheck.md`、`动态规划.md` 等无编号课文自然无配对。

### 3.4 输出

1. **`src/data/self-courses.json`**：`Domain[]` 数组，统一 schema。
2. **`public/courses/`** 静态资源：
   - `public/courses/<课程>/<课文>.md` 与 `README.md`
   - `public/courses/<课程>/assets/`（课文内引用的配图）
   - `public/courses/code/<课程>/`（配套代码）

### 3.5 图片相对路径处理

课文 md 内图片引用为 `assets/xxx.png`，渲染时相对页面根会 404。**渲染前替换**为 `courses/<课程>/assets/xxx.png`（在读取 md 文本后、marked 解析前做字符串替换，接受极小概率误伤代码块内同名文本）。

### 3.6 重跑机制

课程新增/修订课文后重跑脚本，JSON 与静态资源同步更新；已打卡的学习状态按 id 匹配不受影响（新增知识点 id 稳定：编号源自文件名，不在文件名尾部追加内容）。

## 4. App 改造（组件拆分 + 新页面 + 样式）

> 本节在实现「自研课程接入」的同时，一并修复/改进上轮评审发现的现有体验缺陷：单文件膨胀（4.7）、移动端无法切换页面（4.8）、搜索仅限当前分类（4.9）、打卡流程被打断（4.10）。

### 4.1 数据加载

```ts
import selfRaw from './data/self-courses.json'        // 新增
const selfDomains: Domain[] = selfRaw as Domain[]
const javaguideDomains: Domain[] = baseDomains        // 现有三领域
const sources: Source[] = [
  { id: 'self',      title: '自研课程', domains: selfDomains },
  { id: 'javaguide', title: 'JavaGuide', domains: javaguideDomains },
]
```

### 4.2 课程源切换

- App 新增 state：`sourceId`（初始 `'self'`，自研为主）、`reading: Topic | null`。
- `domains` / `domain` / `activeId` 改为随源切换联动；`switchSource(id)` 重置领域与分类。
- 侧边栏（Shell）新增「课程源」面板，复用 `.theme-switch` 样式：

```
课程源
[ ✧ 自研课程 ] [ 外源 JavaGuide ]
```

- 「星航日志」统计页随源切换统计当前源的领域（`StarLog`/`Home` 已按 `domains` 计算，无需改动）。

### 4.3 课文阅读面板（新页面 `read`）

- `Page` 类型扩展 `'read'`；App state `reading: Topic`。
- 组件 `ReadPage`：
  - `useEffect` 中 `fetch(topic.url)` 获取课文文本；
  - **marked 渲染 + DOMPurify 净化**：`DOMPurify.sanitize(marked.parse(md))`（渲染前做 3.5 的图片路径替换）；
  - 若 `topic.codeFiles` 存在，逐文件 `fetch` 显示在 `<pre><code>` 只读区域；
  - 顶部：返回、课文标题、状态快捷切换按钮（开始学习 / 已完成），点击后按现有 `update` 逻辑落库并计入热力图与音效。
- 依赖：`npm install marked dompurify`（dompurify v3 自带类型）。

### 4.4 卡片动作适配

| 场景 | 现行为 | 改造后（自研源） |
| --- | --- | --- |
| `Topic` 组件「阅读资料 ↗」 | `openLink(url)` 外开 | 点击 → `setReading(topic)` → 进入 read 页 |
| `StudyCard` 整卡点击 | `openLink(url)` 外开 | 点击 → 进入 read 页 |
| `StudyCard` 底部来源标注 | `◉ JavaGuide · ⌘ 计算机网络` | 显示「◉ 自研课程 · ⌘ <课程名>」 |
| Detail 页「打开专题 ↗」 | `openLink(category.url)` 外开 | 自研：打开课程 README 阅读；JavaGuide：保持外链 |

传参方式：给 `Detail` / `Checkin` / `Topic` / `StudyCard` 增加可选回调 `onRead?: (topic: Topic) => void`，由 App 注入（`setReading` + `setPage('read')`）；源为 javaguide 时不传，走原外链逻辑。**JavaGuide 相关组件行为零变化**。

### 4.5 localStorage 兼容

- 学习状态 key、完成日志、自定义知识点 key 全部不动。
- 自研知识点 id 与 JavaGuide 不冲突，两源数据在星航日志页切换查看。
- 旧版浏览器中已保存的 JavaGuide 状态（含 `seen`/`answerable` 历史值兼容）不受影响。

### 4.6 样式

`styles.css` 追加 read 页样式：阅读面板卡片（复用 `--surface`/`--border` 变量、两种主题自动适配）、md 排版（标题/表格/代码块）、代码查看区（等宽字体、横向滚动）、加载与空态。新增样式不再使用 `!important` 堆叠。

### 4.7 组件与文件拆分（借接入一并落地）

`main.tsx` 目前 320 行容纳全部组件与逻辑，接入自研课程（新增源切换、阅读页、更多字段）后会急剧膨胀。拆分方案**不改变任何现有行为**，纯搬移：

```text
src/
├── types/knowledge.ts        # Topic / Category / Domain / SourceId / Status / UserState 等全部类型
├── lib/storage.ts            # readStates / readCustomTopics / localStorage key 常量 / 备份导出导入
├── lib/progress.ts           # 完成率、可回答率、连续天数、热力图数据计算
├── lib/sound.ts              # Web Audio 音效（playTick / playDing / playFanfare）
├── data/                     # 三个 JavaGuide JSON + self-courses.json（脚本生成）
├── components/
│   ├── Shell.tsx             # 侧边栏 + 课程源切换 + 移动端导航
│   ├── Topic.tsx / StudyCard.tsx / CheckinCard.tsx
│   └── ReadPage.tsx          # 课文阅读 + 代码查看
├── pages/
│   ├── StarLogPage.tsx / HomePage.tsx / CheckinPage.tsx / DetailPage.tsx
└── main.tsx                  # 仅保留入口与 App 状态编排
```

拆分顺序：先抽 types 与 lib（无 UI 风险）→ 再抽 ReadPage 与 Shell → 最后按页拆组件；每步保持 `npm run build` 通过。

### 4.8 移动端页面导航（修复现有缺陷）

`@media(max-width:620px)` 下 `.side{display:none}`，但 `.mobile-theme-switch` 只有 ☾/☼ 主题按钮——**手机上无法切换「星航日志/我的星图/今日航行/知识星库」四个页面**。修复：移动端固定底部导航栏（四个页面按钮 + 主题切换 + 音效开关），替换现有浮动主题按钮。

### 4.9 全局搜索

Detail 页搜索仅限当前分类。新增全局搜索：跨**当前源**全部 domains 平铺匹配（title 包含，命中按知识点顺序），结果点击直达——自研源进 read 页，JavaGuide 源进 Detail 页。

### 4.10 连续学习流「下一篇」

打卡流程目前读完课文要手动切回页面标记。read 页底部提供「下一篇 →」：按当前分类 topics 顺序定位下一篇，点击自动切换并标记为「学习中」；最后一篇提示返回列表。让打卡形成连续节奏。

## 5. 配套代码问题的处理（明确结论）

**应用内只读查看 + 运行提示，不做应用内执行。**

- 打卡卡片提供「读课文」「看代码」两个动作；代码在应用内以纯文本展示（含文件名与运行提示，如 `python code/network/network_lesson01.py`）。
- 真正运行代码仍在课程仓库的终端里执行——课文本身就带有运行说明，与应用内阅读互补。
- 不做应用内沙箱执行（浏览器 / WebView 无本地文件系统权限，需要后端 + 沙箱，成本高，秋招时间紧不划算；如需后续再做）。

## 7. 风险与注意事项

1. **图片路径**：课文 md 引用 assets 配图时，渲染前必须重写相对路径（见 3.5），否则阅读页图片 404。
2. **id 稳定性**：知识点 id 由「课程名 + 文件名序号」生成，课程文件改名会导致该知识点学习状态"失联"（新 id 视为未学）。建议课程文件改名后重跑脚本并在重跑前导出备份。
3. **README 进度表滞后**：README 中的课程进度表（如 langgraph 7/13）与实际文件数不一致，脚本以文件系统为准，无需手动维护。
4. **`marked` 异步 API**：新版本 `marked.parse` 在 async 模式下返回 Promise，需确保以同步方式调用（不开启 async 选项）或将结果 `String()` 化，避免渲染空白。
5. **大文件**：个别课文（如 langgraph 12 课）较长，阅读页滚动容器需正确限定视口高度（现有 `.list` 已有同款处理可参考）。
6. **Tauri 桌面端**：`fetch('/courses/...')` 在 Tauri 打包后经 `tauri://localhost` 协议可访问 `dist` 内静态资源，无需额外配置；如遇 CORS 问题再评估 `assetProtocol` 方案。
7. **组件拆分回归风险**：4.7 拆分属纯搬移（不顺手改逻辑），每步跑 `npm run build` 保持可编译，行为验证依赖 M5 人工清单。

## 8. 后续可选项（本期不做）

- 代码语法高亮（引入 highlight.js，简单，成本低，可随时加）。
- 课文「学习目标」自动提取为验收问题，打卡时对照自查。
- 课程优先级标注（必背 / 高频 / 中频）由课文编号或 frontmatter 提供。
- 应用内运行代码（沙箱执行 / 容器化），需要后端，另行立项。
