# 第19课:综合-设计：真实业务场景的面试题与思考方法

> 前面的课按知识点讲机制，这一篇反过来：从真实业务场景出发，把知识点串起来回答系统设计题。
>
> 编排顺序是一条故事线：**数据增长 -> 写入并发 -> 线上故障 -> 查询优化 -> 数据安全**，每题给"拆题思路 + 分层回答链 + 追问"，回答链标注所用课号。

## 一、综合题怎么答：拆题三步

真实业务题没有"标准 SQL 答案"，考官想看你**会不会把模糊问题拆成清楚的知识点**。三步：

```text
1. 问清约束：数据量多大？读多还是写多？能接受延迟吗？（不先问就答是最大扣分点）
2. 分层回答：先方案层（接口/架构怎么设计），再机制层（为什么快/为什么慢），最后验证层
3. 每层验证：怎么证明方案有效（EXPLAIN、监控指标、压测）
```

## 二、数据增长：加载与存储

### 1. 数据几个 G，前端列表怎么加载

**拆题**：前端不能拿全量；要回答"接口怎么设计 + 查询怎么快 + 数据怎么分布"三层。

**回答链**：

```text
1. 接口分页（第 4 课）：每页 20~50 条，前端翻页或滚动加载
2. 索引（第 9 课）：分页 SQL 的 WHERE / ORDER BY 要有索引，避免全表扫描加文件排序
3. 深分页（第 4 课）：OFFSET 翻到 100 页后很慢（被跳过的行也要扫描），改键集分页（游标）
4. 验证（第 10 课）：EXPLAIN 看走索引、扫描行数、Using filesort
5. 整体（第 14、15 课）：冷热分离归档、监控连接与磁盘；再涨才考虑分库分表
```

**追问**：翻到第 100 页怎么办？为什么 OFFSET 大就慢？怎么证明你的分页方案快？

### 2. 订单表几个亿行，怎么存

**拆题**：先确认"索引和 SQL 已经合理"，再谈数据层面的治理，最后才谈架构。

**回答链**：

```text
1. 先优化查询（第 7、8 课）：索引、SQL、深分页——数据大不是慢查询的默认借口
2. 冷热分离归档（第 16 课）：历史订单迁到历史表/库，主表变小变快
3. 分区表（第 16 课）：按时间 RANGE 分区，查询剪枝 + 滚动清理
4. 读写分离（第 15 课）：读多写少时从库分担读，注意复制延迟
5. 分库分表（边界）：单实例容量/吞吐真不够才做，代价是跨库事务、JOIN、分页
```

**追问**：归档期间业务怎么写？分区表有什么限制？为什么分库分表是最后手段？

### 3. 按时间排序分页，时间相同的行怎么办

**拆题**：分页必须有**稳定排序**，排序键必须唯一。

**回答链**：

```text
1. 稳定排序（第 4 课）：没有 ORDER BY 不能假设顺序
2. 唯一排序键：时间相同会漏行/重复，要加 id 破平局：
   ORDER BY created_at DESC, id DESC
3. 游标分页：时间游标也要带 id：WHERE created_at < ? OR (created_at = ? AND id < ?)
```

**追问**：为什么时间相同不加 id 会漏数据？

## 三、写入并发：正确性

### 4. 两个人同时买最后一件商品，怎么防超卖

**拆题**：本质是"检查和写入要原子"，不能先 SELECT 再 UPDATE。

**回答链**：

```text
1. 条件更新（第 5 课）：UPDATE ... SET stock = stock - 1 WHERE id = ? AND stock > 0
   用影响行数判断成功与否
2. 事务边界（第 11 课）：扣库存 + 建订单同事务同连接，失败整体回滚
3. 锁与并发（第 12 课）：条件更新本身原子；高并发下热点行要考虑锁持有时间
4. 备选：版本号乐观锁（第 13 课）：UPDATE ... SET stock = stock - 1, version = version + 1
   WHERE id = ? AND version = ?
```

**追问**：为什么"先查再改"会超卖？条件更新为什么安全？乐观锁和悲观锁怎么选？

### 5. 重复支付 / 重复提交怎么防

**拆题**：数据库层（唯一约束）和应用层（幂等键）要一起谈。

**回答链**：

```text
1. 唯一约束（第 3 课）：支付单号/幂等键加 UNIQUE，重复插入会被拒绝
2. 冲突处理（第 5 课）：INSERT IGNORE 或 ON DUPLICATE KEY UPDATE 决定冲突时怎么办
3. 幂等键（第 13 课）：请求带业务幂等键，重试拿同一个键，只生效一次
4. 重试要幂等（第 13 课）：网络超时后的重试不能造成二次扣款
```

**追问**：唯一约束能完全解决幂等吗？为什么不能只用 INSERT IGNORE？

## 四、线上故障：定位

### 6. 线上一条 UPDATE 卡住不返回，怎么定位

**拆题**：先判断是"在等锁"还是"执行慢"，再找持锁者。

**回答链**：

```text
1. 证据（第 18 课）：SHOW PROCESSLIST 看状态和等待
2. 锁等待（第 12 课）：performance_schema.data_locks / data_lock_waits 找谁持锁谁在等
3. 长事务（第 11 课）：事务开始多久、最后提交时间，是不是漏提交
4. 死锁（第 12 课）：SHOW ENGINE INNODB STATUS 看最近死锁
5. 处理：统一访问顺序、缩短事务、补索引缩小锁范围；kill 前确认影响
```

**追问**：怎么区分锁等待和执行慢？kill 连接前要注意什么？

### 7. 系统卡顿、CPU 打满，从数据库角度怎么排查

**拆题**：数据库不是唯一嫌疑，但先看监控指标（第 17 课），再缩小到 SQL/锁/连接。

**回答链**：

```text
1. 指标（第 17 课）：Threads_running、慢查询数、连接数、磁盘——哪个先异常
2. 慢查询（第 10 课）：从慢查询日志拿真实 SQL 和参数
3. EXPLAIN（第 10 课）：看是否全表扫描、filesort、临时表
4. 排除锁（第 10、16 课）：Threads_running 高可能是都在等锁，不是 SQL 慢
5. 验证：优化后看指标回落
```

**追问**：CPU 打满一定是 SQL 慢吗？还可能是什么？

## 五、查询优化

### 8. 加了索引还是慢，可能是什么原因

**拆题**：索引不是"加上就快"，要 EXPLAIN 确认索引真的被用上。

**回答链**：

```text
1. 没走索引（第 10 课）：EXPLAIN 看 type / key——隐式类型转换、函数套列、LIKE '%x'
2. 走了但没用好（第 9 课）：最左前缀没满足、回表过多（要覆盖索引）
3. 选择性低（第 9 课）：低区分度字段索引帮不上，优化器宁愿全表扫描
4. 数据分布（第 10 课）：统计信息过时或数据量变化导致计划变化
5. 不是执行计划问题：可能在等锁（第 10、16 课）
```

**追问**：怎么知道索引有没有被用上？覆盖索引为什么快？

## 六、数据安全：恢复

### 9. 误删了数据（DELETE 忘 WHERE），怎么恢复

**拆题**：先说恢复思路（全量+增量），再说预防。

**回答链**：

```text
1. 恢复思路（第 15 课）：恢复最近一次全量备份 + 回放 binlog 到误删前的时间点
2. 日志基础（第 14 课）：binlog 记录逻辑变更，是时间点恢复的素材
3. 校验：行数、关键数据对账，导入新实例再切换
4. 预防：软删除（第 5 课）、DELETE 前先 SELECT 确认、备份策略和恢复演练
```

**追问**：为什么主从复制不能替代备份？RPO 和 RTO 分别由什么决定？

