# MySQL 与 InnoDB

> 这条课程线面向 MySQL 8.x，既补齐实际开发需要的基础 SQL，又深入讲清 InnoDB 的索引、执行计划、事务、锁、日志和线上排查。
>
> 写作风格沿用 MySQL 速成文档：先建立直觉，再解释机制，配合完整 SQL、典型结果、会话实验和面试回答。基础语法集中用几课讲明白，不把每个语法点拆成独立课程；真正需要理解原理的部分再单独展开。

## 一、课程主线

```text
先能定义数据、写入数据、查询数据
    -> 再理解 MySQL 如何通过索引加速查询
    -> 再理解事务、MVCC 和锁如何处理并发
    -> 再把这些机制用于下单、库存和账户场景
    -> 再理解日志、恢复、数据治理（归档/监控）
    -> 最后综合排查与系统设计
```

课程中反复使用用户、商品、订单、订单明细和账户作为示例：

```text
基础 SQL：如何定义和操作这些数据
索引：如何快速找到这些数据
事务和锁：多人同时修改时如何不出错
日志：修改提交后如何恢复和复制
```

## 二、课程边界

本课程重点讲 MySQL 8.x，存储引擎重点是 InnoDB。涉及 MySQL 以外的数据库时，只用于指出实现差异，不能把 InnoDB 的结论说成所有数据库都如此。

本课程包含基础 SQL，但不追求覆盖完整 SQL 标准。重点是后端开发最常用、最容易出错、并且能够连接到 MySQL 原理的内容：数据库和表、数据类型、约束、增删改查、聚合、JOIN、子查询、CTE、窗口函数、事务和常用管理语句。

课程代码和实验以后放在 `code/database/`，正式课文放在本目录。不要求读者必须安装 MySQL；安装了就按课文验证，没有安装则阅读语句、典型输出和会话执行过程。

### 第 10 课：EXPLAIN、慢查询与查询优化

### 第 12 课：MVCC、快照读、当前读与锁

### 第 14 课：undo log、redo log 与 binlog

目标：分清三类日志的层级和职责，理解提交、回滚、崩溃恢复和复制之间的关系。

内容：

- `undo log`：事务回滚和 MVCC 历史版本；
- `redo log`：InnoDB 数据页的崩溃恢复；
- `binlog`：Server 层的逻辑变更、复制、备份和时间点恢复；
- 为什么 redo log 和 binlog 都需要；
- 日志刷盘、数据页刷盘和事务提交；
- 两阶段提交要解决的一致性问题；
- 数据库异常重启后的恢复过程；
- 长事务为什么会影响 undo log 清理；
- 备份、恢复和复制只建立基本关系，不深入 DBA 工具实现。

核心记忆方式：

```text
undo log：撤销修改、保存历史版本
redo log：重做修改、保证崩溃恢复
binlog：记录变更、用于复制和逻辑恢复
```

实践：根据“修改—提交—数据页未刷盘—异常重启—恢复”的时序，说明三类日志分别发挥什么作用。

面试考点：undo log、redo log、binlog 的区别；为什么需要两阶段提交；数据库异常重启后如何恢复已提交事务。

面试考点：主从复制延迟如何理解；备份和高可用有什么区别；为什么主从复制不能替代备份。

### 第 16 课：数据归档、冷热分离与分区

目标：理解数据增长给大表带来的问题，能解释冷热分离、归档和分区的基本思路与边界。

内容：

- 数据增长给大表带来的问题（查询、备份、维护变慢）；
- 冷热分离：热表与历史表的分工，历史库 / 独立实例形态；
- 归档的基本流程（分批搬移、分批删除、按批次校验、断点续跑）；
- 归档的一致性窗口和大 DELETE 的代价（undo log、锁、复制延迟）；
- 建新表 + RENAME 切换的归档方案；
- 分区表：按范围分区、查询剪枝、滚动清理；
- 分区表达式与剪枝验证（EXPLAIN `partitions` 列，串联第 10 课）；
- 分区表的限制（所有唯一索引须含分区键、分区不等于更快）；
- 归档 / 分区 / 分库分表的边界与选择顺序。

实践：设计订单表的冷热分离方案，说明归档流程和对账方式。

面试考点：订单表几个亿行怎么处理；分区表的好处和限制。

### 第 17 课：数据库监控与容量

目标：知道监控看哪些指标、什么阈值要警惕，能处理磁盘空间不足并做基础容量规划。

内容：

- 监控的核心指标：连接与线程、慢查询、锁与死锁、复制延迟、磁盘；
- 各指标的关注点与直觉阈值；
- 磁盘空间不足：发现、定位、处理、预防；
- binlog 保留与磁盘关系；
- 容量规划：按增长率而不是存量。

实践：用 `SHOW GLOBAL STATUS` / `SHOW GLOBAL VARIABLES` 观察本机连接、慢查询和复制相关配置。

面试考点：数据库监控看哪些指标；磁盘空间不足怎么处理。

### 第 18 课：综合-排查（常见故障与排查方法）

目标：能按"现象 -> 证据 -> 原因 -> 验证"排查常见线上故障，并串联前课知识点。

内容：

- 通用排查流程（确认范围、收集只读证据、缩小、处理、验证）；
- 连接失败和连接数耗尽（串联第 1 课连接池）；
- 长事务、锁等待和死锁（串联第 9、10 课）；
- 慢查询和执行计划变化（串联第 10 课）；
- 磁盘空间不足（串联第 14、15 课）；
- DDL、MDL 和大表变更（串联第 2 课 ALTER）；
- 分库分表只作边界认识。

实践：模拟"一条 UPDATE 卡住"，用 `SHOW PROCESSLIST` 和 `data_lock_waits` 定位持锁者。

面试考点：线上 SQL 慢如何排查；MDL 是什么；长事务有什么影响；磁盘空间不足怎么处理。

### 第 19 课：综合-设计（真实业务场景面试题）

目标：能把前面各课知识点串成系统设计题的完整回答，掌握"拆题三步"。

内容：

- 综合题怎么答：问清约束、分层回答、每层验证；
- 数据增长主题：大表前端加载、订单几亿行存储、稳定排序分页；
- 写入并发主题：防超卖、防重复支付；
- 线上故障主题：UPDATE 卡住、系统卡顿；
- 查询优化主题：加了索引还慢；
- 数据安全主题：误删恢复；
- 每题给拆题思路、分层回答链和常见追问。

实践：对着题目先口述，再对照回答链找差距。

面试考点：大表数据前端加载怎么设计；订单表几个亿行怎么处理；如何防超卖、防重复支付；如何排查线上卡顿。

## 四、阶段验收

完成课程后，应当能够：

1. 创建数据库和业务表，并根据业务含义选择数据类型、主键、唯一约束和默认值。
2. 写出常见的 `INSERT`、`UPDATE`、`DELETE`、`SELECT`、聚合、JOIN、子查询和窗口函数。
3. 正确处理 `NULL`、日期范围、`NOT IN`、分页、稳定排序和影响行数。
4. 画出 InnoDB 主键索引和二级索引，解释 B+ 树、回表、覆盖索引和最左前缀。
5. 阅读一份 `EXPLAIN`，指出实际索引、扫描行数、全表扫描、回表、排序和临时表。
6. 说明事务的 ACID、四种隔离级别，以及脏读、不可重复读和幻读。
7. 区分快照读、当前读、MVCC、行锁、间隙锁、临键锁和死锁。
8. 使用当前读、条件更新或版本号解决库存扣减和账户更新问题。
9. 分清 `undo log`、`redo log`、`binlog`，并解释崩溃恢复、备份和复制的关系。
10. 面对慢查询、锁等待、长事务、连接耗尽或 DDL 阻塞，能够先拿证据，再定位原因并验证修复。
11. 能解释数据归档、冷热分离和分区的基本思路与边界，能处理磁盘空间不足，能按增长率做容量规划。
12. 能把分页、索引、EXPLAIN、归档、读写分离等知识点串成系统设计题（大表加载、防超卖、防重复支付等）的完整回答。

## 五、编写约束

- 每条底层结论标明适用的 MySQL 版本或 InnoDB 引擎；不要把 InnoDB 行为说成所有数据库的统一行为。
- 基础语法必须讲清楚，但集中在前 6 课，不把每个语法点拆成一节独立课。
- SQL 示例优先使用完整业务场景，不能只堆孤立语法；每个关键语法都说明结果、边界和常见错误。
- 课文中的执行计划和锁现象是典型示例，必须说明实际结果还受数据量、统计信息、索引和版本影响。
- 每课都要包含一个核心模型、一个可观察的实践现象和一组面试回答，不只罗列名词。
- 不深入 InnoDB 源码、完整优化器成本模型、复制协议细节、复杂高可用集群、分布式事务和完整分库分表方案；需要时另开专题。
- 不要求读者必须安装 MySQL；安装了提供验证步骤，没有安装提供语句、典型结果和推理过程。
- 先按本大纲逐课编写，除非用户明确要求，不提前扩展到下一课。
