# 第17课:数据库监控与容量

> 前面的课解决"问题怎么处理"，这一篇解决"问题还没发生怎么发现"：监控看哪些指标、什么阈值要警惕、磁盘不够了怎么办、容量怎么估。
>
> 本篇按知识点讲：核心指标、磁盘与容量、监控到排查的衔接（第 18 课）。

**学习目标：**

1. 能说出数据库监控要看哪几类指标，各自代表什么；
2. 能对连接数、慢查询、锁等待、复制延迟给出关注阈值和直觉；
3. 能处理"磁盘空间不足"：发现、定位、处理、预防；
4. 能做基础的容量估算（数据增长、备份空间、binlog 保留）。

## 一、监控的作用：在问题发生前发现信号

线上问题最好在"发生前"或"刚冒头"时被发现。监控回答三个问题：

```text
现在状态怎么样？（连接、线程、慢查询、磁盘）
趋势怎么样？（数据量、连接数、慢查询数的增长）
快到极限了吗？（连接数接近 max_connections、磁盘接近 85%）
```

监控不是越多越好，而是每个指标都对应一个"快出问题"的信号。

## 二、核心指标

### 1. 连接与线程

```sql
SHOW GLOBAL STATUS LIKE 'Threads_connected';  -- 当前连接数
SHOW GLOBAL STATUS LIKE 'Threads_running';    -- 正在执行的线程数
SHOW GLOBAL VARIABLES LIKE 'max_connections';
```

关注点：

- `Threads_connected` 接近 `max_connections`：再增长就要连接耗尽（第 18 课排查）；
- `Threads_running` 明显高于连接数：很多连接在排队，可能在等锁或执行慢 SQL。

### 2. 慢查询

```sql
SHOW GLOBAL VARIABLES LIKE 'slow_query_log';
SHOW GLOBAL VARIABLES LIKE 'long_query_time';
```

关注点：慢查询数量随时间是否增长、有没有新出现的慢 SQL（结合第 10 课慢查询日志）。

### 3. 锁与死锁

- 死锁次数（`SHOW ENGINE INNODB STATUS` 或错误日志）；
- 锁等待时长（`performance_schema.data_lock_waits`）。

关注点：死锁或锁等待突增，通常伴随某个新功能或新 SQL 上线。

### 4. 复制

- 从库回放延迟（`SHOW REPLICA STATUS` 的 `Seconds_Behind_Source`）。

关注点：延迟持续增长超过读写分离能接受的范围（第 15 课讲过读旧数据风险）。

### 5. 磁盘与容量

- 数据目录、binlog、临时文件占用的磁盘；
- 磁盘使用率（通常到 70%~85% 就要规划，而不是 99% 才处理）。

五类指标汇总：

| 指标类 | 关键指标 | 警惕信号 |
|---|---|---|
| 连接与线程 | `Threads_connected`、`Threads_running`、`max_connections` | 连接数接近上限；运行线程明显高于连接数 |
| 慢查询 | `slow_query_log`、`long_query_time`、慢查询数量 | 数量随时间增长、出现新慢 SQL |
| 锁与死锁 | 死锁次数、`data_lock_waits` | 突增，常伴随新功能或新 SQL 上线 |
| 复制 | `Seconds_Behind_Source` | 延迟持续增长，超过读写分离能接受的范围 |
| 磁盘 | 数据文件、binlog、临时文件占用 | 使用率到 70%~85% 就该规划 |

## 三、磁盘空间不足的处理链

发现 -> 定位 -> 处理 -> 预防：

```text
发现：磁盘使用率接近阈值，或写库开始报错
定位：数据文件、binlog、临时文件、慢查询日志各占多少
处理：归档冷数据（第 16 课）、清理过期 binlog、扩容磁盘、调整日志保留期
预防：设置磁盘使用率告警（70%~85% 触发）、控制 binlog 保留、监控增长率
```

binlog 是常见的"隐形杀手"：写入量大时 binlog 增长快，要设置 `binlog_expire_logs_seconds` 等保留策略。

## 四、容量规划基础

容量不只是"现在够不够"，而是"按当前增长率能撑多久"：

```text
数据量增长率：每天新增多少行、多少 GB
备份空间：全量备份 + binlog 保留需要的空间
日志空间：binlog、错误日志、慢查询日志
索引空间：索引通常比数据更大
```

一句话估算：**看增长率而不是存量**，按"3~6 个月后需要什么"规划，比"现在多大"更有用。

## 五、常见错误自查清单

- 只监控 CPU 和内存，不看连接数、慢查询数和磁盘；
- 等到磁盘 99% 才处理，而不是设 70%~85% 的告警；
- 只看当前值不看趋势，等指标爆了才发现；
- 把 `max_connections` 调大当作处理连接数增长的办法；
- 不设 binlog 保留策略，写库量大了磁盘直接打满。

## 七、面试回答模板

### 题目：数据库监控一般看哪些指标？

> 至少看五类：连接与线程（Threads_connected、Threads_running、max_connections）、慢查询（数量和新增 SQL）、锁与死锁、复制延迟、磁盘与容量。每个指标对应一个"快出问题"的信号，比如连接数接近上限、慢查询突增、复制延迟持续增长。

### 题目：磁盘空间不足怎么处理？

> 先定位谁占的空间：数据文件、binlog、临时文件还是日志；再按情况处理——归档冷数据、清理过期 binlog（并设保留策略）、扩容磁盘；最后设置磁盘使用率告警（70%~85% 触发）和监控增长率，避免再次打满。
