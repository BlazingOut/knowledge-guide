# 第7课:路由拆分和项目结构

## 本课范围

第六课把依赖、路由和 SQL 放在一个文件中。本课只做一次最小拆分，让学生看清：

```text
main.py
  -> routers/items.py
      -> dependencies.py
          -> store.py
              -> SQLite
```

本课不追求完整分层应用，不展开 Service、Repository、ORM、认证系统、数据库迁移和测试体系。后续遇到真实复杂度时，再增加对应抽象。

## 学习目标

完成本课后，你应当能够：

- 使用 `APIRouter` 拆分资源路由；
- 使用 `app.include_router()` 把路由注册回应用；
- 解释 `main.py`、路由、依赖和 Store 的职责；
- 使用包内相对导入启动应用；
- 画出一个请求从路由到 SQLite 的调用链；
- 保持拆分前后的基本接口行为一致。

## 1. 为什么要拆分

单文件适合学习一个知识点，但路由、数据库连接和 SQL 混在一起后，修改一个部分容易影响其他部分。

拆分的目标不是增加文件数量，而是让不同变化原因分开：

| 模块 | 负责什么 |
| --- | --- |
| `main.py` | 创建应用、初始化数据库、注册路由 |
| `routers/items.py` | HTTP 方法、路径、请求和响应 |
| `dependencies.py` | 创建请求需要的数据库连接和 Store |
| `store.py` | 执行 SQL 和提交写操作 |

## 2. 使用 `APIRouter`

路由文件中使用 `APIRouter`：

```python
router = APIRouter(prefix="/items", tags=["items"])


@router.get("")
def list_items():
    ...
```

`APIRouter` 本课用到的参数：

- `prefix`：给路由统一添加路径前缀；
- `tags`：在 `/docs` 中对接口分组。

在 `main.py` 中注册：

```python
app = FastAPI(title="FastAPI 第七课")
app.include_router(items_router)
```

最终路径由两部分组合：

```text
prefix "/items" + route path ""
= GET /items
```

如果路由写成 `@router.get("/{item_id}")`，最终路径就是 `/items/{item_id}`。

## 3. 四个文件的职责

### 3.1 `main.py`

只负责组装应用：

```python
setup_database()
app = FastAPI(title="FastAPI 第七课")
app.include_router(items_router)
```

它不直接实现每个接口的 SQL。

### 3.2 `routers/items.py`

负责 HTTP 边界。输入模型和输出模型暂时放在路由文件中，因为本课重点是路由拆分，避免同时引入独立 Schema 层。

```python
@router.get("", response_model=list[ItemOutput])
def list_items(
    limit: int = Query(default=10, ge=1, le=100),
    store: Annotated[ItemStore, Depends(get_store)],
):
    return store.list_items(limit)
```

路由知道 HTTP 参数和依赖，但不直接拼接 SQL。

### 3.3 `dependencies.py`

第六课的连接依赖继续复用：

```python
def get_store(
    connection: Annotated[sqlite3.Connection, Depends(get_connection)],
) -> ItemStore:
    return ItemStore(connection)
```

连接由 `get_connection` 创建并关闭，Store 只持有当前请求的连接。

### 3.4 `store.py`

Store 只负责数据库操作：

```python
class ItemStore:
    def list_items(self, limit: int = 10):
        ...

    def create_item(self, content: str):
        ...
```

它负责参数化 SQL和 `commit()`，不负责读取 HTTP 请求，也不决定 URL 或状态码。

## 4. 依赖方向

当前示例保持单向依赖：

```text
main
  -> router
      -> dependencies
          -> store
              -> sqlite3
```

底层 Store 不应该反过来导入路由，否则容易形成循环导入：

```text
router -> store -> router
```

如果后续增加业务规则，可以再引入 Service。但当前示例没有足够业务复杂度，因此不额外创建 Service 文件。

## 5. 包内导入和启动

`lesson07_app` 是一个 Python 包。包内模块使用相对导入：

```python
from .config import DATABASE
from .store import ItemStore
```

从 `code/fastapi` 目录启动：

```bash
python -m uvicorn lesson07_app.main:app --reload --port 8006
```

`lesson07_app.main:app` 的含义是：

```text
模块路径：lesson07_app.main
对象名称：app
```

不要直接运行 `python lesson07_app/main.py`，因为直接运行包内文件时，相对导入可能无法正确解析。

## 6. 路径配置

配置集中在 `config.py`：

```python
DATABASE = Path(__file__).resolve().parent.parent / "study.sqlite3"
```

这样数据库路径不会因为 SQL 文件或路由文件移动而各自发生变化。多个模块不应该分别拼接数据库路径，否则拆分后可能出现接口使用不同 SQLite 文件的问题。

## 8. 运行和观察

在仓库根目录执行：

```bash
cd code/fastapi
python -m uvicorn lesson07_app.main:app --reload --port 8006
```

打开：

```text
http://127.0.0.1:8006/docs
```

观察：

1. `GET /items` 能正常查询；
2. `GET /items?limit=1` 会限制返回数量；
3. `POST /items` 创建事项；

## 11. 面试高频考点

### 11.1 为什么要拆分路由？

路由模块负责 HTTP 边界，主应用负责组装。拆分后不同资源的接口可以独立维护，但拆分本身不是目的，重点是职责清晰和依赖方向明确。

### 11.2 Router、Dependency、Store 如何区分？

```text
Router      -> HTTP 参数、路径和响应
Dependency  -> 请求资源和公共依赖
Store       -> 数据库访问和 SQL
```

### 11.3 为什么当前不增加 Service 层？

当前只有查询和创建两个简单操作，没有足够的业务编排。过早加入 Service 会增加跳转层级，却不能帮助学生理解新的职责。等出现跨多个 Store 的规则或复杂业务流程时，再引入 Service 更合理。

### 11.4 路由拆分会不会改变性能？

单纯移动模块通常不会明显改变性能。它主要改变代码组织方式。真正影响性能的是数据库查询、网络调用、连接管理和序列化。
