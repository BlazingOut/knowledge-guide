# 第八课：沙盒与执行环境

第七课解决了"能不能调"（权限）；本课解决"在哪调"（执行环境）。Agent 的工具和代码运行在什么地方、被什么边界罩住、超时了能不能真的杀掉——这些是生产 Agent 的硬问题，因为工具执行的往往就是"被模型一句调用触发"的不可信代码。不讲：容器/Kubernetes 部署细节（docker 课与阶段 10）、cgroup/namespace 底层实现（点到）、seccomp/eBPF 高级隔离。

**学习目标：**

1. 能说明为什么工具/代码执行必须沙盒（三个理由）；
2. 能比较容器、轻量虚拟化、进程级隔离的取舍；
3. 能说出资源限制的四个维度，并解释"超时强杀"为什么必须发生在沙盒里；
4. 能设计输出防逃逸（边界、截断、异常提炼）；
5. 能设计沙箱资源池的参数（预热、复用、TTL、调度、超限策略）。

## 1. 沙盒解决什么问题：不可信执行的三种风险

先定义：**沙盒（sandbox）**是给不可信代码/工具的执行划定隔离边界，并对其资源与输出做限制的运行环境。为什么必须要有它——三种风险，第三种最隐蔽：

```text
危险动作   工具代码可能删文件、改数据、发外网请求
资源失控   死循环烧 CPU、申请海量内存、卡死不返回
逃逸输出   执行结果里夹带内部路径、密钥、其他租户数据
```

前两种靠资源限制（第 3 节），第三种靠输出防逃逸（第 4 节）。判断标准一句：**凡是"模型一句话就能触发执行"的代码，默认都当不可信内容，先进沙盒再谈别的。** 第三课的超时包装是线程级"不再等待"；本课把它升级成进程级"真的杀掉"。

## 2. 隔离技术选型：容器、轻量虚拟化、进程级

隔离强度的本质差别是**边界在哪里**：

| | 进程级隔离 | 容器 | 轻量虚拟化（gVisor / Firecracker） |
| --- | --- | --- | --- |
| 边界 | 操作系统进程 | 命名空间 + cgroup | 独立内核/系统调用拦截 |
| 隔离强度 | 低（共享内核） | 中 | 高（恶意代码更难逃出） |
| 启动速度 | 毫秒级 | 百毫秒级 | 数十毫秒~秒级（虚拟机更重） |
| 适合 | 内部工具、低风险代码 | 常规工具沙盒 | 多租户运行不可信用户代码 |

判断标准：**风险越高、越要隔离，代价是启动越慢。** 内部开发工具用进程/容器；"用户提交代码帮它跑"这类要容器或轻量虚拟化。gVisor 用用户态重实现系统调用（隔离强、兼容较好），Firecracker 是微型虚拟机（隔离最强、启动慢于容器）。面试被问"选哪个"：按"要跑的代码可信度 × 启动延迟预算"回答，而不是背名词。

## 3. 资源限制四维：CPU、内存、网络、时间

沙盒内要做四件事，缺一不可：

| 维度 | 限制什么 | 超了怎么办 |
| --- | --- | --- |
| CPU | 计算配额 | 限流或降级 |
| 内存 | 驻留内存上限 | 触发 OOM 杀进程 |
| 网络 | 禁外网或域名白名单 | 拒绝请求 |
| 时间 | 执行时长上限 | **超时强杀** |

第四课/第三课讲过超时的线程版本：`future.result(timeout)` 只是"运行时不再等待"，**任务还活着**，副作用可能继续发生。本课是进程级：用 `subprocess` 起独立进程，`timeout` 一到，进程被真正杀死。课程代码路径 A 的对比最有说服力：

```text
慢任务（sleep 5 秒，超时 2 秒）-> 超时强杀：超过 2.0 秒，进程已被杀死（真实耗时 2.0s）
```

真实耗时 2.0 秒而不是 5 秒——进程真的没了。第三课的线程版本要等它跑完才退出。这就是"为什么超时强杀必须发生在沙盒里"的答案：**不在独立进程里，你根本杀不掉它。** 已发生的副作用怎么办？第 3 课的工具幂等兜底（写操作的 request_id 查重），两条线合起来才是完整方案。

## 4. 输出防逃逸：边界、截断与异常提炼

资源限制防"跑飞"，输出防逃逸防"带出"。三件事：

```text
输出边界   执行结果超过长度上限 -> 截断并标注
序列化边界 只收约定格式（JSON/单行文本）-> 其他拒绝
异常提炼   崩溃时只回传最后一行错误，完整堆栈不外传
```

为什么异常只能提炼一行？两个理由：**泄露内部路径**（`/srv/app/sandbox/worker.py` 这种堆栈行是攻击者的情报）；**污染上下文**（几十行堆栈塞进 `messages`，第 5 课的稀缺资源）。课程代码路径 A：

```text
超长输出 -> 输出越界：10000 字符超过边界 80，已截断：xxx…
异常崩溃 -> 沙盒执行失败：ValueError: 数据库连接断开（堆栈被提炼成一行）
```

面试被问"沙盒里跑出来的东西怎么防止带出密钥/内部信息"，答案就是这三件：长度边界、格式边界、异常提炼。文件系统层面再配只读挂载和临时工作目录（沙盒进程看不到宿主目录树），路径 A 之外的点到为止。

## 5. 沙箱资源池：预热、复用、TTL 与调度

单个沙盒再快，冷启动也是开销。生产做法是**资源池**：提前启动一批沙盒进程/容器，请求来了直接复用。课程代码 `SandboxPool` 的参数就是面试答案：

| 参数 | 含义 | 课程代码 |
| --- | --- | --- |
| `warm_size` | 预热槽位：请求来之前已就绪 | 2 |
| `max_slots` | 总槽位上限 | 4 |
| `idle_ttl_s` | 空闲多久销毁回收，池子收缩 | 60 |

调度四规则，对应四种资源状况：

```text
命中预热   有 warm 槽 -> 直接分配，启动延迟≈0
新建      无 warm 槽且未达上限 -> 冷启动一个（有延迟）
排队      达到上限且请求优先级高 -> 排队等待
拒绝/降级 达到上限且低优先级 -> 拒绝或降级
```

路径 B 的调度记录把四种情况各走了一遍：r1/r2 命中预热，r3 新建，r4 排队，r5 低优先级被拒；回收槽 #0 后 r6 又直接命中预热（复用回收）。路径 B2 演示 TTL：预热槽不被使用、空闲超 60 秒后销毁，池子收缩。

面试被问"资源池怎么防冷启动、怎么防饿死"：**防冷启动靠 warm pool（预热池）；防饿死靠排队 + 优先级 + TTL 回收**——高优先级排队而不是全拒，低优先级降级而不是让池子被占死。

## 6. 常见错误

1. **用线程模拟沙盒**：超时只是"不再等待"，任务还活着、副作用继续。修复：独立进程/容器 + 真的杀（本课路径 A）。
2. **堆栈原样回填**：内部路径和源码行变成攻击情报 + 上下文污染。修复：异常提炼一行。
3. **输出无边界**：工具跑出 10000 字符直接进 `messages`。修复：长度边界 + 截断标注。
4. **预热池设满不复用**：全部冷启动，等于没池子。修复：warm 槽 + 复用回收 + 空闲 TTL。
5. **超限一律拒绝**：高优先级请求也被拒，关键任务饿死。修复：排队 + 优先级 + 降级。
6. **以为沙盒=容器**：隔离强度和启动速度是取舍，内部工具用容器/进程足够，别为"看起来安全"上虚拟机。

## 8. 课后作业

作业在 `code/ai-agent/ai_agent_lesson08.py` 下半部分，两个小函数：

1. `acquire(request_id, priority)`：按优先级返回调度决策文案——有 warm 槽 → `"命中预热槽"`；未达上限 → `"新建槽（冷启动）"`；达到上限且 high → `"排队等待"`；达到上限且 normal → `"拒绝（降级）"`；
2. `summarize_traceback(stderr)`：从完整堆栈提炼一句话——只返回最后一行非空文本；行数超 3 行时加说明；**绝不包含文件路径**。

`homework()` 已准备好调用序列和一段带 `/srv/app/sandbox/worker.py` 路径的堆栈。完成后取消注释，应看到调度决策四条文案，以及提炼结果不含任何路径：

```text
s1 high -> 命中预热槽
s2 high -> 命中预热槽
s3 normal -> 新建槽（冷启动）
s4 high -> 排队等待
提炼结果： ValueError: 笔记服务暂时不可用（堆栈已提炼）
```

思考：第三课的线程超时和本课的进程强杀，本质差别是什么？已发生的副作用分别靠什么兜底？
