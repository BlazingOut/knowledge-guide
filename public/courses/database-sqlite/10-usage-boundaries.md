# 第10课：SQLite 的真实使用边界

> 前面几课学习了 SQLite 的文件模型、Python API、类型系统、外键、事务、WAL、查询计划、特有语法以及备份恢复。这一课把这些知识放回真实项目中，判断什么时候 SQLite 是合适的选择，什么时候应该迁移到 MySQL 或 PostgreSQL。
>
> 本课不再学习新的 SQL 语法，而是学习数据库选型、部署边界和迁移时的实际取舍。

## 一、SQLite 适合什么场景

SQLite 的核心特点是：

```text
数据库就是一个文件
应用直接打开文件
不需要单独部署数据库服务器
```

因此，它特别适合以下场景。

### 1. 本地应用

桌面软件、命令行工具、移动应用和嵌入式程序通常只有一个主要应用实例，数据也主要属于当前设备：

```text
应用程序
    -> 直接打开本地 SQLite 文件
    -> 查询和修改本地数据
```

这种场景不需要为了一组本地数据额外运行 MySQL 服务，SQLite 的部署成本很低。

### 2. 测试数据库

测试可以为每个测试用例或每次测试运行创建独立文件：

```text
测试开始 -> 创建临时数据库文件
测试执行 -> 写入和验证数据
测试结束 -> 删除临时文件
```

它启动快、清理简单，适合单元测试、集成测试和本地开发。

### 3. 本地缓存和离线数据

浏览器、移动端或桌面应用可以使用 SQLite 保存：

- 本地配置；
- 缓存数据；
- 离线任务；
- 搜索索引；
- 最近访问记录。

本地数据库的核心要求通常是可靠读写和离线可用，而不是多台服务器共同写入。

### 4. 小型单机服务

如果服务部署在单台机器上、写入并发有限、数据规模可控，SQLite 也可以满足需求。关键是明确它的写入模型和备份方式，而不是因为“生产环境”三个字就自动排除 SQLite。

## 二、SQLite 不适合什么场景

### 1. 多个应用实例共享写入

假设 Web 服务有多个实例：

```text
服务器 A ─┐
服务器 B ─┼── 共同访问一个 SQLite 文件
服务器 C ─┘
```

如果文件位于共享文件系统中，会遇到：

- 文件锁和网络文件系统兼容性；
- 多实例写入竞争；
- 文件同步和一致性问题；
- 备份、权限和故障恢复复杂；
- 应用实例无法像连接服务器数据库一样统一管理连接。

这类场景通常更适合 MySQL 或 PostgreSQL。

### 2. 高并发写入

WAL 可以改善读写并发，但 SQLite 仍然只有一个写入者：

```text
多个读者可以并发
写事务之间仍然需要竞争
```

如果业务有大量并发写入、热点更新或长事务，`database is locked` 和写入等待会变得频繁。此时服务器数据库的连接管理、行级锁和并发能力通常更合适。

### 3. 复杂的数据库运维需求

如果项目需要：

- 主从复制；
- 读写分离；
- 故障自动切换；
- 统一权限管理；
- 远程监控；
- 时间点恢复；
- 多实例高可用；
- 大规模在线 DDL；

SQLite 的文件模型通常不适合作为主要业务数据库。

## 三、SQLite 与 MySQL 的选择对比

| 维度 | SQLite | MySQL / PostgreSQL |
|---|---|---|
| 部署 | 一个文件 | 独立数据库服务 |
| 连接 | 应用直接打开文件 | 通过网络连接服务器 |
| 写入并发 | 通常一个写入者 | 更适合多客户端并发写入 |
| 扩展方式 | 单机资源和文件管理 | 多实例、复制、读写分离 |
| 备份 | 文件或 SQLite 备份 API | 全量备份、日志和恢复工具 |
| 权限 | 主要依赖文件权限和应用 | 数据库账号、库表权限 |
| 运维 | 简单 | 能力强但复杂 |
| 适合 | 本地、嵌入式、测试、单机 | 共享业务、在线服务、多人并发 |

这不是“SQLite 简单、MySQL 高级”的绝对排名，而是部署模型不同。SQLite 的优势是简单和低成本，服务器数据库的优势是集中管理和并发扩展。

## 四、从 SQLite 迁移到服务器数据库

迁移不是只把文件换成连接字符串，还要检查几个层面。

### 1. 连接方式

SQLite：

```python
sqlite3.connect("app.sqlite3")
```

MySQL：

```text
主机 + 端口 + 用户名 + 密码 + 数据库名
```

应用需要引入新的驱动、连接池、连接超时和凭据管理方式。

### 2. 数据类型

SQLite 的动态类型可能允许历史数据类型不一致，迁移到 MySQL 后需要明确：

- 整数范围；
- 字符串长度；
- 金额精度；
- 日期时间格式和时区；
- `NULL` 和默认值；
- 布尔值表示；
- JSON 字段。

迁移前应扫描旧数据，找出不符合目标类型的记录，而不是让导入过程随机失败。

### 3. SQL 方言

需要检查：

- 自增主键写法；
- UPSERT 语法；
- `RETURNING` 支持情况；
- 日期函数；
- 分页语法；
- 字符串和大小写比较；
- 关键字和标识符引用；
- JSON、全文搜索和扩展函数。

通用 SQL 越多，迁移越容易，但 SQLite 的扩展语法不能默认在 MySQL 中原样运行。

### 4. 并发模型

SQLite 中可能依赖：

```text
单写者
文件锁
WAL
busy_timeout
```

迁移后需要重新检查：

- 事务边界；
- 连接池大小；
- 锁等待；
- 隔离级别；
- 读写分离；
- 重试和幂等。

不能只替换驱动而保留所有 SQLite 并发假设。

## 五、什么时候应该迁移

可以使用这些信号进行判断：

```text
多个服务实例需要共同写入同一份数据
写事务频繁出现 database is locked
数据库文件已经难以备份和分发
需要账号级别的数据库权限
需要主从复制或故障切换
需要稳定的远程连接和连接池管理
单机资源无法满足数据量和并发量
```

但不要只因为数据库文件变大就立刻迁移。更重要的是结合：

- 读写比例；
- 写入峰值；
- 事务持续时间；
- 数据访问位置；
- 备份和恢复要求；
- 团队运维能力；
- 未来部署方式。

## 六、Life Manager 这类项目如何判断

对于本地个人工具或单机应用，可以优先考虑 SQLite：

```text
应用和数据库在同一台机器
数据主要由一个用户使用
写入并发有限
不需要多实例共享
备份可以围绕文件完成
```

如果未来变成多人协作的 Web 服务：

```text
多个用户同时写入
多个应用实例
需要远程访问
需要账号权限和审计
需要主从、监控和故障切换
```

就应重新评估 MySQL 或 PostgreSQL。

选型应该跟着实际部署形态变化，不需要因为未来可能扩展就一开始承担服务器数据库的复杂度，也不能在并发需求已经超出 SQLite 边界后继续依赖它。

## 七、迁移前的检查清单

### 数据

- 是否存在类型不一致的数据？
- 是否存在重复业务键？
- 是否存在孤儿记录？
- NULL 和空字符串是否混用？
- 日期时间是否统一时区？

### SQL

- 是否依赖 SQLite 特有语法？
- 是否使用 `rowid`？
- 是否依赖动态类型转换？
- 是否依赖 SQLite 日期函数或 JSON1？
- 是否存在目标数据库不支持的表达式？

### 应用

- 是否需要更换驱动？
- 是否需要连接池？
- 事务是否绑定同一个连接？
- 是否需要重新设计重试和幂等？
- 是否需要调整错误处理？

### 运维

- 如何备份和恢复？
- 如何监控连接、慢查询和锁？
- 如何发布表结构变化？
- 如何验证迁移结果？
- 如何在迁移失败时回退？

## 八、常见错误

- 只因为 SQLite 是文件数据库就认为它不能用于生产；
- 只因为数据量增长就认为必须马上迁移；
- 只替换数据库驱动，不检查 SQL 方言和类型；
- 把 WAL 当成高并发写入解决方案；
- 把 SQLite 文件放到共享网盘当成多实例数据库；
- 迁移前没有清理重复、孤儿和类型异常数据；
- 只验证迁移脚本执行成功，没有验证业务结果；
- 没有准备回滚和双写期间的数据校验方案。

## 九、面试回答模板

### 题目：SQLite 适合什么场景？

> SQLite 适合本地工具、桌面端、移动端、嵌入式程序、测试数据库、离线应用和写入并发有限的单机服务。它部署简单，不需要独立数据库服务器。需要多实例共享、高并发写入、远程权限、复制和高可用时，通常选择 MySQL 或 PostgreSQL。

### 题目：什么时候应该从 SQLite 迁移到 MySQL？

> 当多个应用实例需要共同写入、写锁冲突频繁、需要账号权限和远程访问，或者需要复制、高可用、统一监控和更强的并发能力时，应评估迁移。迁移不只是换驱动，还要检查数据类型、SQL 方言、事务边界、并发模型、备份和运维流程。

### 题目：WAL 能解决 SQLite 的高并发问题吗？

> WAL 能改善读写同时发生时的阻塞，让读者通常不必等待写入者，但 SQLite 仍然主要只有一个写入者，热点写入和长事务仍会竞争。WAL 是并发改进，不等于服务器数据库的行锁、连接池和水平扩展能力。

完成本课后，SQLite 专题可以暂时收尾。应当能够：

```text
说明 SQLite 文件数据库和 MySQL Server 的部署差异
正确使用 Python sqlite3 连接、参数化查询和事务
解释 SQLite 动态类型、外键开关和 STRICT 表
解释单写者模型、WAL 和 database is locked
使用 EXPLAIN QUERY PLAN 观察 SCAN、SEARCH 和索引
使用 rowid、UPSERT、RETURNING 等 SQLite 特有能力
完成安全的备份、完整性检查和恢复验证
判断继续使用 SQLite 还是迁移到 MySQL/PostgreSQL
```
