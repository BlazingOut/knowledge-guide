# 第3课:标准流、管道与重定向

本课把命令的输出连接起来：先理解三个标准流，再用重定向把输出保存到文件，用管道把一条命令的输出交给另一条命令。这是组合命令的基础，第 2 课预告的 `find | rg` 会在这里讲透。

## 1. 学习目标

完成本课后，你应当能够：

1. 区分 stdin、stdout、stderr 三个标准流及其文件编号。
2. 用 `>`、`>>` 重定向标准输出，知道覆盖、追加和创建文件的副作用。
3. 用 `2>`、`2>&1` 重定向标准错误。
4. 用管道 `|` 把一条命令的输出作为另一条命令的输入。
5. 解释重定向与管道的区别，读懂 `find | rg` 这类组合命令。

## 2. 三个标准流

程序运行时与外界交换数据依靠三个标准流（standard stream）：

| 标准流 | 文件编号 | 作用 | 默认去向 |
| --- | --- | --- | --- |
| stdout | 1 | 输出正常结果 | 终端屏幕 |
| stderr | 2 | 输出错误和诊断信息 | 终端屏幕 |
| stdin | 0 | 读取程序的输入 | 键盘输入 |

在终端里，stdout 和 stderr 看起来都显示在屏幕上，但它们是两条独立的数据流，可以分别保存和处理。stdin 在管道场景中最常用：右侧命令通过 stdin 读取左侧命令的输出。

## 3. 重定向：把输出保存到文件

### 3.1 标准输出重定向：> 和 >>

`>` 把命令的 stdout 写入文件而不是屏幕；`>>` 把输出追加到文件末尾。

**常用形式**

```text
命令 > 文件路径
命令 >> 文件路径
```

| 写法 | 含义 |
| --- | --- |
| `命令 > 文件` | 把 stdout 写入文件；文件不存在则创建，已存在则覆盖原内容 |
| `命令 >> 文件` | 把 stdout 追加到文件末尾；文件不存在则创建 |

```bash
python --version > version.txt
python --version >> version.txt
ls -l version.txt
```

第一次创建 `version.txt`，第二次追加同样的内容，`ls -l` 可以看到文件大小翻倍、修改时间更新。注意 `>` 和 `>>` 本身都会创建文件，覆盖已有文件的内容同样不可恢复。

### 3.2 标准错误重定向：2> 和 2>&1

`2>` 把 stderr 写入文件。`2>&1` 把 stderr 合并到 stdout 当前指向的位置（`&1` 中的 `&` 表示"文件描述符"，不是名为 `1` 的普通文件）。

**常用形式**

```text
命令 2> 文件路径
命令 > 正常.log 2> 错误.log
命令 > 全部.log 2>&1
```

| 写法 | 含义 |
| --- | --- |
| `命令 2> 文件` | 把 stderr 写入文件（2 是 stderr 的编号） |
| `命令 > 正常.log 2> 错误.log` | 正常输出和错误输出分别保存到两个文件 |
| `命令 > 全部.log 2>&1` | 先把 stdout 写入文件，再把 stderr 合并进同一个文件 |

```bash
python missing-script.py 2> error.log
python missing-script.py > normal.log 2> error.log
python missing-script.py > all.log 2>&1
```

`python missing-script.py` 会因为没有这个脚本而向 stderr 输出错误：第一种只保存错误，第二种把空 stdout 和错误分开保存，第三种把两者合并到 `all.log`。

**`2>&1` 的位置很关键**：它表示"把 stderr 指向 stdout 当前的位置"，必须写在 `> 文件` 之后。写成 `2>&1 > 文件` 时，stderr 先指向屏幕，再重定向 stdout 到文件，结果错误仍然显示在屏幕，达不到合并的目的。

### 3.3 丢弃输出：/dev/null

`/dev/null` 是一个特殊的"黑洞"文件，写进去的内容直接丢弃。不需要的输出用 `2>/dev/null` 丢掉：

```bash
python missing-script.py 2>/dev/null
```

上面命令执行后屏幕没有任何输出，错误信息被丢弃。

## 4. 管道：把输出交给下一条命令

管道 `|` 把左侧命令的 stdout 直接接到右侧命令的 stdin，右侧命令的输出再显示到屏幕（或继续接下一段管道）。

**常用形式**

```text
命令1 | 命令2
命令1 | 命令2 | 命令3
```

| 写法 | 含义 |
| --- | --- |
| `命令1 | 命令2` | 命令1 的 stdout 作为命令2 的 stdin |
| `命令1 | 命令2 | 命令3` | 依次串联，数据从左到右流动 |

```bash
find courses -name '*.md' | rg 'lesson'
ls courses | rg 'basics'
```

第 2 课的组合现在讲透了：`find` 输出的文件路径列表不显示在屏幕，而是作为 `rg` 的输入；`rg` 只把包含 `lesson` 的行输出。管道两侧的命令是**同时运行、边产边传**的，不是等左侧命令全部结束才启动右侧命令。

## 5. 常用补充：既查看又保存的 tee

`tee` 把 stdin 的内容既写到屏幕，又写入文件，适合"边看边存"。

**常用形式**

```text
命令 | tee 文件路径
```

| 选项 | 含义 |
| --- | --- |
| （不带参数） | 输出到屏幕的同时写入文件（覆盖已有内容） |
| `-a` | 追加到文件末尾而不是覆盖 |

```bash
python --version | tee run.log
```

## 6. 重定向与管道的区别

| 对比项 | 重定向（`>`、`>>`、`2>`） | 管道（`|`） |
| --- | --- | --- |
| 作用 | 把命令输出写到文件 | 把命令输出交给另一条命令 |
| 右侧对象 | 文件 | 命令（程序） |
| 示例 | `ls > list.txt` | `ls \| rg 'md'` |
| 常见用途 | 保存日志、记录结果 | 组合命令、筛选数据 |

一句话记住：**重定向的右边是文件，管道的右边是命令。**

## 7. 在真实工程中的对应场景

1. 启动服务时把正常输出和错误分开保存：`python app.py > app.log 2> error.log`；
2. 既在终端看输出又想留存一份：`python app.py 2>&1 | tee run.log`；
3. 不想让错误信息刷屏：在命令后加 `2>/dev/null`；
4. 组合命令筛选结果：`find 目录 -name '*.log' | rg 'ERROR'`；
5. 第 5 课查看日志时会大量组合 `tail`、`grep` 和管道，本课是基础。

## 11. 面试考点

- **重定向和管道的区别**：重定向的右边是文件（保存结果），管道的右边是命令（组合处理）；`>` 保存日志，`|` 筛选数据。
- **`2>&1` 的含义**：把 stderr 合并到 stdout 当前指向的位置，常用来把所有输出集中到一个文件；顺序写反（`2>&1 > 文件`）会失效。
- **`命令 > 文件` 和 `命令 2> 文件` 分别做什么**：前者保存正常输出，后者保存错误输出；两个一起用可以把两者分开记录，这在排查服务启动失败时很常用。
- **管道两侧的执行关系**：同时运行、边产边传（流式），不是等左边结束才启动右边；`find | grep`、`ps | grep` 都是经典组合。
- **`/dev/null` 和 `tee`**：丢弃不需要的输出用 `2>/dev/null`；既要看又要存用 `命令 2>&1 | tee 文件`。

## 12. 本课小结

三个标准流是命令与外界交换数据的通道：stdout 是正常结果，stderr 是错误信息，stdin 是输入。重定向把输出写到文件（`>`、`>>`、`2>`、`2>&1`），管道把输出交给下一条命令（`|`），两者是组合命令的两块基石。

下一课将学习文本处理命令（`head`、`tail`、`sort`、`uniq`、`wc`、`cut`），配合管道做查看、排序和统计，也是第 5 课日志排查的前置。
