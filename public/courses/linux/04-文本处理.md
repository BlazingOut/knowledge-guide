# 第4课:文本处理

第 3 课学会了把命令的输出保存成文件、用管道交给下一条命令。本课把这些能力用在真正的文本任务上：查看一个文件、统计行数、排序、统计每种内容出现多少次、按列取数据。这些命令单独都很简单，价值在组合——一条 `sort | uniq -c | sort -rn` 就能回答"日志里哪类错误最多"这类面试题。本课所有命令示例中，`#` 后是注释，实际执行时不输入。

**学习目标：**

1. 能说出 `cat`、`less`、`head`、`tail` 各自适合的场景，并解释为什么看大文件不用 `cat`；
2. 能用 `wc -l` 统计行数；
3. 能用 `sort` 排序、用 `-r` 反向，并理解数值排序为什么必须加 `-n`；
4. 能解释"为什么 `uniq` 前必须先 `sort`"，并用 `sort | uniq -c | sort -rn` 统计每种内容出现的次数并降序排列；
5. 能用 `cut` 按分隔符提取指定列。

## 1. 查看文件：cat、less、head、tail

### 1.1 cat：把整个文件原样输出到屏幕

第 3 课用重定向把输出写进了文件（如 `python --version > version.txt`），现在需要把它读回来。最直觉的命令是 `cat`。

**`cat`（concatenate，拼接）** 把文件内容原样输出到 stdout：

**常用形式**

```text
cat [选项] 文件路径
```

| 选项 | 含义 |
| --- | --- |
| （不带参数） | 把整个文件内容输出到屏幕，日常最常用 |
| `-n` | 每行前显示行号（了解即可） |

```bash
cat version.txt    # 把 version.txt 的全部内容输出到屏幕
```

`cat` 会把整个文件一次性倒到屏幕。文件只有几行时没问题；几万行时，前面的内容会瞬间滚出屏幕，根本来不及看。所以**看大文件不用 `cat`**，改用下一节的 `less` 或 `tail`。

### 1.2 less：分页浏览大文件

**`less`** 是一个分页查看器：它不把整个文件一次性输出，而是每次只显示一屏，可以上下翻页、按关键词搜索。适合看大文件。

**常用形式**

```text
less 文件路径
```

进入 `less` 后是交互界面，用按键操作：

| 按键 | 含义 |
| --- | --- |
| `空格` / `j` | 向下翻一页 / 向下翻一行 |
| `b` | 向上翻一页 |
| `/关键词` | 向下搜索关键词，`n` 跳到下一个匹配 |
| `q` | 退出 `less` |

```bash
less notes.txt    # 分页查看 notes.txt；按 q 退出
```

`less` 比 `cat` 好在两点：大文件不一次性占满内存、可以随时往回翻；还能像第 2 课的 `rg` 一样搜索关键词。面试问"看大文件用什么"，答案是 `less` 而不是 `cat`。

### 1.3 head / tail：只看开头或结尾

大多数时候我们不需要整个文件，只需要开头几行（如文件头说明）或结尾几行（如最新日志）。

**`head`** 输出文件开头，**`tail`** 输出文件结尾：

**常用形式**

```text
head [选项] 文件路径
tail [选项] 文件路径
```

| 选项 | 含义 |
| --- | --- |
| `-n N` | 只输出开头 / 结尾的 N 行，默认 N = 10 |

```bash
head -n 5 README.md    # 看 README 的开头 5 行
tail -n 5 run.log      # 看日志的最后 5 行，也就是最新的 5 条
```

注意 `tail -n 5` 的含义：它取的是文件**末尾**的 5 行，而日志文件总是越往后越新，所以 `tail` 天然就是"查最近日志"的答案起点——第 5 课会在此基础上展开 `tail -f` 实时跟踪。

## 2. 统计行数：wc

**`wc`（word count，字数统计）** 数一个文件有多少行、多少个单词、多少字节。本课只用到行数：

**常用形式**

```text
wc [选项] 文件路径
```

| 选项 | 含义 |
| --- | --- |
| `-l` | 只输出行数（lines），必会 |
| `-w` | 输出单词数（了解即可） |
| `-c` | 输出字节数（了解即可） |

```bash
wc -l notes.txt        # notes.txt 有多少行
find courses -name '*.md' | wc -l   # 项目里有多少个 Markdown 文件
```

第二行的思路是第 2、3 课的组合：`find` 输出一行一个文件路径，`wc -l` 数行数，结果就是文件个数。"日志里一共有多少条记录"同样可以用 `wc -l 日志文件` 回答。

## 3. 排序与去重：sort、uniq

### 3.1 sort：按行排序

文本处理里大量任务是"找出出现最多的东西"，而排序是第一步。

**`sort`** 按行把内容排序输出，本身不修改文件：

**常用形式**

```text
sort [选项] [文件路径 ...]
```

| 选项 | 含义 |
| --- | --- |
| `-r` | 反向排序（降序） |
| `-n` | 按数值大小排序，而不是按字典序 |

```bash
sort names.txt           # 按字典序升序
sort -r names.txt        # 反向排序
sort -n -r numbers.txt   # 按数值从大到小
```

`-n` 很容易被漏掉：默认的字典序里，`"10"` 会排在 `"2"` 前面（因为按字符逐个比较，`'1' < '2'`）。对数字排序必须加 `-n`，否则得到的是"按字符排"的结果。

### 3.2 uniq：合并相邻的重复行并计数

**`uniq`（unique，唯一）** 把**相邻且相同**的行合并成一行，`-c` 在每行前显示这一行出现了几次：

**常用形式**

```text
uniq [选项] [文件路径 ...]
```

| 选项 | 含义 |
| --- | --- |
| `-c` | 每行前显示该行出现的次数 |

```bash
sort names.txt | uniq -c    # 先排序聚拢，再去重并计数
```

`uniq` 的边界必须讲清楚：**它只看相邻行**。如果相同内容散落在文件各处，`uniq` 会以为它们是不同的行，计数就错了。所以正确顺序永远是"先 `sort` 让相同行聚到一起，再 `uniq -c`"。

```text
原始内容:  A  B  A  B  A
直接 uniq:  A  B  A  B  A        # 全部"相邻不重复"，等于没去重
先 sort:    A  A  A  B  B
再 uniq -c: 3 A   2 B            # 这才是正确计数
```

## 4. 按列提取：cut

**`cut`** 按分隔符把每一行切开，再取指定的列。适合处理"每一行都是 `用户名:口令:...` 这种固定结构"的文件。

**常用形式**

```text
cut -d 分隔符 -f 列号 文件路径
```

| 选项 | 含义 |
| --- | --- |
| `-d` | 指定分隔符，默认是制表符 |
| `-f` | 取第几列，从 1 开始计数 |

```bash
cut -d ':' -f 1 /etc/passwd    # 按 : 切分，取第 1 列，得到所有用户名
```

`/etc/passwd` 的每一行用 `:` 分成若干字段，第 1 个是用户名。用空格分隔的文件要写成 `-d ' '`，因为 `cut` 默认只认制表符。

## 5. 组合：sort | uniq -c | sort -rn

前面几个命令单独都很弱，组合起来才是工程能力。下面这条管道是面试和日常排错的高频组合，回答的是"**统计出现次数最多的行**"：

```text
sort（把所有相同内容聚到一起）
  -> uniq -c（每组统计出现次数）
    -> sort -rn（按次数从大到小排）
      -> head -n N（取前 N 行）
```

```bash
sort access.log | uniq -c | sort -rn | head -n 10
# 第 1 步：排序，让相同内容相邻
# 第 2 步：去重并计数，输出 "次数 内容"
# 第 3 步：按次数降序
# 第 4 步：只保留最多的前 10 行
```

换成日志场景，`access.log` 里的每一行是一条访问记录，这条管道就能回答"访问最多的 IP 是哪几个"；把内容换成错误类型，就能回答"哪类错误出现最多"。面试问"如何统计日志中出现次数最多的 X"，答案就是这条管道，并且要能解释为什么 `sort` 必须写在 `uniq` 前面。

## 6. 本课命令速查表

| 命令 | 含义 | 常用参数 |
| --- | --- | --- |
| `cat` | 把整个文件输出到屏幕 | `-n` 显示行号 |
| `less` | 分页浏览大文件 | 交互按键：`q` 退出、`/关键词` 搜索 |
| `head` | 输出开头 N 行 | `-n N`（默认 10） |
| `tail` | 输出结尾 N 行 | `-n N`（默认 10） |
| `wc` | 统计行数 / 单词数 / 字节数 | `-l` 只数行数 |
| `sort` | 按行排序 | `-r` 降序；`-n` 按数值 |
| `uniq` | 合并相邻重复行 | `-c` 显示出现次数 |
| `cut` | 按分隔符提取列 | `-d` 分隔符；`-f` 列号 |

## 7. 常见错误

| 常见错误 | 现象 | 正确做法 |
| --- | --- | --- |
| `uniq` 前不 `sort` | 相同行不相邻，计数严重漏掉 | 先 `sort` 聚拢，再 `uniq -c` |
| `sort` 不加 `-n` | `10` 排在 `2` 前面 | 数值排序加 `-n` |
| `head` / `tail` 不带 `-n` | 只能看到 10 行 | 明确写 `-n 100` |
| `cut` 用错分隔符 | 取不到想要的列 | 先确认分隔符，空格分隔用 `-d ' '` |
| `cat` 打开大文件 | 内容瞬间刷屏，看不到开头 | 改用 `less` 或 `tail` |

## 8. 运行本课命令练习

在项目根目录执行（`#` 后是注释，不输入）：

```bash
wc -l courses/engineering/linux/README.md      # 数一数大纲文件的行数
head -n 5 courses/engineering/linux/README.md  # 看大纲开头 5 行
tail -n 5 courses/engineering/linux/README.md  # 看大纲最后 5 行
less courses/engineering/linux/README.md       # 分页浏览；按 q 退出
find courses -name '*.md' | wc -l              # 数一数课程里有多少个 md 文件
find courses -name '*.md' | sort | uniq -c | sort -rn | head -n 10
# 统计每个课程目录下 md 文件的数量分布（按目录名聚拢计数）
cut -d ':' -f 1 /etc/passwd | head -n 5        # 看系统前 5 个用户名
```

每执行一条命令，先预测输出（几行、什么顺序），再对照实际结果。

## 11. 面试高频考点

- **如何统计一个文件有多少行**：`wc -l 文件`。对命令输出统计条数时从管道读：`命令输出 | wc -l`（例如 `find ... | wc -l` 统计文件个数）。口述：`wc -l` 数行数，管道把命令输出喂给它。
- **如何统计出现次数最多的内容**：`sort 文件 | uniq -c | sort -rn | head -n 10`。口述要带机制：`sort` 让相同行相邻（`uniq` 只能合并相邻重复行）→ `uniq -c` 计数 → `sort -rn` 按次数降序 → `head` 取前 N。面试常追问"为什么 `uniq` 前要 `sort`"，答案就是 `uniq` 只看相邻行。
- **head 和 tail 的作用**：`head` 看开头（文件头、表头说明），`tail` 看末尾（日志的最新内容），`-n` 指定行数。`tail -f` 实时跟踪留到第 5 课。
- **less 比 cat 好在哪**：`cat` 一次性全量输出、不能往回翻、大文件刷屏；`less` 分页显示、可以上下翻、能搜索，大文件友好。
- **数值排序陷阱**：`sort` 默认按字典序，`"10"` 排在 `"2"` 前；按数值排序必须加 `-n`。

## 12. 小结与下一课预告

本课的命令单独都很简单，真正的能力在组合：`find | wc -l` 数条数，`sort | uniq -c | sort -rn` 统计出现次数最多的行，`cut` 从结构化文本里取列。这些组合是日志排查的零件。

下一课进入面试高频主题——**日志查看与排查**：`tail -n` 取最新日志、`tail -f` 实时跟踪、`grep` 过滤关键词并带上下文，以及 systemd 的 `journalctl`，把本课和前三课的命令用在真实排错上。
