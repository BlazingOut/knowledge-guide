# 第6课:文件权限与用户基础

日志课（第 5 课）提到"服务没日志可能是没有读日志的权限"，本课把权限讲透。Linux 是多用户系统：一台机器上有 root、你自己、各种服务账号，如果没有权限隔离，任何人都能读改别人的文件。本课回答三个问题：权限长什么样（`ls -l` 怎么读）、怎么改（`chmod`/`chown`）、"Permission denied"怎么定位（`whoami`/`id`/`sudo`）。本课命令示例中，`#` 后是注释，实际执行时不输入。

**学习目标：**

1. 能逐字符读出 `ls -l` 输出的权限字段，区分文件与目录的 rwx 含义；
2. 能把 `755`、`644`、`600` 换算成权限位，并说出各自的典型场景；
3. 能用 `chmod` 的数字和符号写法修改权限；
4. 能区分 `chmod` 和 `chown`，说出各自改什么、谁有权执行；
5. 能用 `whoami`、`id` 确认当前身份，解释 `sudo` 的用途和风险，区分 `sudo` 与 `su`；
6. 能定位并解释常见的 Permission denied。

## 1. 权限的三组主体：所有者、所属组、其他用户

每个文件都记录着三类身份的权限。Linux 用"**三类主体 × 三种操作**"描述一个文件谁能对它做什么：

| 主体 | 符号 | 是谁 |
| --- | --- | --- |
| 所有者（owner） | `u`（user） | 创建这个文件的用户 |
| 所属组（group） | `g` | 文件所属的用户组，组内成员共享该组权限 |
| 其他用户（others） | `o` | 以上两者之外的任何人 |

三种操作是读（r）、写（w）、执行（x），下一节展开。先记住判断顺序：系统先看"你是所有者吗"→ 是就看所有者权限；不是就看"你在文件所属的组里吗"→ 是就看组权限；都不是就看其他用户权限。

## 2. 读 ls -l 的输出：第一个字段怎么拆

第 1 课用过 `ls -l` 的详细格式，现在读它的第一个字段——十个字符：

```text
-rw-r--r-- 1 you you 1234 Oct 21 10:00 notes.txt
│ └─┬─┘ └┬┘ └┬┘
│  │    │   └ 其他用户的权限
│  │    └──── 所属组的权限
│  └───────── 所有者的权限
└──────────── 类型：- 普通文件，d 目录，l 符号链接
```

第一字符是**类型**（`-` 普通文件、`d` 目录、`l` 符号链接），后面九字符分成三组，每组三个位，按顺序是读、写、执行：

| 权限位 | 对文件 | 对目录 |
| --- | --- | --- |
| `r`（read，读） | 能读文件内容 | 能列出目录里的文件名 |
| `w`（write，写） | 能修改文件内容 | 能在目录里创建、删除文件 |
| `x`（execute，执行） | 能把文件当程序运行 | 能进入目录（`cd` 进去并访问其中文件） |

缺失的位显示为 `-`。`-rw-r--r--` 表示：普通文件，所有者可读写，组和其他用户只可读。

**目录权限的边界**（面试易混点）：目录的 `r` 和 `x` 是分开的——只有 `r` 没有 `x` 时，你能 `ls` 看到文件名列表，但 `cd` 进不去、也读不了里面的文件；要"进得去、用得了"，目录必须同时有 `r` 和 `x`。这就是"能 ls 却 cd 不进去"的答案。

## 3. 数字权限：755、644、600 怎么换算

每个权限位对应一个数字：`r=4`、`w=2`、`x=1`。一组的三个位相加，就是一个数字：

| 数字 | 权限 | 相加 |
| --- | --- | --- |
| 7 | rwx（读写执行） | 4+2+1 |
| 6 | rw-（读写） | 4+2 |
| 5 | r-x（读执行） | 4+1 |
| 4 | r--（只读） | 4 |
| 0 | ---（无权限） | 0 |

三个数字依次是**所有者 / 所属组 / 其他用户**的权限，合起来就是完整的权限。三个高频组合：

| 权限 | 所有者 | 组 | 其他 | 典型场景 |
| --- | --- | --- | --- | --- |
| `755` | rwx | r-x | r-x | 可执行文件、目录（别人能进能读，不能改） |
| `644` | rw- | r-- | r-- | 普通文件（别人只能读） |
| `600` | rw- | --- | --- | 私密文件（只有自己能读写，如密钥） |

换算练习：`644` 的第一位 6=rw-、后两位 4=r--，所以是"所有者读写、别人只读"。目录默认通常是 `755`，普通文件默认通常是 `644`——这是系统按"隐藏权限默认值"（umask，了解即可）生成的，不用记规则，用 `ls -l` 看实际值。

## 4. chmod：修改权限位

**`chmod`（change mode）** 修改文件或目录的权限。只有文件所有者和 root 能执行。数字写法一次给三组都设好：

**常用形式**

```text
chmod 权限数字 文件路径
```

```bash
chmod 600 ~/linux-course-tmp/secret.txt   # 私密文件只允许自己读写
chmod 755 ~/linux-course-tmp/script.sh    # 让脚本可执行
```

符号写法按需增减，不需要重算三组数字（了解即可，能读面试场景）：

**常用形式**

```text
chmod [主体][+/-][权限] 文件路径
```

| 写法 | 含义 |
| --- | --- |
| `chmod +x 文件` | 给所有人加执行权限（最常用简写） |
| `chmod u+x 文件` | 只给所有者加执行权限 |
| `chmod g-w 文件` | 去掉所属组的写权限 |

**让脚本可执行的两步**：`chmod +x script.sh` 之后，用 `./script.sh` 运行（`./` 表示当前目录下的文件，第 1 课写过这类相对路径；为什么不能直接 `script.sh`，与 PATH 有关，第 7 课展开）。文件没有 `x` 位时运行会报 "Permission denied"，这是面试里"脚本明明存在却跑不了"的答案。

## 5. 确认身份：whoami、id

排错时先确认"当前是谁在执行"：

**常用形式**

```text
whoami
id [选项]
```

| 命令 | 含义 | 常用参数 |
| --- | --- | --- |
| `whoami` | 显示当前用户名 | 无 |
| `id` | 显示当前用户的 UID、GID 和所属组 | `-u` 只看用户 ID（了解即可） |

```bash
whoami    # 我是哪个用户
id        # 我的用户 ID（uid）、组 ID（gid）、在哪些组里
```

看到 "Permission denied" 时，第一步就是 `whoami` + `ls -l 目标文件`：确认文件的所有者是不是当前用户，再对着权限位判断到底缺哪个 `r`/`w`/`x`。

## 6. chown：修改归属

**`chown`（change owner）** 修改文件的所有者（和所属组）。因为改归属等于"把文件送给别人"，只有 root 能执行：

**常用形式**

```text
chown 新所有者 文件路径
chown 新所有者:新组 文件路径
```

```bash
chown you notes.txt          # 把 notes.txt 的所有者改成 you（需要 sudo）
chown you:dev notes.txt      # 同时改所有者 you 和所属组 dev
```

面试里"**chmod 和 chown 的区别**"是必背对比：`chmod` 改**权限位**（谁能读/写/执行），`chown` 改**归属**（文件是谁的、属于哪个组）。普通用户能对自己的文件 `chmod`，但不能 `chown` 别人的文件。

## 7. sudo：临时以管理员身份执行

很多操作需要 root 权限：读系统日志、安装软件、改系统配置。但日常不该以 root 身份登录——权限太大，一条失误命令就能毁掉系统（第 2 课的 `rm -rf` 在 root 下是灾难性的）。

**`sudo`（superuser do）** 让当前用户以管理员身份**临时**执行一条命令：执行时输入自己的密码（不是 root 密码），执行完回到普通身份。

**常用形式**

```text
sudo 命令
```

```bash
sudo tail -n 50 /var/log/syslog    # 以管理员身份读系统日志
```

`sudo` 与 `su` 的对比（面试易混点）：

| 对比项 | `sudo` | `su` |
| --- | --- | --- |
| 作用 | 只对当前这一条命令临时提权 | 直接切换成另一个用户（默认 root） |
| 之后的状态 | 命令结束回到普通身份 | 一直以该用户身份操作，直到退出 |
| 风险 | 单条命令，范围可控 | 长期以 root 操作，失误影响全局 |

**sudo 的风险**：权限大、波及系统全局；`sudo rm -rf` 这类组合尤其危险。原则是"能用普通权限就不用 sudo，用 sudo 前想清楚这条命令的后果"。

## 8. 本课命令速查表

| 命令 | 含义 | 常用参数 |
| --- | --- | --- |
| `ls -l` | 详细列出文件，含权限字段 | `-l` |
| `chmod` | 修改权限位 | 数字 `644`/`755`/`600`；符号 `+x`、`u+x` |
| `chown` | 修改文件所有者和所属组 | `所有者:组`（需要 root） |
| `whoami` | 显示当前用户名 | 无 |
| `id` | 显示 UID、GID 和所属组 | `-u` 只看用户 ID |
| `sudo` | 以管理员身份执行一条命令 | 直接跟要执行的命令 |

## 9. 常见错误

| 常见错误 | 现象 | 正确做法 |
| --- | --- | --- |
| 权限数字算错 | 文件被改成所有人可改或自己都读不了 | 记住 `r=4 w=2 x=1`，常用 644/755/600 三档 |
| 目录缺 `x` 权限 | 能 `ls` 看到文件名，`cd` 却进不去 | 目录要有 `x`（执行）才能进入 |
| 脚本没加 `x` 就运行 | 报 Permission denied | 先 `chmod +x` 再 `./运行` |
| 对别人的文件 `chmod` | 报 Operation not permitted | 只有所有者和 root 能改权限 |
| 一直用 `su` 切 root | 所有命令都以 root 执行，风险大 | 单条命令提权用 `sudo` |
| 读系统日志忘加 `sudo` | Permission denied | `/var/log` 下多数文件要 `sudo` 读 |

## 10. 运行本课命令练习

```bash
mkdir -p ~/linux-course-tmp
touch ~/linux-course-tmp/demo.txt
ls -l ~/linux-course-tmp/demo.txt        # 看默认权限，通常是 -rw-r--r--（644）
whoami                                   # 我是哪个用户
id                                       # 我的 UID 和所属组
chmod 600 ~/linux-course-tmp/demo.txt
ls -l ~/linux-course-tmp/demo.txt        # 变成 -rw-------（600）
chmod 644 ~/linux-course-tmp/demo.txt
ls -l ~/linux-course-tmp/demo.txt        # 恢复 -rw-r--r--
# 制造一次 Permission denied：
chmod 000 ~/linux-course-tmp/demo.txt
cat ~/linux-course-tmp/demo.txt          # 应该报 Permission denied
chmod 644 ~/linux-course-tmp/demo.txt    # 记得恢复，否则后面练习读不了
# 目录 x 权限的作用：
chmod 000 ~/linux-course-tmp/private     # 如果 private 不存在，先 mkdir
cd ~/linux-course-tmp/private            # 应该报 Permission denied，进不去
chmod 755 ~/linux-course-tmp/private
```

（`private` 目录如果还不存在，先 `mkdir ~/linux-course-tmp/private` 再执行目录权限练习。）

如果你的系统日志在 `/var/log/syslog` 或 `/var/log/auth.log`，再试一条需要提权的命令：

```bash
sudo tail -n 20 /var/log/syslog    # 提示输入密码；输入时屏幕不显示字符，正常现象
```

## 13. 面试高频考点

- **755 和 644 分别表示什么**：口述模板："755 是所有者 rwx、组和其他 r-x，常见于可执行文件或目录；644 是所有者 rw-、组和其他 r--，常见于普通文件。换算规则是 r=4、w=2、x=1 相加，7=4+2+1，6=4+2。"
- **为什么会出现 Permission denied**：口述模板："先 `whoami` 确认当前用户，再 `ls -l` 看文件所有者，对照权限位判断缺什么——常见三类：文件不是你的且你没有读权限、目录没有 x 进不去、脚本没有 x 不能执行。"（定位链：身份 → 归属 → 权限位。）
- **chmod 和 chown 的区别**：`chmod` 改权限位（谁能读/写/执行），`chown` 改归属（文件的所有者和组）；普通用户只能对自己的文件 `chmod`，`chown` 需要 root。
- **sudo 的用途和风险**：单条命令临时以管理员身份执行，用完回到普通身份；权限大，`sudo rm -rf` 类操作会毁掉系统，能用普通权限就不用 sudo。
- **目录权限三件套**：目录的 `r` = 能列出文件名，`w` = 能增删文件，`x` = 能进入目录；只有 `r` 没有 `x` 时"能 ls 却进不去"，这是面试常设的追问。

## 14. 小结与下一课预告

权限是"多用户系统如何隔离"的答案：`ls -l` 读出三类主体的 rwx，`chmod` 改权限位（数字或符号），`chown` 改归属，`sudo` 临时提权。排错时先确认身份（`whoami`），再对照权限位（`ls -l`），最后决定要不要 `sudo`——这条链和日志课串起来，就是"服务起不来"的两大排查入口。
