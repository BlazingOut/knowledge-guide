# 完整系统实战：外卖系统 课程大纲

目标：把前面所有课程（网络、OS、数据库、Redis、FastAPI、Docker）串成一个**可运行、可测试、可部署、可讲述**的完整外卖系统项目，定位类似校招经典案例"苍穹外卖"，但按本课程的写作规范重写。

选择外卖系统作为教学案例的原因：它天然覆盖后端几乎全部经典问题——下单多表事务、库存防超卖、支付回调幂等、订单超时取消、热点菜品缓存、接口限流、消息与异步任务。这些问题正是秋招面试的高频考点。

本课程的核心能力是四件事：

- 能画出并讲清一条完整请求链路（从点餐到出餐）；
- 能亲手搭建一个真实系统（FastAPI + MySQL + Redis + Nginx + 异步任务）；
- 能主动制造故障并完成"复现 → 定位 → 修复 → 验证"的排查；
- 能在面试中用 5 分钟讲清架构、亮点与踩坑（超卖、重复支付、超时取消、缓存防护）。

本课程按"真实系统知识点全景"（见文末附录）规划：必学层在本课程和前置课程全覆盖；实操层在本课程动手；了解层只要求能说清"是什么、什么时候用"，不深入。

学习版定位：不做真实支付、不做配送调度与骑手端、不做 Kubernetes 和高可用。配送和骑手端只作为扩展方向一句话带过，核心把下单链路讲透。

## 前置知识

完成以下课程（或具备同等能力）：网络基础（HTTP/DNS/TCP，含 network 第 9 课 Session/JWT 概念）、操作系统基础、数据库课程（MySQL 事务、索引、第 11 课下单库存并发控制）、Redis 课程、FastAPI 课程、Docker 课程。

## 课程结构

### 第 1 课：全景图：一条点餐请求的完整旅程

目标：建立"从浏览器到数据库再到异步任务"的完整系统心智模型，作为全课程的锚点。

内容：系统架构图（浏览器 → DNS → Nginx 网关 → FastAPI → Redis → MySQL → 异步 Worker）；用户下单后每一步发生了什么（点餐 → 下单事务 → 扣库存 → 生成订单 → 支付回调 → 商家接单 → 出餐）；每层可能出故障的位置（缓存失效、库存扣减、支付重复、订单超时）。

实践：复述一条点餐请求的完整旅程，标出每层的职责和至少一个故障点。

面试考点：输入 URL 后发生了什么；如何分层描述一个系统。

### 第 2 课：开发环境与项目骨架

目标：用 Docker Compose 把 FastAPI + MySQL + Redis + Nginx 跑起来，建立可复现的开发环境。

内容：`docker-compose.yml`（services / ports / volumes / environment）；**Nginx 网关层**（接收请求、转发到 FastAPI、基础超时配置、静态资源）；项目目录结构；配置管理（环境变量、settings）；MySQL 与 Redis 的连接方式；服务健康检查。

实践：一条命令启动全套服务（含 Nginx）；用 curl 分别验证网关、API、MySQL、Redis 连通。

面试考点：为什么用 Docker Compose；Nginx 在链路中做什么；配置和密钥怎么管理；为什么这里用 MySQL 而不是 SQLite。

### 第 3 课：数据模型与数据库

目标：设计外卖系统的核心表，理解订单为什么要拆表、金额为什么用定点数，并在写数据访问时建立第一条安全红线。

内容：用户、商家、分类、菜品、购物车、订单、订单明细、支付记录等表设计；订单主单与明细的拆分原因；事务（下单 = 多表一起成功或失败）；索引与常见查询；种子数据；**参数化查询与 SQL 注入防护**（写 SQL 的第一条安全红线）。

实践：写模型、建库、造种子数据；用 SQL 验证订单查询和索引效果；演示并修复一次参数拼接导致的注入风险。

面试考点：订单为什么拆主单 + 明细；金额为什么用 DECIMAL 不用 FLOAT；事务 ACID；**SQL 注入怎么发生、怎么防（参数化查询）**。

### 第 4 课：认证与安全基础

目标：实现用户和商家的注册、登录、鉴权与角色区分，并掌握 Web 应用三类常见安全问题的原理与防护。

内容：密码哈希；Token（JWT 或 session，概念复用 network 第 9 课）；FastAPI 依赖注入做鉴权；用户端与商家管理端的角色区分；**安全基础：SQL 注入、XSS、CSRF 的原理与防护，CORS 概念**。

实践：实现注册登录接口，给受保护路由加鉴权依赖；验证注入与 XSS 输入被防护。

面试考点：认证和授权的区别；Token 怎么校验；密码为什么要哈希；SQL 注入 / XSS / CSRF 各自怎么防。

### 第 5 课：菜品与购物车

目标：实现菜品浏览和购物车，接入第一处缓存。

内容：分类与菜品 CRUD；购物车的数据结构选择（Redis Hash 还是 MySQL，按场景取舍）；菜品列表缓存（Cache Aside）；热点菜品的缓存防护思路预告。

实践：实现菜品接口和购物车，给菜品列表接入缓存并观察命中率。

面试考点：购物车存 Redis 还是 MySQL；Cache Aside 流程；热点数据缓存策略。

### 第 6 课：下单与库存（本课核心）

目标：实现下单事务和库存扣减，理解并解决超卖问题。

内容：下单 = 订单 + 明细 + 扣库存的多表事务；超卖现象与原因；乐观锁（条件更新 / version，复用 database 第 11 课的知识，这里在真实系统里实操）；Redis 预扣减与分布式锁简介；订单状态机（待支付 / 已支付 / 制作中 / 已完成 / 已取消）。

实践：实现下单接口，用并发脚本复现超卖，再用条件更新修复。

面试考点：怎么防止超卖；乐观锁和悲观锁怎么选；订单状态机设计；下单为什么要事务。

### 第 7 课：支付回调与幂等

目标：模拟支付回调，处理重复通知。

内容：支付回调接口的设计（不接真实支付，用模拟回调）；回调重复到达的原因；按支付单号幂等；只有"未支付 → 已支付"才更新状态；回调验签思路。

实践：实现支付回调，用脚本重复通知验证只生效一次。

面试考点：支付回调为什么会重复；幂等怎么实现；幂等和分布式锁的区别。

### 第 8 课：异步任务：订单超时取消与通知

目标：把超时取消、支付后通知等动作异步化。

内容：为什么订单需要超时自动取消（延迟任务）；用 Redis 实现延迟任务（Stream / ZSET 到期扫描）；Worker 消费、状态与重试；失败退避。

实践：实现订单超时自动取消，模拟 Worker 失败重试。

面试考点：订单超时取消有哪些实现方式（定时扫描 / 延迟队列 / 消息队列延时消息）；可靠消息需要哪三件事。

### 第 9 课：限流与缓存防护

目标：保护下单等关键接口，防缓存穿透、击穿、雪崩。

内容：下单接口按用户限流（超限返回 429）；不存在菜品的空值缓存（防穿透）；热点菜品缓存击穿防护；批量失效的随机 TTL（防雪崩）。

实践：给下单接口加限流，为菜品缓存加随机 TTL，用脚本观察回源次数。

面试考点：限流算法取舍；缓存三兄弟的成因与对策。

### 第 10 课：日志、监控与订单链路排查

目标：让系统"可观测"，为排错打底。

内容：结构化日志；请求 ID 串联（用户 → 下单 → 支付回调 → 异步任务）；关键指标（接口耗时、错误率、缓存命中率、队列长度、库存变化）与基础告警规则；日志与指标的观察方式（对应 network 排错课与 database 线上排查课）。

实践：给系统加请求 ID 和关键日志，观察一次完整下单的日志串联，并至少配一条告警规则。

面试考点：如何观测一个系统；请求 ID 为什么重要；怎么从日志定位一笔订单的问题。

### 第 11 课：故障注入与排查实战（本课程核心）

目标：主动制造故障，完成真实的排查训练。

内容：依次制造并排查：订单查询慢（缺索引慢 SQL）、菜品缓存穿透/雪崩、库存超卖复现、支付重复通知、订单积压（Worker 卡死）、连接池耗尽。每个故障记录"现象 → 假设 → 定位（日志/指标/命令）→ 修复 → 验证"。

实践：至少排查 3 类故障，并把排查过程写进项目文档。

面试考点：给一个故障场景（页面超时、接口慢、连接满、缓存失效、订单积压），按"界定 → 分层 → 定位 → 验证"讲清排查路径。

### 第 12 课：前端接入与全链路演示

目标：从浏览器把一条外卖业务完整走通。

内容：轻量前端（用户端点餐页面 + 商家管理端简单页面，或模板/API 客户端）；登录 → 浏览菜品 → 加购物车 → 下单 → 支付 → 查看订单状态；**CORS 与跨域（前后端联调的实际处理）**。

实践：从浏览器完成一次完整的点餐流程，处理一次真实的跨域问题。

面试考点：前后端如何协作；CORS 为什么存在、怎么处理；从浏览器视角讲一条请求。

### 第 13 课：测试、部署与面试讲述

目标：交付一个可测试、可部署、可讲述的项目。

内容：接口测试（下单、幂等、库存并发、鉴权）；Docker 部署流程；项目文档；用 5 分钟讲清系统（架构图、亮点、踩过的坑、故障排查）。

实践：完成测试和部署说明，写一页项目讲述稿，并模拟讲一遍。

面试考点：项目介绍怎么讲；怎么把"超卖修复""重复支付处理""故障排查"讲成亮点。

## 综合练习

从第 2 课起逐课累积，最终交付一个可运行、可测试、可部署的外卖系统，包含：认证与安全（鉴权依赖、参数化查询、CORS）、菜品与购物车、下单事务、库存防超卖、支付回调幂等、订单超时取消、限流、缓存防护、日志与指标、至少一个接口测试，以及第 11 课的故障排查记录。

## 阶段验收

1. 能画出完整点餐链路，并指出每层的故障点。
2. 能一条命令启动全套开发环境（含 Nginx 网关）。
3. 能解释订单拆表、事务、超卖、幂等、延迟任务、缓存防护在项目中的落点。
4. 能解释 SQL 注入 / XSS / CSRF 的原理与防护，能说清认证与授权的区别。
5. 能主动制造并完成至少 3 类故障的排查（现象 → 定位 → 修复 → 验证）。
6. 能用 5 分钟讲清项目架构、亮点（超卖、重复支付、超时取消）与踩坑。

## 课程编写约束

- 每课先给"这课在整条链路的哪一环"的全景定位，再讲细节。
- 代码只用前面课程讲过的知识；新概念按《课程编写要求》4.1 规则当场解析。
- 命令、函数、接口一律配注释和速查表。
- 故障注入课必须有完整的"复现 → 定位 → 修复 → 验证"记录。
- 安全内容只讲防护思路，不写可直接滥用的攻击细节。
- 学习版定位：不做真实支付、不做骑手端和配送调度、不写 Kubernetes 和高可用；此类内容只留一句指向后续分布式课程。
- 面试考点以"超卖、重复支付、超时取消、缓存防护、排错"为亮点主线，贯穿全课程。
