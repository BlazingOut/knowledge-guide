# 第6课:全链路串讲

前五课把链路拆成了五段：分清问题、召回、排序、评估、重排与冷启动。本课不新增任何算法，只做两件事：把五段串成一条**可以在面试现场口述**的固定叙事，再用一段不依赖任何机器学习库的综合练习代码把同一条链路跑通。

**学习目标：**

1. 按固定顺序口述一条车货请求从进入到出结果的全过程，每步说清输入和输出；
2. 对“没有特征怎么办、新线路怎么办、AUC 涨了业务不涨怎么办”这类追问，接得住并指到对应环节；
3. 跑通综合练习代码，把每一步输出和五课的概念对上号。

## 1. 固定的讲述顺序

八个步骤，顺序固定。换一个场景（网约车派单、电商推荐）变的只是每步的内容，不变的是顺序：

```text
1 业务目标    -> 优化什么数字（成交率 / 履约率 / 司机等待时长）      [第 1 课]
2 硬约束      -> 车型、路线、载重、时间窗，不满足直接丢弃           [第 2 课]
3 多路召回    -> 规则一路、倒排一路、行为一路，合并去重缩小候选      [第 2 课]
4 特征与标签  -> 一条样本 = 司机 x 货 x 上下文；标签选成交并留观察窗 [第 3 课]
5 模型选择    -> 逻辑回归基线起步，非线性明显换树模型               [第 3 课]
6 离线指标    -> 精确率 / 召回率 / AUC，按时间切分数据              [第 4 课]
7 重排规则    -> 互斥去重、相似去重、保曝光、亏损过滤               [第 5 课]
8 线上指标    -> 成交率、履约率、取消率，不只看离线涨没涨           [第 4、5 课]
```

背下这八个词不是为了背，是为了讲的时候不漏段、不跳段。每一段被追问时，都能退回对应的课展开。

## 2. 走一遍：北京到天津、9.6 米、明早装货

一笔货进入系统：出发地北京，目的地天津，要求 9.6 米厢式车，明早装货。按八步走：

**业务目标。** 这条链路优化的是成交率和履约率——货主尽快找到能接的司机，司机接到跑得成的活，次要指标是司机等待时长。

**硬约束。** 全库货物里，车型不是 9.6 米厢式的直接丢弃；装货时间冲突的丢弃；出发地不在司机可接范围的丢弃。这些条件不满足就是不可能成交，不交给模型。

**多路召回。** 剩下的候选仍然太多。路线一路：装货地、目的地建倒排，北京→天津的货先取出来；车型一路：9.6 米厢式的货取出来；行为一路：历史上跑过京沪方向、常驻北京的司机看过的货取出来。三路合并去重，剩一个几十条的候选集。

**特征与标签。** 每条候选做成一条样本：司机侧的历史成交数、常跑线路，货侧的距离、报价，交叉的“常跑线路是否命中这条路线”，上下文的明早运力。标签用“成交后未取消”，并留出观察窗——昨天发生的展示今天还不能记 0。

**模型选择。** 先上逻辑回归：特征列不多，每列的方向要能解释给运营听。哪个特征在推高分数要答得上来。特征加到明显出现非线性、人工做交叉做不动时，换梯度提升树。

**离线指标。** 按时间切分：上个月训练，这个月测试。看精确率和召回率——前几名里真成交的密度，以及真成交的被找到了多少；AUC 用来和上一版模型比较排序能力。

**重排规则。** 分数排完还要过三道：同线路同车型同时段的重复报价只留一条；新发布的货保一个曝光位；价格低于线路成本的亏损单过滤。

**线上指标。** 上线后看成交率有没有变、履约率有没有掉、取消率有没有升。AUC 涨 0.02 不是上线的理由，这些数字才是。

八个步骤走完，“为什么把这三名司机排在前面”就有了完整答案：他们通过了硬约束和两路召回（没被丢、被找到了），特征和分数说明车型一致、距离近、历史成交多、报价在合理区间（被排到了前面），且没有互相冲突、不是亏损单（重排没有把他们挤下去）。

## 3. 常见追问与接法

追问来了先定位它落在哪一步，再从那一步展开。

**“没有特征怎么办？”** 落在特征与标签。冷启动思路：先用不依赖历史的列（车型、距离、报价），给新实体保曝光换数据，数据回来后特征逐步补齐（第 5 课）。

**“新线路怎么办？”** 同样落在冷启动。整条链路退回规则：报价区间用固定规则，线路标记数据不足，特征显式置缺失；等曝光和成交积累后再回到正常排序（第 5 课）。

**“AUC 涨了、成交率不涨，怎么办？”** 落在离线指标。按顺序查三件事：特征穿越、训练与线上分布差异、目标错位（离线优化点击、业务要履约）。还要看改善是否只发生在尾部——AUC 对头部不敏感（第 4 课）。

**“坏反馈怎么进样本？”** 落在标签。成交后取消的记为 0，且要等取消窗口过去再定标签；曝光未成交和随机抽来的负样本分开记（第 3、5 课）。

**“搜索有查询词，推荐没有，链路差在哪？”** 只差在召回怎么触发：搜索用查询词建倒排直接取候选；推荐没有查询词，用司机画像和行为触发多路召回。召回之后的排序、评估、重排完全同构（第 1、2 课）。

## 4. 综合练习代码做了什么

`code/search-recommend/06-full-walkthrough.py` 用 Python 标准库把八步里的 2 到 7 步跑通（第 1 步和第 8 步是业务指标，代码里以打印代替）。10 票货、6 名司机，查询是一笔“北京→天津、9.6 米箱式、明早装货”的货，系统为它排出司机名单。

代码分六段，每段对应一课，全部打印中间结果：

| 代码段 | 做的事 | 对应课 |
| --- | --- | --- |
| 硬过滤 | 车型、线路方向、装货时段不满足直接丢弃 | 第 2 课 |
| 两路召回 | 路线倒排一路、司机常跑线路行为一路，合并去重 | 第 2 课 |
| 特征表 | 每条候选手工列：距离、历史成交、常跑命中、价格偏离 | 第 3 课 |
| 规则打分 | 一条可解释的加权公式，说明每列方向 | 第 3 课 |
| 重排 | 同实体去重 + 新司机保曝光，打印谁被挤出、为什么 | 第 5 课 |
| 精确率 | 以前 2 名为预测成交，按后来真实成交算 precision | 第 4 课 |

只用字典、列表、集合和排序，不引入任何机器学习库。打分公式是固定权重，不是训练出来的——它演示的是推理和评估的形状，与第 3 课用四行数据做的事一脉相承。

## 5. 运行课程代码

代码在 `code/search-recommend/06-full-walkthrough.py`，只用 Python 标准库，无第三方依赖：

```bash
python code/search-recommend/06-full-walkthrough.py
```

运行后重点对照六段输出：硬过滤删掉了谁、为什么；两路召回各自捞到哪些编号、合并后剩谁；特征表里哪几列来自司机侧、哪几列来自交叉；打分公式把谁抬上去、谁压下来；重排挤掉了谁、新司机的保曝光位给了谁；precision@2 等于多少、漏掉的成交在第几位。

课后作业在文件末尾 `# ===== 课后作业 =====` 之后，默认注释掉。两道题：给货单加一条“新线路”的货并写出它的冷启动处理；把精确率换成召回率并说明排序变好后召回为什么没变。

## 6. 阶段验收

对照课程大纲的八条验收：前三条对应第 1、2 课（区分三种问题、画出四段链路、召回的适用边界），第 4、5 条对应第 3 课（样本与特征、模型取舍），第 6 条对应第 4 课（指标差别），第 7 条对应第 5 课（时间切分、冷启动、重排各防什么错），第 8 条就是本课的口述目标。八条都能口头回答，这门课可以结课。

## 7. 面试高频考点

**用自己的话讲车货匹配。** 按八步顺序讲，每步一句话带输入输出。讲到哪一步被追问，就退回那一课的机制展开；不跳步、不抢先展开深度模型。

**搜索和推荐在这条链路里哪一段不同。** 只有召回的触发方式不同：搜索有查询词，倒排直接取候选；推荐没有查询词，用司机画像和行为触发多路召回。硬约束、排序、评估、重排完全同构。

**如何证明不是只背了名词。** 两个办法：对同一个环节说出它的失败模式（召回口径太窄会漏掉正样本、重排规则伤害纯分数、时间切分不做会虚高）；对追问给出排查顺序（成交率掉了，按召回覆盖、特征穿越、标签定义、重排规则四步走，一次只改一个怀疑点）。

**课程完结。** 综合练习和阶段验收都通过后，这门课的收尾动作是把第 6 节的八步叙事讲给不熟悉推荐的人听——能让他们听懂，才算真的能把车货匹配讲成一条链路。
