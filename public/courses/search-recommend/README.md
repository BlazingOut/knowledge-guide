# 搜索与推荐课程大纲

目标：用较短篇幅建立“一次匹配请求如何从海量候选变成排序结果”的心智模型，能在算法一面把搜索、推荐和车货匹配讲成同一条链路。本课程是快速课：讲清职责边界、样本标签、特征和指标，不推导论文，不展开深度排序网络和大数据组件。

本课程属于基础知识课程。贯穿例子用物流里的车货匹配（货主发货、司机接单），因为约束比普通信息流推荐更明显：路线、车型、时间窗、价格必须先讲清楚。不绑定 Life Manager，也不要求已有推荐实习。

本课程共六课，原则是**先分清问题，再走链路，最后能口述**：第 1 课分清搜索、推荐、匹配和指标；第 2 课讲召回为什么必须先缩小候选；第 3 课讲排序用的样本、特征和模型取舍；第 4 课讲离线评估为什么不能只看准确率；第 5 课讲重排、冷启动和车货约束；第 6 课把一条请求串起来，并收束一面追问。定价、补贴、大模型只作为排序目标或相邻系统一句话带过，不单开课。

## 前置知识

知道分类和回归的差别（成交与否是分类，价格是回归）；会写基础 SQL（过滤、连接、分组）；会读简单 Python。不要求手推反向传播，不要求用过 Spark、Flink 或推荐框架。

## 课程结构

### 第 1 课：搜索、推荐、匹配是三种问题

目标：用同一套判断标准区分搜索、推荐和双边匹配，能画出召回、粗排、精排、重排，并说出每段在优化什么。

内容：搜索有明确查询（司机搜“北京到上海的货”）；推荐没有这句查询，系统猜测司机现在想看什么；车货匹配是双边约束，货和车必须同时满足硬条件，不是“猜你喜欢”。四段链路：召回从全库捞出候选，粗排用轻模型砍到可精排的规模，精排用更重的模型和更多特征打分，重排用业务规则调整顺序。优化目标对照：信息流常看点击率，车货匹配更看匹配率、成交率、履约率和司机接到合适货的时间。本课不讲具体召回算法和模型公式。

实践：用同一批“10 个司机、100 票货”的文字例子，分别写成搜索、推荐、匹配各一步，标出哪一步还没发生模型打分。

面试考点：搜索和推荐差在哪；为什么工业界要分召回和排序；车货匹配比普通推荐多了哪些硬约束；点击率高是否等于业务好。

### 第 2 课：召回：先把候选缩小

目标：说明为什么不能对全库逐条精排，能讲清规则召回、倒排、协同过滤和多路合并各自解决什么。

内容：规模问题：全库打分既慢又浪费，召回负责“别漏掉明显相关的”。车货里的硬过滤先做：线路方向、车型、载重、距离上限、时间窗，不满足的直接丢弃，不交给模型“学习掉”。倒排索引：用城市、车型等键快速取出候选，对应搜索里的关键词检索。协同过滤只讲直觉：看过相似货的司机，或和这票货一起成交过的货；用户侧与物品侧各一句，不讲矩阵分解推导。向量召回只说明“把司机和货变成向量，找近邻”，不讲训练和索引参数。多路召回：规则一路、行为一路、地理一路，合并后去重，再交给排序。召回阶段宁可多给一些，也不能用过严的模型分把正样本滤光。

实践：用 Python 字典模拟倒排（城市、车型 → 货单列表），对一票查询做过滤、多路合并和去重，打印每路召回了谁、合并后剩谁。

面试考点：召回和排序的目标有什么不同；硬过滤为什么不要塞进模型；多路召回为什么需要、合并时冲突怎么办；协同过滤在新司机、新货上为什么会失效。

### 第 3 课：排序：样本、特征、模型怎么选

目标：能把“给候选打分”说成监督学习问题，并说明线性模型与树模型的取舍，而不是背模型名单。

内容：一条样本是“某个司机在某个上下文下看到某票货”。标签按业务选：是否点击、是否成交、是否履约；成交比点击更接近收入，但反馈更慢，要说明标签延迟。特征四类：司机侧（历史接单、常跑线路、活跃度）、货侧（距离、价格、货物类型）、交叉（车型是否匹配、价格相对历史成交价）、上下文（时段、城市运力松紧）。线性模型（逻辑回归）适合作为可解释、易上线的基线：特征贡献能讲给人听。树模型适合表格特征、非线性关系，工业界排序很常见；本课只讲“为什么常比线性模型吃特征更省事”，不讲分裂公式。深度模型只保留一句边界：行为序列很长、特征交叉手工做不动时再考虑，一面不要主动展开结构。负样本：曝光未成交、随机负例不能混为一谈。

实践：手写一张小表（司机、货、距离、车型是否匹配、是否成交），用规则先打一个可解释分数，再说明若改成逻辑回归，输入和标签分别是哪几列。不训练真实模型。

面试考点：排序的标签为什么不能随便用点击；特征穿越是什么（用了当时还不知道的成交后信息）；为什么车货场景往往先上可解释模型；正负样本不均衡时模型会怎样。

### 第 4 课：评估：离线数字怎么才不算骗人

目标：能选择和解释分类指标、排序指标，并说明离线变好不等于线上变好。

内容：成交是少数类，准确率会被“全部预测不成交”刷高，所以要同时看精确率、召回率和 F1。ROC 曲线下面积（AUC）衡量“随机抽一个正样本和一个负样本，正样本分更高的概率”，适合比较排序模型，但不直接等于成交率提升。归一化折损累计增益（NDCG）只讲直觉：正确的货排得越靠前，得分越高；不要求手算长公式。切分方式：车货数据按时间切，不能随机打乱，否则用未来运力预测过去。离线与线上不一致的常见原因：特征穿越、训练集和线上分布不同、离线优化点击但线上要履约。上线判断看业务指标（成交率、履约率、司机等待时长），不只看 AUC 涨了零点几。

实践：给 8 条带分数和标签的排序结果，手工算精确率、召回率，并判断两种排序哪个更符合“好货在前”。用一段错误的随机切分叙述，指出泄漏发生在哪。

面试考点：为什么准确率不够；AUC 高但成交率不涨可能是什么原因；时间切分解决什么；你如何向业务解释“模型变好了”。

### 第 5 课：重排、冷启动，以及车货约束怎么落地

目标：说明精排分数不是最终顺序，能把规则、探索和双边约束放回链路上。

内容：重排做精排不方便做的事：同一司机不要连续看到互相冲突的货、相似货去重、新司机或新货保留最低曝光、明显亏本价格过滤。这些是规则或简单约束，不是再训练一个大模型。冷启动：没有历史成交时，协同过滤和复杂模型都不可靠，退回路程、车型和价格规则，并用少量探索收集反馈。反馈闭环：曝光、点击、成交、取消、履约要分开记，取消多的“高成交预测”可能是坏匹配。定价不展开成一门课：价格是特征，也是成交概率的输入；排序分可以理解成“这个价下成交且能履约的可能性”。补贴、风控、大模型助手各一句边界：补贴改变价格特征，风控负责剔除异常样本，助手负责解释推荐理由，都不替代召回和排序。

实践：给精排已排好的 5 条结果，加上“同城冲突货只能留一条、新司机至少一条”两条规则，写出重排后的顺序，并说明哪条规则伤害了纯分数。

面试考点：为什么有了精排还要重排；冷启动怎么做才不是空话；车货匹配里哪些约束必须硬编码；推荐结果不好时你先查召回、排序还是规则。

### 第 6 课：把一条车货请求讲完

目标：独立口述从请求进入到结果展示的全链路，并能接住一面常见追问。

内容：固定叙事顺序：业务目标 → 硬约束 → 多路召回 → 特征与标签 → 模型选择 → 离线指标 → 重排规则 → 线上看什么。用一笔“北京到天津、9.6 米、明早装货”的货，走到“为什么把这三名司机排在前面”。追问清单：没有特征怎么办、新线路怎么办、AUC 涨了业务不涨怎么办、坏反馈怎么进样本、搜索词和推荐没有查询词时链路差在哪。本课不新增算法，只把前五课收成可以当场讲的版本。明确不讲：深度兴趣网络、广告竞价、Spark 作业、在线 A/B 平台实现细节。

实践：限时 5 分钟口述一遍；再针对“如果成交率掉了”按召回覆盖、特征穿越、标签定义、重排规则四步排查，每次只改一个怀疑点。

面试考点：用自己的话讲清车货匹配的召回和排序；搜索和推荐在这条链路里哪一段不同；你如何证明不是只背了名词。

## 综合练习

选一笔货和一组司机，不调用机器学习库，用 Python 完成：硬过滤、两路召回合并去重、一张手工特征表、按可解释规则打分、两条重排规则、以及用精确率说明这次排序哪里好哪里坏。最后用第 6 课的顺序把同一次运行讲出来。

## 阶段验收

学习者应能够：

1. 区分搜索、推荐和双边匹配，并说出车货场景的硬约束。
2. 画出召回、粗排、精排、重排，说明每段的输入、输出和失败模式。
3. 解释硬过滤、倒排、多路召回和协同过滤的适用边界。
4. 定义一条排序样本的特征、标签和负样本，指出特征穿越。
5. 说明为什么先用逻辑回归做基线，树模型解决什么，深度模型何时才有必要提。
6. 解释准确率失效的原因，以及 AUC、精确率、召回率和业务成交率的差别。
7. 说明时间切分、冷启动和重排规则各自防止什么错误。
8. 在没有真实模型的情况下，把一笔车货请求从头讲到结果和排查顺序。

## 课程编写约束

- 这是快速课，但仍按机制写：每个概念先定义，再讲输入输出，再给车货例子，最后给面试追问。不压成名词表。
- 每课只承担链路中的一段。召回算法、排序模型、评估指标、重排规则不在同一课讲完。
- 例子统一用车货匹配。不要改写成 Life Manager，也不要假装读者已有推荐系统项目。
- 代码只在第 2 课和第 6 课的综合练习出现，使用 Python 标准库做过滤、合并和打分；不引入 PyTorch、Spark 或推荐框架。
- 深度排序模型、广告竞价、在线学习、流处理只点名边界，不写结构和参数。
- 大纲定稿前不写课时正文。
