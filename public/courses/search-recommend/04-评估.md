# 第4课:评估

第 3 课结尾留了一个问题：四行数据里规则的分数和真实成交对不上，那么怎么判断一套分数到底是好是坏？评估回答这个问题。本课全部内容都发生在**离线**：拿一批带标签的历史数据，算出几个数字，用来决定要不要把新模型放到线上。

本课不训练模型，也不写代码。要建立的是三个判断：准确率在成交这种少数类问题上会失效；AUC 和精确率、召回率回答的是不同的问题；离线数字变好不等于线上业务变好。

**学习目标：**

1. 说明成交数据上为什么只看准确率会被误导；
2. 给一批带标签的排序结果，手工算出精确率和召回率；
3. 用“随机抽一正一负”的口径解释 AUC，并说明它衡量的是排序不是成交率；
4. 说明为什么车货数据必须按时间切分，随机切分泄漏在哪里；
5. 列出离线涨、线上不涨的常见原因，并说出上线判断看哪些业务指标。

## 1. 成交是少数类，准确率先失效

先定义场景。手上有一批历史展示：每次展示一条货给一个司机，后来记下有没有成交。8 条展示里 3 条成交、5 条没成交。现在要判断一套分数排出的顺序好不好。

最直觉的指标是**准确率**（accuracy）：预测对了的样本占全部样本的比例。它有一个隐含动作——先把分数变成“成交 / 不成交”两个类别（比如分数大于某阈值算预测成交），再数对错。

失效发生在少数类上。构造一个极端模型：它对所有人都预测“不成交”。

```text
8 条展示：3 成交、5 不成交
模型预测：全部"不成交"
猜对 5 条不成交，准确率 = 5 / 8 = 62.5%
```

这个模型没有排出任何顺序，没有提供任何信息，准确率却有 62.5%。如果按另一种顺序排的模型只拿到 62.5%，它会被误判成“和瞎猜一样”。成交占总展示的比例越小（车货里通常就是小比例），这个空洞越大。结论：**少数类问题上，准确率不能单独用**，需要把“预测为成交的里面有多少真成交”和“真成交的里面被找到了多少”分开数——这就是精确率和召回率。

## 2. 精确率与召回率：一对互相拉扯的数

沿用第 3 课的记法：1 是后来发生的事件（本课统一用“成交”），0 是没发生。把分数收成类别后，每条样本落入四个格子之一：

| | 后来真成交 | 后来没成交 |
| --- | --- | --- |
| 被预测为成交 | TP（真阳性） | FP（假阳性） |
| 被预测为不成交 | FN（假阴性） | TN（真阴性） |

TP / FP / FN / TN 是四个计数的缩写：True/False 说预测对不对，Positive/Negative 说预测成哪一类。准确率就是 (TP + TN) / 全部。

- **精确率**（precision）= TP / (TP + FP)：**预测为成交的里面，真成交的比例**。它回答“排在前面的货可信吗”。
- **召回率**（recall）= TP / (TP + FN)：**真成交的里面，被找出来的比例**。它回答“该找到的货漏了吗”。

两者天然拉扯。把阈值调高——只把分数极高的货判为成交——FP 变少，精确率上升；但同时一些分数中等的真成交被划走，FN 变多，召回率下降。反之放宽阈值，召回率上升、精确率下降。单独报其中一个都可以靠调阈值刷出来，所以两个要一起看。**F1** 是把两者合成一个数的常用方式：取精确率和召回率的调和平均，两者都高 F1 才高，任何一项接近 0 都会把 F1 拖向 0。

车货场景里这对指标有直接的业务读法：精确率低，意味着司机经常看到“看起来好但其实不合适”的货，浪费点击；召回率低，意味着有些本来能成交的货根本没被排到前面，货主等不到人。

## 3. AUC：衡量排序本身的一个数

精确率和召回率都要先选一个阈值把分数切成两类。排序场景更关心另一件事：**正样本是不是普遍排在负样本前面**。**AUC**（Area Under Curve，ROC 曲线下面积）回答的就是它。

口径不用背 ROC 曲线，记住这个等价说法就够：**随机抽一个正样本和一个负样本，正样本分数比负样本高的概率。** AUC = 0.5 等于瞎排；AUC = 1 表示所有正样本都压在所有负样本上面。

这个概率可以拿小数据手数。4 条样本，2 正 2 负：

```text
编号  分数   标签
A    0.9    1
B    0.6    1
C    0.7    0
D    0.2    0

正负配对共 2 x 2 = 4 对：
(A,C) 正高 -> 对    (A,D) 正高 -> 对
(B,C) 正低 -> 错    (B,D) 正高 -> 对
AUC = 3 / 4 = 0.75
```

注意 B 和 C 构成的一对：B 是正样本却排在 C 后面，每出现一对这样的“逆序”，AUC 就损失一份。AUC 只看正负之间的相对顺序，正样本之间的先后它不管——这是它和下一节 NDCG 的关键差别。

两个使用边界。第一，AUC 适合**比较两个模型**在同一批数据上的排序能力（0.76 比 0.74 好），它不是业务数字，AUC 从 0.74 涨到 0.76 不等于成交率涨多少，甚至不等于涨。第二，AUC 高不代表前面的位置排得好——把最好的货从第 1 名换到第 5 名，只要它仍在所有负样本之上，AUC 一分不减。

## 4. NDCG：位置越靠前，贡献越大

业务上位置是有价的：排第 1 的货几乎必被看到，排第 10 的货大概率没人翻到。**NDCG**（Normalized Discounted Cumulative Gain，归一化折损累计增益）把“位置越靠后，贡献打越多折”编进指标里。

只看直觉和趋势，不要求手算公式。每条样本按相关性贡献一个分数，位置越靠后折损越重：

```text
位置     1      2      3      4      5
折损后   1.00   0.63   0.50   0.43   0.39
```

一票真成交的货排在第 1 位，几乎贡献满分；同样这票货排到第 5 位，贡献只剩约四成。把整页按位置折损加起来，再除以“理论最好排序”的得分做归一化，得到 0 到 1 之间的 NDCG：越接近 1，说明好东西越靠前。

AUC 和 NDCG 的分工：AUC 看全体正负样本的相对顺序，适合比较模型；NDCG 看头部位置的安排，更接近“司机第一屏看到什么”。车货匹配的第一屏价值很高，两个都要看。

## 5. 数据按时间切，不随机切

评估前要把历史数据分成训练集和测试集。切法本身就是一个泄漏点。

**随机切分**的做法是把全部展示记录打乱，随机抽 80% 训练、20% 测试。问题在于这些记录在时间上是连续的：同一名司机、同一条线路在 10 月和 11 月的行为高度相似，甚至同一票货前后多次展示会分进两侧。模型在训练集里已经“见过未来”——测试集里的样本和它训练时见过的几乎相同，测出来的分数虚高。车货数据还有一层：运力、价格随时间波动，随机切分让训练集里混进了后来的运力信息。

正确做法是**按时间切**：按请求发生的时间排序，前面的时间段做训练，后面的事件段做测试。它模拟真实上线的情形——模型只用过去，面对的是将来。判断标准同第 3 课的特征穿越一致：**训练时能查到的信息，测试时才允许出现。**

```text
错误：全部记录打乱 -> 随机 80% / 20%
正确：按时间排序 -> 前 80% 时间段训练 -> 后 20% 时间段测试
```

## 6. 离线涨、线上不涨的三个常见原因

离线指标涨了就上线吗？先解释这三个常见的不一致，再谈上线判断。

**特征穿越。** 第 3 课定义过：打分之后才知道的信息进了特征。离线测试集同样会穿越，涨出来的分数是假象。复核办法：逐列问“生成这次分数之前，这个值能查到吗”。

**分布不一致。** 训练和测试数据来自和线上不同的分布。典型如训练数据全是历史成功线路，上线后新线路占比升高；或离线用的是上个月的低谷期，上线时撞上运力紧张。离线数字再好，覆盖不了没见过的情形。

**目标错位。** 离线优化的是标签对应的指标（比如点击），线上考核的是另一件事（比如履约）。第 3 课讲过标签选错会让排序偏向“容易被打开”的货——离线 AUC 涨，说明模型更会预测点击，而业务要的是成交后能履约。

所以上线判断看**业务指标**：成交率、履约率、司机从发货到接单的等待时长。离线指标的作用是把明显更差的模型挡在门外，以及给出“值得上线上看一眼”的理由；它不能替代线上验证。

## 7. 动手：给 8 条结果算指标

8 条展示，3 条真实成交。两个排序：

```text
排序甲（新模型）  货号: 3  7  1  5  2  8  4  6   成交: 1  1  1  0  0  0  0  0
排序乙（旧规则）  货号: 3  2  7  8  1  5  4  6   成交: 1  0  1  0  1  0  0  0
```

取前 4 位为“预测成交”（阈值做法），手工填四个格子：

```text
排序甲：TP = 3（货 3、7、1）  FP = 1（货 5）  FN = 0  TN = 4
        精确率 = 3/4          召回率 = 3/3 = 1
排序乙：TP = 2（货 3、7）    FP = 2（货 2、8） FN = 1（货 1） TN = 3
        精确率 = 2/4          召回率 = 2/3
```

对照准确率：甲 (3+4)/8 = 87.5%，乙 (2+3)/8 = 62.5%，而第 1 节那个“全预测不成交”的模型准确率恰好也是 62.5%——**准确率完全分不出旧规则和瞎猜**，精确率、召回率分得清清楚楚。

再做第 5 节的找泄漏练习。有人这样叙述实验：“把 10 月全部 20 万条展示随机打乱，80% 训练、20% 测试，特征里带了这票货的最终成交价，AUC 0.92。”泄漏有两处：随机切分让同一司机、同一票货时间上相近的记录同时出现在两侧；最终成交价是成交之后才确定的数，放进了特征。修正：按时间切，成交价换成“展示时刻的报价”。

2. 精确率和召回率分别回答什么问题？为什么单看其中一个可以靠阈值刷高？
3. 用“随机抽一正一负”的口径说出 AUC 是什么。两个模型 AUC 0.76 和 0.74，能得出什么、不能得出什么？
4. 把成交货从第 1 位挪到第 5 位，AUC 为什么不变，NDCG 为什么变小？
5. 随机切分的泄漏发生在哪？按时间切是怎么避免它的？
6. 离线 AUC 涨了，上线前你应该先检查哪三件事？

## 9. 面试高频考点

**为什么准确率不够。** 成交是少数类，全预测“不成交”就能拿到接近多数类占比的准确率。要改用精确率（预测为成交的里面有多少真成交）和召回率（真成交的被找到了多少），必要时用 F1 合成一个数。

**AUC 是什么、怎么向业务解释。** 随机抽一个成交样本和一个未成交样本，模型给成交样本更高分的概率。它衡量排序质量，适合比较模型；它不预测成交率涨多少，也不关心头部位置。向业务解释“模型变好了”要落到业务指标：同样的曝光下成交率、履约率有没有变化，而不是 AUC 涨了零点几。

**AUC 涨了、成交率不涨的可能原因。** 离线特征穿越（涨是假象）；离线与线上分布不一致（新线路、运力波动覆盖不到）；目标错位（离线优化点击、业务要履约）；以及改善只发生在尾部而业务价值集中在头部（AUC 对头部不敏感，这时要看 NDCG 或头部指标）。

**时间切分解决什么。** 随机切分让时间上相邻、高度相似的记录分进训练和测试两侧，训练集变相见到了未来；车货数据里运力和价格随时间变化，会进一步放大虚高。按时间切保证“训练用过去、测试用将来”，与线上真实情形一致。

**下一课预告：** 离线数字合格只是拿到上线资格。线上真实的顺序还要经过最后一道工序——重排：同一司机不该连续看到互相冲突的货，新司机新货要有最低曝光。第 5 课讲这些规则怎么放回链路。
