# 滑动窗口

如果说之前的双指针是“点对点”的移动，那么滑动窗口关注的就是**“点对面”**——即一个连续的**子区间**。
它是解决**子数组（Subarray）**或**子串（Substring）**相关问题的头号利器。

---

## 第一部分：核心思想与定义

1. **一句话定义**：维护一个由左右两个指针围成的“窗口”，通过移动右边界扩展窗口，移动左边界收缩窗口，从而在 $O(N)$ 时间内捕捉所有可能的子区间。
    
2. **核心思想**：
    
    - **类比**：就像一台**扫描仪**。窗口在数组上滑过，窗口的大小可以固定（如寻找长度为 k 的最大和），也可以动态变化（如寻找满足条件的最短子串）。
        
3. **关键特征**：
    
    - 解决的问题通常与**连续**有关。
        
    - 窗口内的状态（和、最大值、字符频率）随着边界移动而增量更新。
        
4. **视觉化表示**：
    

Plaintext

```
Array: [ 2,  3,  1,  2,  4,  3 ]  Target Sum = 7

Step 1: [ 2, 3, 1, 2 ] -> Sum=8 (Too big! Shrink Left)
          L        R
Step 2:    [ 3, 1, 2 ] -> Sum=6 (Too small! Expand Right)
             L     R
Step 3:    [ 3, 1, 2, 4 ] -> Sum=10 (Too big! Shrink Left)
             L        R
```

---

## 第二部分：适用场景与问题识别

1. **问题特征信号**：
    
    - **关键词**：最长子串、最小连续子数组、至少包含...、滑动窗口。 
        
    - **常见模式**：
        
        - “找满足某个条件的**最短**连续子区间。”
        - “找满足某个条件的**最长**连续子区间。”
        - “固定窗口大小为 K，求某个最值。”
            
2. **适用场景**：
    
    - **最佳使用**：数组/字符串中要求结果必须是**连续**的。
        
    - **不适用**：要求结果可以是不连续的子序列（此时考虑动态规划或回溯）；数组包含负数且求和（此时窗口逻辑会失效，通常改用前缀和+哈希表）。
        
3. **与其他方法的关系**：
    
    - **vs 暴力双循环**：暴力法枚举所有子数组 $O(N^2)$，滑动窗口只需 $O(N)$。

## 第三部分：标准化解法模板（Python）

这是滑动窗口最通用的“万能公式”。掌握了这个逻辑，你能解决 90% 的窗口题。


```python
def sliding_window(nums):
    left = 0
    right = 0
    window_state = ... # 用于记录窗口内状态（如 sum, count 等）
    res = ... # 记录最终答案
    
    # 1. 右边界不断扩张
    while right < len(nums):
        # a. 【入窗】：将 nums[right] 加入窗口，并更新 window_state
        # ... (你的逻辑)
        
        # 2. 判断是否需要收缩左边界
        # 这里的 condition 取决于是求“最长”还是“最短”
        while window_needs_shrink(window_state):
            # b. 【出窗】：将 nums[left] 移出窗口，并更新 window_state
            # ... (你的逻辑)
            left += 1
            
        # 3. 【更新结果】：在这里更新你的 res
        # 注意：求最长通常在 while 外更新，求最短通常在 while 内更新
        res = update_res(res, left, right)
        
        right += 1
        
    return res
```
简单模板
```python

    left = 0

    for right in range(len(nums)):
        # 1. 入窗：更新窗口状态

        while (condition_not_met):
            # window_state.remove(nums[left])
```

### 边界条件与陷阱

- **初始化**：`left = 0`, `right = 0`。
    
- **更新顺序**：先增加 `right` 还是先更新结果？建议严格遵循“入窗 -> 收缩 -> 更新结果”的逻辑。

## 第四部分：精选题目与学习路径

### **核心母题（1-2题）**

#### 1. [LeetCode #209. 长度最小的子数组](https://leetcode.cn/problems/minimum-size-subarray-sum/)

- **为什么选此题**：最基础的变长滑动窗口。
    
- **解题逻辑**：
    
    1. 移动 `right` 累加 `sum`。
        
    2. 一旦 `sum >= target`，尝试收缩 `left` 以减小长度，同时记录最小值。
        
- **复杂度**：时间 $O(N)$，空间 $O(1)$。
    

#### 2. [LeetCode #3. 无重复字符的最长子串](https://leetcode.cn/problems/longest-substring-without-repeating-characters/)

- **为什么选此题**：结合了**哈希表**和滑动窗口。
    
- **解题逻辑**：用哈希表记录字符频率。当某个字符频率 > 1，说明重复了，开始收缩 `left` 直到重复字符消失。
    
#### **[LeetCode #76. 最小覆盖子串 (Hard)](https://leetcode.cn/problems/minimum-window-substring/)**

- **为什么选此题**：它是滑动窗口的**终极形态**。
    
- **难点**：你需要维护一个哈希表来记录“还差多少个字符才能满足要求”。它完美结合了：双指针收缩逻辑 + 复杂的哈希表计数更新。
    
- **建议**：先自己写，写不出来再看题解，重点看 `need` 和 `have` 两个变量是如何同步的。
    

#### **[LeetCode #424. 替换后的最长重复字符 (Medium)](https://leetcode.cn/problems/longest-repeating-character-replacement/)**

- **为什么选此题**：考察窗口内的**全局状态维护**。
    
- **难点**：你需要实时知道窗口内出现频率最高的字符次数。
    
- **启发**：这题会让你理解为什么有时候我们不需要在 `while` 里完全收缩窗口，而只需要让窗口“平移”。

## 第五部分

重新审视收缩边界。

从76题可以看出一个新的问题，左边界的收缩是每一步都需要的吗？

左边界的作用有两个：
- 静态情况下，left-right是满足 了题目中的条件的情况
- 动态情况下，left的收缩承担了一个筛选的过程（通常需要计算最小长度）

那么在我们可以看出，通常计算最小满足的时候，不可能一上来就满足静态状况的，这里其实有一个等待的过程：等待right扩张直到满足条件。

那么，完整的模板应该是
```python
# 1. 入窗
window_state(nums[right])

# 1.1 积累condition 1
condition_1 更新

# 2. 收缩
if condition 1：
	while 收缩条件:
		
```
然而大多数情况下，这个收缩条件与condition1是一样的，所以我们不需要单独写出来。


## 本质

滑动窗口的本质是**枚举每一个位置作为终点（right）时，能向左延伸的最远距离**。 对于每一个 `right`：

- 我们尽可能地包含它。
    
- 如果包含它导致 `0` 太多了，我们不得不放弃掉左边的一些元素。
    
- 当 `while` 结束时，我们得到了以当前 `right` 结尾的、满足条件的最长区间。
