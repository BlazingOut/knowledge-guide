# 分布式后端基础课程大纲

目标：建立对分布式后端常见问题的基础认识，理解服务拆分后会出现哪些新的故障，以及如何使用超时、重试、限流、熔断、降级、幂等和最终一致性控制影响范围。

本课程不以搭建复杂微服务平台为目标，也不深入 Kubernetes、Raft、Paxos 和大规模分库分表。重点是能够读懂常见后端架构，设计一个基本可靠的服务调用流程，并解释其中的取舍。

本课程共九课。前两课建立分布式系统的基本模型；第 3 课讲负载均衡与一致性哈希（请求如何路由到实例、数据如何均匀分片）；第 4 至 6 课学习服务可靠性（超时、重试与幂等、限流熔断降级）；第 7 课讲分布式一致性与业务操作（含分布式事务概念与任务租约）；第 8 课讲高可用与分布式 ID；第 9 课进行综合设计与故障排查。

## 前置知识

完成 Python、FastAPI、数据库和 Redis 基础课程，能够：

- 编写并测试一个 FastAPI 接口；
- 理解进程、线程、端口和 HTTP 请求；
- 使用数据库事务和参数化 SQL；
- 使用 Redis 完成缓存、计数、限流和幂等；
- 解释超时、异常和日志的基本作用。

## 课程结构

### 第 1 课：单机、集群与分布式系统

目标：区分单机系统、集群和分布式系统，理解为什么应用从一台机器扩展到多台机器后会产生新的问题。

内容：

- 单体应用和多实例应用；
- 集群与分布式系统的区别；
- 服务、节点、客户端和网络；
- 数据共享和状态管理；
- 单点故障；
- 水平扩展与垂直扩展；
- 网络调用与函数调用的区别；
- 部分节点失败时系统可能处于什么状态。

实践：把一个单进程 FastAPI 应用画成两个应用实例、一个数据库和一个 Redis 的架构图，标出每个组件的状态和故障影响。

### 第 2 课：CAP、BASE 与最终一致性

目标：理解分布式系统中的一致性、可用性和分区容错，以及最终一致性的基本含义。

内容：

- 网络分区和节点不可达；
- 一致性、可用性和分区容错；
- CAP 的适用边界；
- 强一致性和最终一致性；
- BASE 的基本思想；
- 为什么不能简单说“CAP 只能三选二”；
- 缓存、数据库副本和消息系统中的最终一致性。

实践：模拟一个数据库和缓存之间的短暂不一致，说明系统如何通过删除、重试、过期或补偿最终恢复。

### 第 3 课：负载均衡与一致性哈希

目标：理解多实例下请求如何被路由到某个实例，以及数据如何均匀分布到多台节点；能说明负载均衡算法与一致性哈希的取舍。

内容：

- 为什么需要负载均衡：水平扩展后请求要分流到多个实例，避免单点过载和单点故障；
- 负载均衡的两种位置：客户端侧（调用方选择实例）和服务端侧（网关或反向代理转发）；
- 常见算法：轮询、随机、加权轮询、最小连接——各自的适用场景；
- 取模分片的问题：节点增减时大量数据需要重新映射；
- 一致性哈希：哈希环、虚拟节点，如何在节点增减时只影响局部；
- 一致性哈希在缓存分片、数据库分片和负载均衡中的用法；
- 负载均衡与健康检查：如何剔除不可用实例。

实践：用 Python 字典模拟一个负载均衡器（轮询、随机、加权），再对比取模和一致性哈希在“增加一个节点”时的重映射比例，打印每次请求路由到哪个节点。

面试考点：轮询和加权轮询的区别；为什么取模在扩缩容时不好；一致性哈希怎么减少重映射；虚拟节点解决什么问题。

### 第 4 课：服务间调用与超时

目标：设计一个有明确超时边界的服务调用流程。

内容：

- 同步调用和异步调用；
- 服务调用链；
- 连接超时、读取超时和整体请求超时；
- 超时预算如何在多级调用中分配；
- 为什么没有超时的网络请求可能拖垮线程或协程；
- 超时后的返回、取消和资源释放；
- HTTP 客户端的基础超时配置。

实践：实现一个调用下游服务的 FastAPI 接口，为连接和读取设置超时，并记录调用耗时和失败原因。

### 第 5 课：重试、退避与幂等

目标：理解什么时候可以重试，如何避免重试放大故障。

内容：

- 临时错误和永久错误；
- 哪些请求适合重试；
- 固定间隔、指数退避和随机抖动；
- 最大重试次数；
- 重试风暴；
- 请求超时但服务端可能已经成功的问题；
- 幂等键与重复提交；
- 重试和事务的关系。

实践：为一个下游查询调用增加有限次数的指数退避重试，并区分可重试错误和不可重试错误。

### 第 6 课：限流、熔断与降级

目标：在下游服务变慢或不可用时限制影响范围。

内容：

- 限流保护什么；
- 客户端限流和服务端限流；
- 并发数限制和请求速率限制；
- 级联失败与雪崩效应：一个慢服务如何逐级拖垮整条调用链，以及为什么要在源头掐断；
- 熔断器的关闭、打开和半开状态；
- 连续失败为什么需要暂时停止调用；
- 降级数据、默认结果和快速失败；
- 限流、熔断和降级之间的区别；
- 429、503 等状态码的基本使用场景。

实践：为一个模拟下游服务增加失败计数，连续失败后暂时熔断，并返回一个明确的降级响应。

### 第 7 课：分布式一致性与业务操作

目标：理解跨数据库、缓存和消息系统的业务一致性问题，能说清常见分布式事务方案的取舍。

内容：

- 单个数据库事务的边界；
- 为什么跨服务调用不能直接共享本地事务；
- 分布式事务方案的概念级对比：2PC（两阶段提交）、TCC（Try-Confirm-Cancel）、Saga 与本地消息表——各自解决什么、是强一致还是最终一致、代价与适用场景；
- 最终一致性和补偿任务；
- Outbox Pattern 的基本思路；
- 操作状态和状态机；
- 业务幂等与重复消息；
- 任务执行租约：为什么任务可能永久停留在 `running`；
- 租约超时、心跳续约、超时扫描与过期任务重新领取；
- 恢复重跑为什么必须配合执行幂等；
- 无法安全重放的外部副作用（发邮件、扣款、调用第三方）如何谨慎处理；
- 库存、余额和普通展示数据的一致性差异。

实践：设计一个“数据库写入后发送任务”的流程，记录发送失败时的状态，并说明如何重试和补偿。再模拟一个 Worker 执行业务成功后、更新任务状态前崩溃的场景：任务停留在 `running`，说明如何通过租约超时、心跳和扫描恢复它，以及恢复后重跑为什么需要幂等或去重保护。

### 第 8 课：高可用、故障转移与分布式 ID

目标：理解副本、故障转移和分布式 ID 的基本用途。

内容：

- 主从、副本和读写分离的基本概念；
- 故障检测和故障转移；
- 单点故障和冗余；
- 数据副本之间的延迟；
- 分布式 ID 为什么需要全局唯一；
- UUID、数据库号段和 Snowflake 思路；
- 时钟回拨和 ID 生成风险；
- 高可用不等于数据永不丢失。

实践：为一个多实例任务系统设计任务 ID，比较 UUID 和带时间顺序的 ID，并说明各自的优缺点。

### 第 9 课：综合系统设计与故障排查

目标：完成一个小型分布式后端设计，并根据故障现象定位问题。

综合场景：设计一个接收用户请求、写入数据库、发送异步任务并调用模型服务的 API。

要求说明：

- 哪些数据由数据库保存；
- 哪些状态可以放 Redis；
- 哪些操作需要幂等；
- 请求如何路由到多个实例（负载均衡）；
- 下游调用的超时和重试策略；
- 如何限流、熔断和降级；
- 任务失败如何重试；
- 消息重复消费如何处理；
- 服务不可用时用户看到什么结果；
- 如何通过日志定位一次请求失败。

故障排查至少覆盖两种情况：

- 下游服务响应变慢；
- 重试导致请求数量增加；
- 缓存与数据库短暂不一致；
- 消息重复消费；
- 某个服务实例不可用；
- 分布式 ID 出现重复或顺序异常。

## 综合练习

完成一个“可靠的异步任务 API”：

```text
客户端
    -> API 网关或 FastAPI
    -> 限流和幂等检查
    -> 写入数据库
    -> 写入任务消息
    -> Worker 消费任务
    -> 调用下游服务
    -> 超时、重试或降级
    -> 更新任务状态
```

最低要求：

- 一个同步 API；
- 一个数据库事务；
- 一个 Redis 状态或幂等记录；
- 一个异步任务消费者；
- 一个带超时的下游调用；
- 有限次数重试和退避；
- 一种限流或熔断策略；
- 任务状态和失败原因；
- 一份故障排查记录。

## 阶段验收

学习者应能够：

1. 区分单机、集群和分布式系统。
2. 解释网络分区、CAP 和最终一致性的基本含义。
3. 解释负载均衡算法（轮询、加权、最小连接），说明一致性哈希在节点增减时为什么优于取模。
4. 为服务间调用设置连接、读取和整体超时。
5. 判断一个失败是否适合重试。
6. 使用退避和最大次数限制重试。
7. 解释重试为什么必须结合幂等。
8. 区分限流、熔断和降级，说明级联失败与雪崩的成因。
9. 说明跨服务操作为什么不能直接依赖单个本地事务。
10. 对比 2PC、TCC、Saga 和本地消息表的取舍。
11. 设计一个带状态、重试和补偿的异步任务流程。
12. 说明任务为什么可能永久停留在 `running`，并设计租约超时恢复与幂等保护的流程。
13. 解释副本、故障转移和数据丢失之间的关系。
14. 说明分布式 ID 要解决的问题。
15. 根据日志、耗时、错误类型和任务状态定位常见故障。

## 本课程暂不深入

- Raft、Paxos 和其他共识算法的完整推导；
- Kubernetes 控制面和服务网格；
- 完整微服务注册发现平台；
- 大规模分库分表和跨地域部署；
- 分布式事务协议的完整实现；
- 高级容量规划和压测方法；
- 云厂商具体产品的运维细节。

## 课程编写约束

- 每课只引入少量新的分布式概念，先用单机模拟观察，再解释多节点问题。
- 每课应包含学习目标、知识点、项目对应场景、可运行示例、课后作业和验收问题。
- 示例必须明确哪些故障是模拟出来的，哪些行为是真实网络或进程行为。
- 所有重试示例必须设置最大次数和退避，不能写无限重试。
- 所有写操作示例必须讨论幂等和重复执行。
- 不把“加了 Redis”或“部署了多台机器”直接等同于高可用。
