# 环境隔离与切换

> 第一课讲了隔离的机制，这一课把它讲深，并亲手验证：容器里的网络世界是什么样的，端口映射到底在做什么，两个容器为什么互不干扰，以及怎样切换环境。
>
> 目标：能解释"本机 Python 为什么连得进容器里的 Redis"，能证明容器是隔离的，并会切换环境。

## 一、这一课要解决什么问题

一个很自然的疑问：

```text
Redis 明明运行在容器里
    -> 本机的 Python 为什么连 127.0.0.1:6379 就能用？
    -> 这个 127.0.0.1:6379 到底是容器的，还是我电脑的？
    -> 两个 Redis 容器同时跑，会互相干扰吗？
    -> 想换一个 Redis 版本，怎么换？
```

第一课说"容器有自己的网络空间"，但没有解释清楚它意味着什么。这一课先把机制讲透，再亲手验证。

本课回答五个问题：

1. 容器里的网络世界和外面的世界是什么关系？
2. 端口映射到底在做什么，数据是怎么从 Python 到 Redis 的？
3. 两个容器同时运行，为什么互不干扰？
4. 隔离的"三面墙"各自的原理是什么？
5. 怎样切换环境（版本、容器、端口）？

命令示例中 `#` 后面的文字是注释，实际执行时不输入。

## 二、容器里的网络世界

### 1. Redis 监听的是"容器世界"的端口

```text
容器内部（独立的小世界）
    redis-server 进程
        -> 监听容器内部的 6379 端口
        -> 在容器里连 127.0.0.1:6379 直接通
```

执行 `docker exec -it redis-course redis-cli` 时，你已经站在容器内部，和 Redis 在同一个世界里，所以不需要任何映射。

### 2. 容器也有 IP，但通常不该用它

```text
每个容器在 Docker 的内部网络里有一个 IP（如 172.17.0.2）
    -> 这个 IP 每次重建容器都可能变
    -> 它不是给使用者对外的稳定入口
    -> 面向使用者的入口应该是端口映射
```

从宿主机的角度看，容器里的 Redis 是"看不见的"——就像房间里的人，外面的人不知道他的分机号是多少。

## 三、端口映射的机制

### 1. 没有映射时

```text
你的 Python（Windows 世界）
    -> 连接 127.0.0.1:6379
    -> 找 Windows 本机的 6379 端口
    -> 那里什么都没有（门是关的）
    -> Connection refused
```

注意：**Redis 其实还在好好运行**，只是容器外部的世界够不到它。它只在自己的世界里等连接。

### 2. 加上 `-p 6379:6379` 之后

```text
你的 Python（Windows 世界）
    -> 连接 127.0.0.1:6379      （敲本机的门 A）
    -> Docker 收到：转发到容器 6379（门 B）
    -> 容器里的 redis-server 处理命令
    -> 结果原路返回
```

`-p` 的格式是 **本机端口 : 容器端口**：

```text
-p 6379:6379
   左侧 6379：你 Windows 上的入口（门 A）
   右侧 6379：容器内部 Redis 监听的门牌（门 B）
```

### 3. 类比：总机转分机

容器里的 Redis 像办公室里坐在工位上的人，**分机号 6379**。`-p` 是在总机上把一条直线接到这个分机：

```text
外部打直线号码（本机 6379）
    -> 总机（Docker）转接
    -> 分机响（容器里的 6379）
    -> Redis 接起来
```

### 4. 为什么两侧可以不同

`-p 6380:6379` 表示：本机开 6380 号门，通到容器里的 6379 号门。左侧是"外面的人怎么敲门"，右侧是"里面的分机号是多少"，两者独立。容器里的 Redis 不需要做任何修改。

### 5. 两种连接方式对比

| 方式 | 路径 | 需要映射吗 |
|---|---|---|
| 本机 Python 连 `127.0.0.1:6379` | Windows → 门 A → 转发 → 门 B | 需要 |
| `docker exec -it redis-course redis-cli` | 直接进容器内部，同一世界 | 不需要 |

两种方式连到的是**同一个 Redis**，区别只是从哪个门进去。

## 四、两个容器看隔离

### 1. 同时跑两个 Redis

```bash
docker run --name redis-course-7 -p 6379:6379 -d redis:7   # 第一个 Redis：版本 7
docker run --name redis-course-6 -p 6380:6379 -d redis:6   # 第二个 Redis：版本 6，本机换端口 6380
```

用 `docker ps` 观察：两个容器同时在运行，各自有自己的名字、端口和进程。

### 2. 验证数据隔离

进入第一个容器写入一条数据：

```bash
docker exec -it redis-course-7 redis-cli   # 进入容器 7 的命令行
```

```text
127.0.0.1:6379> SET course:isolated "only in container 7"
OK
127.0.0.1:6379> exit
```

进入第二个容器读取：

```bash
docker exec -it redis-course-6 redis-cli   # 进入容器 6 的命令行
```

```text
127.0.0.1:6379> GET course:isolated
(nil)
```

第二个容器读不到第一个容器写的数据。两个 Redis 看似长得一样，实际是两套完全独立的数据。

### 3. 小结

```text
两个容器 = 两个隔离的环境
    -> 进程互不可见
    -> 文件系统互不可见
    -> 数据互不可见
    -> 通过各自的本机端口对外提供服务
```

`docker exec` 是本课反复用到的最小命令（完整用法在下一课）：

```text
docker exec：在运行中的容器里执行命令
-it：交互式模式（保持输入并分配终端）
redis-cli：在容器里启动 Redis 命令行客户端
```

## 五、隔离机制：三面墙的原理

第一课说容器有"三面墙"，这一课把每面墙的机制说清楚。**不需要记操作系统术语，只需要知道"为什么"**。

### 1. 进程：容器有自己的进程世界

```text
容器里看到的进程列表
    -> 和宿主机看到的不一样
    -> 容器里的进程不知道自己"外面"还有进程
```

机制层面：操作系统允许一组进程拥有独立的进程编号空间，容器里的 1 号进程是它自己的进程，和宿主机的进程编号无关。使用者的感受：像一台独立电脑在运行。

验证：

```bash
docker exec -it redis-course-7 ps -ef   # 容器里的进程列表，和宿主机 docker ps 看到的视角不同
```

### 2. 文件系统：容器有自己的根文件系统

```text
容器里的 / 目录
    -> 来自镜像的分层文件系统
    -> 不等于 Windows 的 C 盘根目录
```

机制层面：容器启动时，Docker 把镜像的只读分层加一个可写层，组装成容器自己的文件系统视图。容器里的进程读写文件，都发生在这个视图里。

验证：

```bash
docker exec -it redis-course-7 ls /   # 看到的是 Linux 目录结构，不是 C 盘
```

### 3. 网络：容器有自己的端口空间

```text
容器内部的 6379
    -> 默认只存在于容器世界里
    -> 必须通过 -p 映射，外面才够得到
```

机制层面：每个容器有独立的网络空间，里面有自己的一套端口。外面世界的 6379 和容器世界的 6379 是两个不同的门牌号，端口映射就是给两个世界之间接一根管道（第三节已经讲过这根管道怎么工作）。

## 六、切换环境

### 1. 换 tag = 换版本环境

```text
redis:7   -> 环境 A：Redis 7
redis:6   -> 环境 B：Redis 6
redis:7.4 -> 固定到 Redis 7.4 系列的环境
```

应用代码不用变，想换环境的版本，就换镜像 tag。这是"切换环境"最直接的形式。

### 2. 多个容器 = 多个环境并存

同一个镜像也可以起多个容器，每个都是独立环境：

```bash
docker run --name redis-a -p 6381:6379 -d redis:7   # 环境 A
docker run --name redis-b -p 6382:6379 -d redis:7   # 环境 B，同一镜像
```

互不影响，想删哪个删哪个。Redis 第一课里用过的 6380 端口例子，本质就是两个环境并存。

### 3. 端口映射决定入口

结合第三节的机制：

```text
容器内部端口不变（Redis 都监听 6379）
本机暴露端口是你的访问入口（6379 / 6380 / 6381 ...）
换本机端口 = 换一个入口 = 访问到不同的环境
```

两个容器不能同时映射同一个本机端口，否则第二个启动失败——因为门 A 只能通向一扇门 B。

| 命令 | 含义 | 参数说明 |
|---|---|---|
| `docker run 镜像:tag` | 创建并启动容器 | `--name` 起名，`-p` 端口映射，`-d` 后台运行 |
| `docker ps` | 查看运行中的容器 | 加 `-a` 显示所有容器 |

| `docker stop 容器` | 停止容器 | — |
| `docker rm 容器` | 删除容器 | 运行中加 `-f` 强制删除 |

## 八、完整练习

```bash
# 1. 查看当前有哪些容器
docker ps -a

# 2. 同时启动 Redis 7 和 Redis 6
docker run --name redis-course-7 -p 6379:6379 -d redis:7
docker run --name redis-course-6 -p 6380:6379 -d redis:6

# 3. 确认两个容器都在运行
docker ps

# 4. 容器内验证数据隔离：进容器 7 写入
docker exec -it redis-course-7 redis-cli
#   执行 SET course:isolated "only in 7"，然后输入 exit

# 5. 容器内验证数据隔离：进容器 6 读取，应得到 (nil)
docker exec -it redis-course-6 redis-cli
#   执行 GET course:isolated，然后输入 exit

# 6. 从外面验证端口映射：用本机 Python 连接容器 7 的 Redis
python -c "import redis; c=redis.Redis(host='127.0.0.1', port=6379, decode_responses=True); print(c.ping(), c.get('course:isolated'))"
#   需要先安装 Python 的 redis 包（Redis 课程第一课安装过）

# 7. 认识"换 tag 就是换环境"：再起一个固定版本的 Redis
docker run --name redis-course-7-2 -p 6381:6379 -d redis:7.4

# 8. 练习结束，清理自己创建的容器
docker stop redis-course-7 redis-course-6 redis-course-7-2
docker rm redis-course-7 redis-course-6 redis-course-7-2
```

第 6 步就是在回答本课开头的问题：Python 走本机 6379 的门，Docker 转发到容器 6379，容器里的 Redis 响应，结果原路返回。如果这一步报 `Connection refused`，先确认容器在运行、映射正确。

练习结论：

```text
容器是隔离的：数据、进程、文件系统互不干扰
端口映射是通道：本机端口 -> Docker 转发 -> 容器端口
环境是可切换的：tag、容器、端口都可以作为切换手段
```

## 九、常见错误

### 1. 两个容器映射同一个本机端口

```bash
docker run --name redis-course-7 -p 6379:6379 -d redis:7
docker run --name redis-course-6 -p 6379:6379 -d redis:6   # 报错：端口已被占用
```

本机端口必须唯一，第二个容器换一个端口（如 6380）。原因见第六节：门 A 只能通向一扇门 B。

### 2. 对已停止的容器执行 exec

```text
Error response from daemon: container ... is not running
```

`docker exec` 只能进入运行中的容器。先 `docker start` 或重新 `docker run`。

### 3. 以为容器之间数据互通

本课第四节已经验证过：不互通。每个容器是独立环境，删除一个不影响另一个。

### 4. 用容器的内部 IP 连接

```text
容器的 IP（如 172.17.0.2）会随重建变化，且不是对外入口
```

需要从外部访问容器服务时，用端口映射，而不是容器的内部 IP。

### 5. 练习完不清理容器

容器会持续占用端口和资源。练习结束后按"先 stop 再 rm"的顺序清理自己创建的容器。

## 十、面试回答模板

### 题目：容器是怎么做到隔离的？

> 容器通过操作系统的进程、文件系统和网络隔离能力，让一组进程拥有独立的进程树、文件视图和端口空间，它们共享宿主机内核。所以容器在使用者看来像一台独立的小电脑，机制上是一组隔离的进程。两个容器同时运行，数据和进程互不干扰。

### 题目：端口映射是怎么工作的？

> 容器里的服务监听的是容器内部的端口，容器外面的世界默认访问不到。`-p 本机端口:容器端口` 把两者连起来：发到本机端口的数据被 Docker 转发到容器端口，结果再原路返回。没有映射时，从宿主机连接会 Connection refused，但容器里的服务仍在运行。

### 题目：怎样切换环境？

> 环境可以理解成"镜像版本 + 配置"。换镜像 tag（如 `redis:7` 换成 `redis:6`）就是切换版本环境；同一个镜像起多个容器、用不同端口，就是多个环境并存。需要可复现时用具体版本 tag，避免依赖会漂移的 `latest`。
