# 镜像与容器的日常管理

> 这一课在第一课的基础上，把镜像和容器这两个概念变成能熟练使用的日常命令。
>
> 目标不是背命令，而是能回答：本机有哪些镜像？哪些容器在运行？怎么停止、启动、删除？怎么看日志、进容器？

## 一、这一课要解决什么问题

第一课已经会用 `docker run` 启动容器。使用一段时间后，会碰到新的问题：

```text
装了好几个镜像
    -> 不知道本机到底有哪些
    -> 容器停止后找不到它了
    -> 想清理又怕删错东西
```

本课回答七个问题：

1. 怎样查看本机已有的镜像？
2. 镜像的 tag 是什么，`latest` 有什么问题？
3. 镜像从哪里来？怎样判断别人分享的镜像能不能用？
4. 容器有哪些状态，怎样停止、启动、删除？
5. 怎样查看容器的日志？
6. 怎样进入正在运行的容器执行命令？
7. 怎样安全地清理镜像和容器？

命令示例中 `#` 后面的文字是注释，实际执行时不输入。

## 二、镜像管理

### 1. 查看本机镜像

```bash
docker images
```

它会列出本机已有的镜像：

```text
REPOSITORY   TAG      IMAGE ID       CREATED       SIZE
hello-world  latest   4ab4c602aa5e   2 weeks ago   3.77kB
redis        7        c6c9052d7d24   4 weeks ago   159MB
```

```text
REPOSITORY：镜像名字
TAG：版本标签
IMAGE ID：镜像的唯一标识
SIZE：占用的磁盘大小
```

### 2. 拉取镜像

`docker run` 在本地没有镜像时会自动拉取。如果想只下载、不创建容器，用 `docker pull`：

```bash
docker pull redis:7
```

这样做的好处是：可以提前把镜像准备好，拉取过程中的下载进度也更直观。

```text
docker run 镜像名    ≈  拉取（如果本地没有） + 创建容器 + 启动容器
docker pull 镜像名   ≈  只拉取，不创建容器
```

### 3. 镜像的 tag

`redis:7` 里冒号后面的是 tag。规则：

```text
docker run redis        -> 等价于 docker run redis:latest
docker run redis:7      -> Redis 7 大版本，会跟随 7.x 的小版本更新
docker run redis:7.4    -> 固定到 7.4 系列
docker run redis:7.4.1  -> 固定到具体小版本
```

需要注意 `latest`：

```text
latest 不是"最新最好的版本"，只是一个可变的标签
今天和明天拉到的 latest，内容可能不一样
需要可复现的环境时，用固定的版本 tag
```

### 4. 镜像存在哪里

镜像由 Docker 统一管理，不存放在你的项目文件夹里。Windows + WSL2 后端时，镜像存在 WSL 的虚拟磁盘文件中。可以用：

```bash
docker system df
```

查看镜像、容器和数据卷占用的磁盘空间。清理不再被引用的悬空镜像：

```bash
docker image prune
```

### 5. 镜像从哪里来：别人分享的环境

Redis 课程里的 `redis:7` 就是一个由 Redis 官方维护、分享在 Docker Hub 上的镜像。这也是 Docker 最常见的用法：**不需要自己从零构建环境，直接用别人已经打包好的镜像**。

```text
别人把环境打包成镜像
    -> 发布到 Docker Hub（或其他镜像仓库）
    -> 你通过 docker pull 或 docker run 直接使用
```

"查看别人分享的环境"体现在几个地方：

```text
镜像页说明：https://hub.docker.com/_/redis
    写清楚镜像是做什么的、有哪些 tag、怎么使用

docker search redis
    在命令行搜索 Docker Hub 上的镜像

docker history redis:7
    查看这个镜像是分几步、用什么方式构建出来的

docker inspect redis:7
    查看镜像的详细配置
```

判断一个镜像能不能用，先看：

- 是否是官方镜像（Docker Official Image 标识）或可信发布者；
- 下载量和更新维护状态；
- 镜像页面的说明是否清楚，用法和版本是否明确。

不要随意运行来源不明的镜像，尤其是会挂载目录、或需要管理员权限的镜像。

## 三、容器的生命周期

### 1. 容器有哪些状态

```text
镜像 image（只读模板）
    | docker run：创建并启动
    v
运行中 running
    | docker stop：停止
    v
已停止 stopped
    | docker start：再次启动
    v
运行中 running
    |
    | docker rm：删除（运行中需要先停止，或加 -f）
    v
已删除 removed
```

可以把容器理解成一台用镜像"图纸"搭出来的机器：开机、关机、重新开机、报废拆除。停止不是删除，删除才是消失。

### 2. 停止和启动

```bash
docker stop redis-course     # 停止容器：先给进程发停止信号，超时后强制结束
docker start redis-course    # 启动一个已停止的容器
docker restart redis-course  # 重启：等于先停止再启动
```

### 3. 删除容器

```bash
docker rm redis-course
```

删除运行中的容器会报错，需要先停止，或者强制删除：

```bash
docker rm -f redis-course    # 强制删除运行中的容器
```

删除容器不会删除镜像（第一课的结论）：

```bash
docker rm redis-course       # 容器没了
docker images                # 镜像 redis:7 仍然在
```

## 四、查看容器信息

### 1. 查看运行中的容器

```bash
docker ps
```

结果字段：

```text
CONTAINER ID：容器短 ID
IMAGE：使用的镜像
COMMAND：容器启动时执行的命令
STATUS：运行状态
PORTS：端口映射
NAMES：容器名字
```

没有用 `--name` 指定名字时，Docker 会自动生成一个随机名字（例如 `xenodochial_meninsky`）。练习时建议总是用 `--name` 起名，这样停止、删除、看日志都方便。

`docker ps` 只显示运行中的容器。想看到已停止的容器：

```bash
docker ps -a
```

容器停止后不会消失，用 `docker ps -a` 能看到它，并可以从这里看到它的退出状态：

```text
STATUS
Up 5 minutes        运行中
Exited (0) ...      已停止，退出码 0（正常退出）
Exited (1) ...      已停止，退出码非 0（通常是异常退出）
```

### 2. 查看日志

```bash
docker logs redis-course
```

容器启动时的输出和错误都会出现在这里。持续跟随日志输出：

```bash
docker logs -f redis-course    # -f：像 tail -f 一样持续输出，按 Ctrl+C 退出
```

容器启动后立刻退出、或者行为异常时，第一件事就是看日志。

### 3. 查看详细信息

```bash
docker inspect redis-course
```

`docker inspect` 输出容器的完整配置信息（JSON 格式，内容很长）。本课只需要知道它的用途：当需要确认容器的具体配置、端口、环境变量时，从这里查。

## 五、进入容器执行命令

### 1. 在运行中的容器里执行命令

```bash
docker exec -it redis-course redis-cli
```

拆开看：

```text
docker exec：在运行中的容器里执行一条命令
-it：交互式模式（-i 保持输入，-t 分配终端）
redis-course：容器名
redis-cli：要执行的命令，这里是启动 Redis 自带的命令行客户端
```

执行后进入容器内部的 Redis 命令行：

```text
127.0.0.1:6379> PING
PONG
127.0.0.1:6379> SET hello "world"
OK
127.0.0.1:6379> exit
```

输入 `exit` 回到本机的 PowerShell。此时执行命令的位置是容器内部，和通过本机端口映射连接是两条不同的路径：

```text
方式一：docker exec -it redis-course redis-cli
    直接在容器内部执行命令

方式二：本机安装 redis-cli，连接 127.0.0.1:6379
    经过端口映射访问容器里的 Redis
```

### 2. exec 的用途

- 进入容器排查问题：查看进程、配置、临时执行命令；
- 它只能用于运行中的容器。容器已停止时执行会报错：

```text
Error response from daemon: container ... is not running
```

## 七、完整练习：跑一遍容器的一生

依次执行并观察每一步的结果：

```bash
docker images                                 # 1. 查看本机有哪些镜像

docker pull redis:7                           # 2. 拉取 Redis 镜像

docker run --name redis-course -p 6379:6379 -d redis:7   # 3. 创建并后台启动容器

docker ps                                    # 4. 看到 redis-course 处于运行中

docker logs redis-course                     # 5. 查看 Redis 启动日志

docker exec -it redis-course redis-cli       # 6. 进入容器里的 redis-cli
#    在里面执行 PING、SET、GET，然后输入 exit 退出

docker stop redis-course                     # 7. 停止容器

docker ps                                    # 8. 不再显示 redis-course
docker ps -a                                 # 9. 但它在"所有容器"里仍然可见

docker start redis-course                    # 10. 再次启动

docker stop redis-course
docker rm redis-course                       # 11. 删除练习容器

docker images                                # 12. 镜像 redis:7 仍然保留
```

练习最后两步：

```bash
docker rm redis-course    # 确认只是练习环境后删除容器
docker rmi redis:7        # 确认不再使用后删除镜像
```

`docker rmi` 在镜像仍被容器引用时会失败。先删容器、再删镜像，是清理时的正确顺序。

## 八、常见错误

### 1. `docker ps` 看不到刚运行的容器

可能的原因：

- 容器已经停止。用 `docker ps -a` 查看，看 STATUS 里的退出码；
- 容器启动后立即退出。用 `docker logs 容器名` 查看退出原因。

注意 `hello-world` 本身就是"启动、打印、退出"的容器，它运行后立即停止是正常行为。

### 2. 删除运行中的容器报错

```text
Error response from daemon: You cannot remove a running container
```

先 `docker stop`，或直接用 `docker rm -f` 强制删除。

### 3. 对已停止的容器执行 exec

```text
Error response from daemon: container ... is not running
```

`docker exec` 只能进入运行中的容器。先 `docker start`。

### 4. 删除镜像被容器占用

```text
Error response from daemon: conflict: unable to remove repository reference ...
```

镜像仍被某个容器（即使已停止）引用。先删除引用它的容器，再删镜像。

### 5. 分不清删除容器和删除镜像

```text
docker rm 容器   -> 删除容器，镜像还在
docker rmi 镜像  -> 删除镜像，不直接删除容器
```

清理顺序：先容器后镜像。

### 6. 依赖 `latest` 标签

`redis:latest` 拉到的内容可能随上游更新而变化。需要环境可复现时，使用固定 tag，例如 `redis:7.4`。

### 7. 用镜像名当成容器名

```text
docker stop hello-world
Error response from daemon: No such container: hello-world
```

`hello-world` 是镜像名，不是容器名。没有用 `--name` 起名时，Docker 会给容器一个随机名字。用 `docker ps -a` 查看容器的真实名字或容器 ID，然后按名字或 ID 操作：

```bash
docker rm xenodochial_meninsky
```

另外，已经退出的容器（例如 `hello-world` 打印完就自动结束）不需要 `docker stop`，直接 `docker rm` 即可。

## 九、面试回答模板

### 题目：容器有哪些状态，`docker stop` 和 `docker rm` 有什么区别？

> 容器有运行中、已停止、已删除等状态。`stop` 只是停止容器进程，容器本身和它的配置还在，可以重新 `start`；`rm` 是删除容器，删除后需要重新 `docker run`。生产环境中删除前要确认容器内没有未保存的数据。

### 题目：`docker exec` 是做什么的？

> `docker exec` 在运行中的容器里执行一条命令，常用 `-it` 进入交互式终端，或执行排查命令。它只能在运行中的容器里使用，适合进容器查看配置、进程或临时验证。

### 题目：为什么不推荐依赖 `latest` 标签？

> `latest` 是可变标签，指向的内容会随上游发布变化，不同时间拉到的镜像可能不同，环境无法复现。需要确定性时使用固定版本 tag，例如 `redis:7.4`。
