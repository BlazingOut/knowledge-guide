# 第2课:镜像、容器与隔离

> 第 1 课把 Docker 装好，并跑起了第一个容器。这一课把"镜像"和"容器"两个对象讲透：镜像从哪里来、tag 怎么选、容器怎么管理、两个容器为什么互不干扰。
>
> 目标：能管理镜像和容器的生命周期，能看日志、进入容器，能用两个 Redis 容器验证隔离。本课不涉及端口映射；从宿主机访问容器服务放在第 5 课。

命令示例中 `#` 后面的文字是注释，实际执行时不输入。

## 1. 这一课要解决什么问题

第 1 课已经会用 `docker run` 启动容器。使用一段时间后，会碰到新的问题：

```text
装了好几个镜像
    -> 不知道本机到底有哪些
    -> 拉下来的镜像 tag 是什么意思
    -> 容器停止后找不到它了
    -> 想清理又怕删错东西
    -> 两个容器同时跑，数据会不会串
```

本课回答七个问题：

1. 本机有哪些镜像？
2. 镜像的 tag 是什么，`latest` 有什么问题？
3. 镜像从哪里来，怎样判断能不能用？
4. 容器有哪些状态，怎样停止、启动、删除？
5. 怎样查看容器日志？
6. 怎样进入正在运行的容器执行命令？
7. 两个容器同时运行，为什么互不干扰？

## 2. 镜像：只读模板

### 2.1 查看本机镜像

```bash
docker images
```

它会列出本机已有的镜像：

```text
REPOSITORY   TAG      IMAGE ID       CREATED       SIZE
hello-world  latest   4ab4c602aa5e   2 weeks ago   3.77kB
redis        7        c6c9052d7d24   4 weeks ago   159MB
```

```text
REPOSITORY：镜像名字
TAG：版本标签
IMAGE ID：镜像的唯一标识
SIZE：占用的磁盘大小
```

### 2.2 拉取镜像

`docker run` 在本地没有镜像时会自动拉取。如果想只下载、不创建容器，用 `docker pull`：

```bash
docker pull redis:7
```

这样做的好处是：可以提前把镜像准备好，拉取过程中的下载进度也更直观。

```text
docker run 镜像名    ≈  拉取（如果本地没有） + 创建容器 + 启动容器
docker pull 镜像名   ≈  只拉取，不创建容器
```

### 2.3 镜像的 tag

`redis:7` 里冒号后面的是 tag。规则：

```text
docker run redis        -> 等价于 docker run redis:latest
docker run redis:7      -> Redis 7 大版本，会跟随 7.x 的小版本更新
docker run redis:7.4    -> 固定到 7.4 系列
docker run redis:7.4.1  -> 固定到具体小版本
```

需要注意 `latest`：

```text
latest 不是"最新最好的版本"，只是一个可变的标签
今天和明天拉到的 latest，内容可能不一样
需要可复现的环境时，用固定的版本 tag
```

### 2.4 镜像从哪里来

Redis 课程里的 `redis:7` 就是一个由 Redis 官方维护、分享在 Docker Hub 上的镜像。这也是 Docker 最常见的用法：**不需要自己从零构建环境，直接用别人已经打包好的镜像**。

```text
别人把环境打包成镜像
    -> 发布到 Docker Hub（或其他镜像仓库）
    -> 你通过 docker pull 或 docker run 直接使用
```

"查看别人分享的环境"体现在几个地方：

```text
镜像页说明：https://hub.docker.com/_/redis
    写清楚镜像是做什么的、有哪些 tag、怎么使用

docker search redis
    在命令行搜索 Docker Hub 上的镜像

docker history redis:7
    查看这个镜像是分几步、用什么方式构建出来的

docker inspect redis:7
    查看镜像的详细配置
```

判断一个镜像能不能用，先看：

- 是否是官方镜像（Docker Official Image 标识）或可信发布者；
- 下载量和更新维护状态；
- 镜像页面的说明是否清楚，用法和版本是否明确。

不要随意运行来源不明的镜像，尤其是会挂载目录、或需要管理员权限的镜像。

### 2.5 删除镜像

```bash
docker rmi redis:7
```

如果镜像仍被某个容器（即使已停止）引用，删除会失败：

```text
Error response from daemon: conflict: unable to remove repository reference ...
```

先删除引用它的容器，再删镜像。删除顺序是"先容器、后镜像"。

## 3. 容器：运行实例

### 3.1 容器有哪些状态

```text
镜像 image（只读模板）
    | docker run：创建并启动
    v
运行中 running
    | docker stop：停止
    v
已停止 stopped
    | docker start：再次启动
    v
运行中 running
    |
    | docker rm：删除（运行中需要先停止，或加 -f）
    v
已删除 removed
```

可以把容器理解成一台用镜像"图纸"搭出来的机器：开机、关机、重新开机、报废拆除。停止不是删除，删除才是消失。

### 3.2 创建并启动容器

```bash
docker run --name redis-manage -d redis:7
```

`docker run` 一步完成三件事：

```text
本地没有镜像 -> 拉取
创建容器
启动容器
```

常用参数：

| 参数 | 含义 |
|---|---|
| `--name redis-manage` | 给容器起名，后续 stop、rm、logs 都用这个名字 |
| `-d` | 后台运行，不占用当前终端 |
| `redis:7` | 使用的镜像和 tag |

Docker 参数有短参数和长参数两种写法：

```text
短参数：-d、-p 8080:8000、-e APP_ENV=dev
长参数：--name、--network、--env-file、--add-host、--mount
```

长参数的两种等价写法：

```bash
--name redis-manage
--name=redis-manage
```

`--` 是长参数前缀，`-` 是短参数前缀；短参数有时可以合写：

```text
-it  等价于  -i -t
```

长参数的值本身还可以包含分隔符，不要和参数名的等号混淆：

```bash
--add-host=host.docker.internal:host-gateway
# 参数名：--add-host
# 值：host.docker.internal:host-gateway
# 值内部用 : 分隔“主机名”和“地址”

--mount type=bind,source="${PWD}/04-init.sql",target=/init.sql,readonly
# 参数名：--mount
# 值：type=bind,source=...,target=...,readonly
# 值内部用逗号分隔多个 key=value
```

值里有空格时加引号，例如 `--env-file "my env file"`。

容器名必须唯一。如果已经有同名容器，`docker run` 会报 `Conflict. The container name "/redis-manage" is already in use`。先删除旧容器，或者换一个名字。

### 3.3 停止、启动和重启

```bash
docker stop redis-manage     # 停止容器：先给进程发停止信号，超时后强制结束
docker start redis-manage    # 启动一个已停止的容器
docker restart redis-manage  # 重启：等于先停止再启动
```

停止后容器并没有消失，只是进程结束了；容器的配置和可写层还在，可以用 `docker start` 再启动。

### 3.4 删除容器

```bash
docker rm redis-manage
```

删除运行中的容器会报错，需要先停止，或者强制删除：

```bash
docker rm -f redis-manage    # 强制删除运行中的容器
```

删除容器不会删除镜像：

```bash
docker rm redis-manage       # 容器没了
docker images                # 镜像 redis:7 仍然在
```

### 3.5 查看容器

查看运行中的容器：

```bash
docker ps
```

结果字段：

```text
CONTAINER ID：容器短 ID
IMAGE：使用的镜像
COMMAND：容器启动时执行的命令
STATUS：运行状态
PORTS：端口映射
NAMES：容器名字
```

没有用 `--name` 指定名字时，Docker 会自动生成一个随机名字（例如 `xenodochial_meninsky`）。练习时建议总是用 `--name` 起名，这样停止、删除、看日志都方便。

`docker ps` 只显示运行中的容器。想看到已停止的容器：

```bash
docker ps -a
```

容器停止后不会消失，用 `docker ps -a` 能看到它，并可以从这里看到它的退出状态：

```text
STATUS
Up 5 minutes        运行中
Exited (0) ...      已停止，退出码 0（正常退出）
Exited (1) ...      已停止，退出码非 0（通常是异常退出）
```

本课还没有讲端口映射，所以 `PORTS` 一列暂时为空是正常的；端口映射在第 5 课展开。

### 3.6 查看日志

```bash
docker logs redis-manage
```

容器启动时的输出和错误都会出现在这里。持续跟随日志输出：

```bash
docker logs -f redis-manage    # -f：像 tail -f 一样持续输出，按 Ctrl+C 退出
```

容器启动后立刻退出、或者行为异常时，第一件事就是看日志。

### 3.7 进入容器执行命令

```bash
docker exec -it redis-manage redis-cli
```

拆开看：

```text
docker exec：在运行中的容器里执行一条命令
-it：交互式模式（-i 保持输入，-t 分配终端）
redis-manage：容器名
redis-cli：要执行的命令，这里是启动 Redis 自带的命令行客户端
```

执行后进入容器内部的 Redis 命令行：

```text
127.0.0.1:6379> PING
PONG
127.0.0.1:6379> SET hello "world"
OK
127.0.0.1:6379> exit
```

输入 `exit` 回到本机的 PowerShell。注意：**退出 exec 不会停止容器**，容器的主进程 `redis-server` 仍然在后台运行，`docker ps` 依然显示它 Up；停止容器要用 `docker stop`。

`docker exec` 只能用于运行中的容器。容器已停止时执行会报错：

```text
Error response from daemon: container ... is not running
```

### 3.8 进入容器终端与目录结构

容器里的 `/` 是容器自己的 Linux 根目录，不是 Windows 的 `C:\`。它由镜像的只读层和容器的可写层叠加而成。

进入容器看看：

```bash
docker exec -it redis-manage sh
# 进入容器里的 Linux shell；不是 Windows PowerShell
```

`docker exec` 的通用写法是：

```text
docker exec -it 容器名 命令
```

- `-i`：保持标准输入，能继续输入；
- `-t`：分配一个终端；
- `-it`：交互式终端，进 shell 时常用；
- `sh`：容器里的 shell；很多精简镜像没有 `bash`，但通常有 `sh`。

常用进入方式：

| 目的 | 命令 |
|---|---|
| 进入容器 shell | `docker exec -it 容器名 sh` |
| 进入 bash（镜像里有时） | `docker exec -it 容器名 bash` |
| 以 root 身份进入（调试用） | `docker exec -it -u root 容器名 sh` |
| 在 Compose 服务里进入 | `docker compose exec 服务名 sh` |
| 启动一个新容器并进 shell | `docker run -it --rm 镜像名 sh` |

`docker attach` 和 `docker exec` 不是一回事：

```text
docker exec     -> 在运行中的容器里新开一个进程，适合进 shell 排查
docker attach   -> 接到容器主进程的 stdin/stdout，不适合当交互式 shell
```

`docker attach` 到主进程后按 `Ctrl+C` 可能把主进程一起停掉，所以排查时优先用 `docker exec -it ... sh`。

下面 `$` 表示容器内的 shell 提示符，不是要输入的内容：

```text
$ pwd
/data
$ ls /
bin  boot  data  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
$ cat /etc/os-release
# 这里会显示容器里的 Linux 发行版信息
$ exit
```

`pwd` 显示当前工作目录；`ls /` 显示容器根目录；`cat /etc/os-release` 显示容器里的 Linux 发行版。不同镜像的目录和默认工作目录可能不同。

关键区分：

| 路径 | 在哪 | 谁用 |
|---|---|---|
| `C:\...\code\docker` | 宿主机 | 你编辑代码、准备构建上下文 |
| `code/docker` | 宿主机 | `docker build` 读取的构建上下文 |
| `/app` | 容器内 | 容器里的应用进程 |
| `/data` | 容器内 | Redis 镜像的默认数据目录 |

第 3 课 Dockerfile 里的 `WORKDIR /app` 设置的是**容器内**目录；Docker 构建时会在镜像里创建 `/app`。它和宿主机的 `code/docker` 不是同一个目录。

容器里新建或修改的文件只存在于这个容器的可写层；删除容器后，可写层一起删除，镜像不受影响。需要长期保存的数据要用 volume，第 4 课展开。

### 3.9 查看详细信息

```bash
docker inspect redis-manage
```

`docker inspect` 输出容器的完整配置信息（JSON 格式，内容很长）。当需要确认容器的具体配置、端口、环境变量时，从这里查。

本节的 `redis-manage` 只用于演示容器命令。进入下一节前，先清理它：

```bash
docker stop redis-manage
docker rm redis-manage
```

## 4. 两个容器看隔离

### 4.1 同时跑两个 Redis

```bash
docker run --name redis-a -d redis:7   # 容器 A
docker run --name redis-b -d redis:7   # 容器 B，同一镜像
```

用 `docker ps` 观察：两个容器同时在运行，各自有自己的名字、状态和可写层。两个容器里的 Redis 都监听各自的 `6379`，但这是两个独立容器世界里的 `6379`，互不冲突。

### 4.2 验证进程隔离

从宿主机查看容器 A 和容器 B 里的进程：

```bash
docker top redis-a
docker top redis-b
```

两个容器都有自己的进程列表，彼此看不到对方的进程。容器里的 Redis 进程在容器内部可以是 1 号进程，和宿主机上的进程编号没有关系，这就是进程隔离。

精简镜像里不一定安装了 `ps`，所以这里用 Docker 自带的 `docker top`，比 `docker exec ... ps -ef` 更稳妥。

### 4.3 验证文件系统隔离

```bash
docker exec -it redis-a ls /
```

看到的是容器自己的根目录，不是 Windows 的 C 盘，也不是容器 B 的根目录。

可以在容器 A 里创建一个文件：

```bash
docker exec -it redis-a sh -c "echo only-a > /tmp/marker"
docker exec -it redis-a cat /tmp/marker
docker exec -it redis-b cat /tmp/marker
```

容器 A 能读到 `/tmp/marker`，容器 B 读不到。每个容器有自己的可写层，文件系统互不影响。

### 4.4 验证数据隔离

进入容器 A 写入一条数据：

```bash
docker exec -it redis-a redis-cli
```

```text
127.0.0.1:6379> SET course:isolated "only in container a"
OK
127.0.0.1:6379> exit
```

进入容器 B 读取：

```bash
docker exec -it redis-b redis-cli
```

```text
127.0.0.1:6379> GET course:isolated
(nil)
```

容器 B 读不到容器 A 写的数据。两个 Redis 看似长得一样，实际是两套完全独立的数据。

### 4.5 小结

```text
两个容器 = 两个隔离的环境
    -> 进程互不可见
    -> 文件系统互不可见
    -> 数据互不可见
```

这三条对应第 1 课说的三面墙：进程、文件系统、网络。本课验证了进程、文件系统和数据；网络隔离和端口映射放在第 5 课。

注意区分"隔离"和"持久化"：容器 A 的数据容器 B 看不到，但删除容器 A 后，它自己的数据也会消失。需要长期保存的数据要用数据卷，第 4 课展开。

## 5. 环境切换

### 5.1 换 tag = 换镜像版本

```text
redis:7   -> 环境 A：Redis 7
redis:6   -> 环境 B：Redis 6
redis:7.4 -> 固定到 Redis 7.4 系列的环境
```

应用代码不用变，想换环境的版本，就换镜像 tag。这是"切换环境"最直接的形式。

### 5.2 多个容器 = 多个环境并存

同一个镜像也可以起多个容器，每个都是独立环境：

```bash
docker run --name redis-a -d redis:7   # 环境 A
docker run --name redis-b -d redis:7   # 环境 B，同一镜像
```

互不影响，想删哪个删哪个。

### 5.3 端口是另一条切换路径

容器内部端口不变，但外部怎么访问它，取决于端口映射。端口映射以及"换本机端口 = 换一个入口"的内容，统一放在第 5 课，本课不重复。

## 6. 本课命令速查表

| 对象 | 命令 | 含义 | 参数说明 |
|---|---|---|---|
| 镜像 | `docker images` | 查看本机镜像 | — |
| 镜像 | `docker pull 镜像:tag` | 拉取镜像 | 不写 tag 默认 `latest` |
| 镜像 | `docker history 镜像` | 查看镜像的构建步骤 | — |
| 镜像 | `docker inspect 镜像` | 查看镜像详细配置 | 输出为 JSON |
| 镜像 | `docker search 关键字` | 在 Docker Hub 上搜索镜像 | 加 `--filter is-official=true` 只看官方镜像 |
| 镜像 | `docker rmi 镜像` | 删除镜像 | 仍被容器引用时会失败 |
| 容器 | `docker run 镜像` | 创建并启动容器 | `--name` 起名，`-d` 后台运行 |
| 容器 | `docker ps` | 查看运行中的容器 | 加 `-a` 显示所有容器 |
| 容器 | `docker top 容器` | 查看容器内的进程 | 不需要进入容器 |
| 容器 | `docker stop 容器` | 停止容器 | 先发停止信号，超时后强制结束 |
| 容器 | `docker start 容器` | 启动已停止的容器 | — |
| 容器 | `docker restart 容器` | 重启容器 | 等于先停止再启动 |
| 容器 | `docker rm 容器` | 删除容器 | 运行中加 `-f` 强制删除 |
| 容器 | `docker logs 容器` | 查看容器日志 | 加 `-f` 持续跟随输出 |
| 容器 | `docker exec 容器 命令` | 在运行中的容器里执行命令 | 加 `-it` 进入交互式模式 |
| 容器 | `docker inspect 容器` | 查看容器详细配置 | 输出为 JSON |

## 7. 完整练习：镜像与容器的一生

如果前面已经留下同名的 `redis-a`、`redis-b` 容器，先执行 `docker rm -f redis-a redis-b` 再开始。

依次执行并观察每一步的结果：

```bash
docker images                                 # 1. 查看本机有哪些镜像

docker pull redis:7                           # 2. 拉取 Redis 镜像

docker run --name redis-a -d redis:7          # 3. 创建并后台启动容器 A
docker run --name redis-b -d redis:7          # 4. 创建并后台启动容器 B

docker ps                                     # 5. 看到两个容器都在运行

docker logs redis-a                           # 6. 查看 Redis 启动日志

docker exec -it redis-a redis-cli             # 7. 进入容器 A 的 redis-cli
#    执行 SET course:isolated "only in a"，然后输入 exit

docker exec -it redis-b redis-cli             # 8. 进入容器 B 的 redis-cli
#    执行 GET course:isolated，应得到 (nil)，然后输入 exit

docker top redis-a                          # 9. 从宿主机观察容器 A 的进程列表
docker exec -it redis-a ls /                  # 10. 观察容器 A 的根目录

docker stop redis-a                           # 11. 停止容器 A
docker ps                                     # 12. 不再显示 redis-a
docker ps -a                                  # 13. 但它在"所有容器"里仍然可见

docker start redis-a                          # 14. 再次启动
docker stop redis-a redis-b                   # 15. 停止两个容器
docker rm redis-a redis-b                     # 16. 删除两个容器

docker images                                 # 17. 镜像 redis:7 仍然保留
```

练习最后一步：

```bash
# 确认 redis-demo、redis-manage 等容器都不再使用这个镜像后，再删除镜像
docker rmi redis:7
```

`docker rmi` 在镜像仍被容器引用时会失败。先删容器、再删镜像，是清理时的正确顺序。

练习中两个容器都没有端口映射，所以从 Windows 本机无法直接连接它们；这是有意安排，端口映射在第 5 课学习。

## 8. 常见错误

### 8.1 `docker ps` 看不到刚运行的容器

可能的原因：

- 容器已经停止。用 `docker ps -a` 查看，看 STATUS 里的退出码；
- 容器启动后立即退出。用 `docker logs 容器名` 查看退出原因。

注意 `hello-world` 本身就是"启动、打印、退出"的容器，它运行后立即停止是正常行为。

### 8.2 删除运行中的容器报错

```text
Error response from daemon: You cannot remove a running container
```

先 `docker stop`，或直接用 `docker rm -f` 强制删除。

### 8.3 对已停止的容器执行 exec

```text
Error response from daemon: container ... is not running
```

`docker exec` 只能进入运行中的容器。先 `docker start`。

### 8.4 删除镜像被容器占用

```text
Error response from daemon: conflict: unable to remove repository reference ...
```

镜像仍被某个容器（即使已停止）引用。先删除引用它的容器，再删镜像。

### 8.5 依赖 `latest` 标签

`redis:latest` 拉到的内容可能随上游更新而变化。需要环境可复现时，使用固定 tag，例如 `redis:7.4`。

### 8.6 用镜像名当成容器名

```text
docker stop hello-world
Error response from daemon: No such container: hello-world
```

`hello-world` 是镜像名，不是容器名。没有用 `--name` 起名时，Docker 会给容器一个随机名字。用 `docker ps -a` 查看容器的真实名字或容器 ID，然后按名字或 ID 操作。

### 8.7 容器名重复

```text
Error response from daemon: Conflict. The container name "/redis-a" is already in use
```

容器名在同一个 Docker 环境里必须唯一。先删除旧容器，或者给新容器换一个名字。

## 9. 面试高频考点

### 9.1 镜像和容器有什么区别？

> 镜像是只读模板，包含应用、依赖和配置；容器是镜像运行起来的实例。一个镜像可以创建多个容器，容器之间互不影响。删除容器不会删除镜像。

### 9.2 `docker stop` 和 `docker rm` 有什么区别？

> `stop` 只是停止容器进程，容器本身、配置和可写层还在，可以重新 `start`；`rm` 是删除容器，删除后需要重新 `docker run`。生产环境中删除前要确认容器内没有未保存的数据。

### 9.3 `docker exec` 是做什么的？

> `docker exec` 在运行中的容器里执行一条命令，常用 `-it` 进入交互式终端，或执行排查命令。它只能在运行中的容器里使用，适合进容器查看配置、进程或临时验证。

### 9.4 为什么不推荐依赖 `latest` 标签？

> `latest` 是可变标签，指向的内容会随上游发布变化，不同时间拉到的镜像可能不同，环境无法复现。需要确定性时使用固定版本 tag，例如 `redis:7.4`。

### 9.5 两个容器为什么互不干扰？

> 每个容器有独立的进程空间、文件系统视图和网络空间，共享的是宿主机内核。容器 A 写入的数据在容器 B 里读不到，因为两个容器有各自的可写层；删除一个容器也不会影响另一个。

### 9.6 容器里的路径和宿主机路径有什么区别？

> 容器里的 `/` 是容器自己的 Linux 根文件系统，由镜像层和容器可写层组成；宿主机的 `C:\...\code\docker` 是另一个文件系统。`docker exec ... pwd`、`ls /` 看到的是容器内路径；`docker build` 的最后一个参数是宿主机上的构建上下文。两者不是同一个目录，`COPY` 负责把宿主机上下文里的文件复制到容器镜像里。

### 9.7 `docker exec` 和 `docker attach` 有什么区别？

> `docker exec` 在运行中的容器里新开一个进程，适合进入 shell、执行排查命令；`docker attach` 接到容器主进程的 stdin/stdout，不适合当交互式 shell，按 `Ctrl+C` 还可能把主进程一起停掉。需要进容器终端时优先用 `docker exec -it 容器 sh`。
